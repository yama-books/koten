# 1. 本書の役割

PoC v2以降に追加された方針を、次の試作品を作るための基準として一本化する。

本書では、以下を区別する。

- **固定**: PoC以降も原則維持する設計
- **採用方向**: 強く採用したいが実装方法は未確定
- **PoC仮値**: 検証のための暫定値
- **未決**: 実装前に判断が必要

企画の中心は、**文字を操作するゲームではなく、文字の生活を観察する箱庭**である。

変体仮名は独立した個体として、
「気づく → 向く → 一拍見る → 判断する → 行動する → 結果を受ける → 周囲が再判断する」
という生活を行う。

ユーザーは主として観察者であり、環境・色・住民構成へ軽く介入する。

# 12. 記号の変換文法

候補として維持する基本文法:

- `、 + 、 ⇄ ゛`
- `。 ⇄ ゜`
- `。。 ⇄ ゛`
- `。 + 、` → 果実／尾のある生物／道具
- `゜ + 、` → 虫眼鏡／網／鍵／クラゲ
- `゜ + ゜` → 鎖
- `。` 多数 → 泡／石垣／星座／実
- `、` 多数 → 草／雨／煙／鎖／風

変形は原則可逆。

句読点等にもIDを与え、
誰が拾い、何として扱い、何へ変化したかを残せるようにする。

【固定方針】

# 13. 濁点・半濁点を文字へ与える

「文字体系上付けられるか」と「本人が付けたいか」を分離する。

初期アプリ上の音韻制約候補:
- か行: 濁点可
- さ行: 濁点可
- た行: 濁点可
- は行: 濁点・半濁点可
- その他: 原則付着不可

付着不可でも出来事は起こる。

例:
- 乗せようとして落ちる
- 何度も試す
- 他個体へ渡す
- 投げて遊ぶ
- 保管する
- 無視する

濁点自体を個体が生み出す／拾う／分解するイベントも許す。

# 14. 色

初期は**黒中心**。

目的:
- 元来の性格を観察しやすい
- 色付与前後の差を比較できる
- 情報過多を防ぐ

ユーザーは後から色を与えられる。

ただし、
「赤=活発」「青=冷静」
のような全個体共通効果は置かない。

各個体に隠れた色相性を持つ。
同色・異色の他個体への反応もあり得る。

まれに最初から淡い色を持つ個体が出現してよい。
`innate_color` としてユーザー付与色と区別する。

出現率2〜5%はPoC候補値で未確定。

【黒中心・個体差は固定方針／率は未決】

# 22. 工房・生産文化

完成済みの工場を最初から置かない。

繰り返される共同作業の結果として工房が成立する。

例:
田が区画
→ 堂が共同作業場
→ 具が道具
→ 麻が繊維
→ 婦が加工
→ 傳が材料搬送
→ 數Ⅰが工程を整える
→ 所Ⅱが完成品置場
→ 織物工房のような場所になる

生産に関係しやすい個体候補:
春Ⅰ、農、菜、木、根、茂、麻、婦、布、具、砥、土、地、田、堂、傳、致、數Ⅰ、所Ⅱ、寶、本Ⅲ。

これは職業ではなく「やりやすい行動」である。

工房でも失敗を許す。
材料を誰かが遊びに持ち出す、搬送役が別件へ行く、雨で流れる等。

# 26. 勝手に去る個体

導入する方向。

ただし、
**箱庭から去る ≠ 個体データを失う**

観察ノート、関係、発見状態は残る。
数日後に戻ってよい。

定住性そのものも隠れた個体差にする。

入れ替え操作は単なる削除ではなく、
出口へ向かう、見送る、新しい個体が来る、
という出来事として見せる。

# 30. PoCの評価基準

## 可読性
8体前後でも誰が何をしたか追える。

# 35. 開発方法

キャラクター設定を机上だけで完成させない。

正式な反復:

**設計  
→ 自動生活  
→ ログ保存  
→ 観察  
→ 想定外の関係・行動を抽出  
→ 性格・能力・イベント頻度を調整  
→ 再び自動生活**

確認する:
- 慎重な個体が事件へ出過ぎていないか
- 同じ個体ばかり解決していないか
- 想定外の二体が自然に関係を作っていないか
- 面白い句読点解釈が出たか
- 背景が生活によって変わったか
- 工房・畑・集落のような構造が自然発生したか

**自律運転ログ自体をキャラクター設計の検証装置にする。**

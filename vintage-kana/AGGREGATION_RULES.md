# AGGREGATION_RULES — vintage-kana

最終更新: 2026-09-18

この文書は、国語研「変体仮名字形データベース」から収集した資料別字体件数を、どのように0補完・比率化するかを定める。

## 1. 原則

### 生データを上書きしない

`glyph-distribution*.json` は、国語研DBページに明示された非ゼロ件数の転記を保持する。

ページに資料名が出ない組合せを0とみなす処理は、`glyph-distribution-derived-*.json` にのみ保存する。

### 0は「明示値」ではなく「省略からの推定」

派生データでは、ある字体・付加記号の組合せが少なくとも一資料で確認されている場合、その組合せについて国語研DBページに列挙されない他資料を `count=0` とする。

```text
count_status: inferred-zero-from-omission
```

を必ず付す。

原DBが「0件」と文字で明示しているわけではないため、`observed-zero` とは呼ばない。

## 2. 比率は二種類に分ける

### share_within_kana_all_forms

同一 `source_witness × kana` 内の、すべての字形・濁点区分を分母にする。

```text
count / Σ(count of all forms for the same witness and kana)
```

用途:
- 資料内で、その音価に紐づけられた全記録の構成を俯瞰する
- 分布監査

注意:
- 無印・濁点・半濁点を同じ分母へ含むため、学習UIでの「候補字体の選択順位」には原則使用しない。

### share_within_kana_same_diacritic

同一 `source_witness × kana × diacritic` 内だけを分母にする。

```text
count / Σ(count of forms with the same diacritic class)
```

用途:
- 同じ無印／濁点／半濁点区分の中で字体分布を比較する
- 将来、入力文字の濁清条件を一致させた候補提示を検討する際の基礎値

同じ付加記号区分の合計が0の場合は、比率を `null` とする。0/0を0とはしない。

## 3. UIでの扱い

これらの比率は**歴史的な正解確率ではない**。

表示する場合は、

- 「この資料では○件」
- 「この資料の同区分内で○%」
- 「この資料で確認された分布」

のように、資料内の観察事実として示す。

次の表現には使わない。

- 「この字体が正しい」
- 「この字体がおすすめ」
- 「江戸時代では○%の確率でこの字体を使う」
- 「歴史的に自然さ○%」

## 4. 資料を勝手に合算しない

異なる `source_witness` の件数・比率は、既定では合算しない。

特に、

- 同じ作品の異本
- 同じ作品の異なる巻
- 異なる時代・媒体
- 異なるジャンル

を一つの「標準分布」にまとめない。

複数資料を集計する場合は、目的・対象範囲・重み付けを別途定義する。

## 5. 小標本の扱い

比率が高くても、分母が1件・2件等なら強い使用傾向とは扱わない。

UIや教材では比率だけでなく、

- 件数
- 分母
- 資料名

を追跡できるようにする。

統計的な閾値・信頼区間等を導入する場合は、別の分析仕様として定義する。

## 6. 現行派生データ

47音価本体:

- 250種類の `kana × glyph × diacritic` 形
- 15資料
- 3,750セル
- 原DBで非ゼロ: 2,046セル
- 省略から推定した0: 1,704セル

補遺「ん」:

- 1形
- 15資料
- 15セル
- すべて非ゼロ

## 7. 計算検算

2026-09-18 の生成時に以下を確認した。

- すべての比率が0以上1以下
- `share_within_kana_all_forms` は、分母が正の各資料×仮名群で丸め誤差の範囲内で合計1
- `share_within_kana_same_diacritic` も、分母が正の各群で丸め誤差の範囲内で合計1
- 8桁丸めによる最大合計誤差: 0.00000002

## 8. 次段階

比率は「どこを深掘りするか」を選ぶために使う。

たとえば、

- 同一作品の異本間で分布差が大きい字体
- ある資料に集中する字体
- 同じ字母の異体間で分布が逆転する例

を抽出し、原資料の実文脈へ戻る。

比率だけで教材例を生成しない。


## 9. 一覧表示専用の頻度順位（2026-09-23）

「字形を見る」の各音の中では、学習者が実資料で遭遇しやすい字体から確認できるよう、**一覧表示だけ**に使う横断集計を定義する。

対象と計算:

- 対象資料: Phase 1 の初期15資料単位
- 入力: 現行の `data/glyph-distribution.json`
- 対象: `diacritic = none` の Unicode 変体仮名（`U+1B***`）
- `totalObserved`: 15資料の明示された `count` を単純合計する
- `witnessCount`: 1件以上確認された資料単位数
- `glyph-distribution-part2.json` は現在 `glyph-distribution.json` に包含される旧分割データなので、**重ねて合算しない**

一覧の順序:

1. 現代の通常平仮名を先頭に固定
2. 変体仮名を `totalObserved` 降順
3. 同数なら `witnessCount` 降順
4. なお同じなら `glyph_id` 昇順

これは「歴史的に標準」「この字体が正しい」という順位ではなく、**この15資料で確認された出現件数に基づく閲覧順**である。出題の正誤判定や歴史的な自然さの判定には使わない。

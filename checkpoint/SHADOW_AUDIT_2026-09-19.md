# Checkpoint DB shadow audit
更新: 2026-09-19

## 結果

既存4サンプル、計990文字で legacy の文法・識別 hit と DB shadow detector を比較した。

| 指標 | 件数 |
|---|---:|
| legacy 比較対象 | 348 |
| DB raw hit | 310 |
| DB resolved | 69 |
| DB suppressed | 241 |
| legacy と位置一致 | 69 |
| DB only | 0 |
| legacy only | 252 |

- raw hit の legacy 被覆: **89.1%**
- 現時点で安全に通した hit: **19.8%**
- これは正答率ではない。短い表面形を文脈未解決のまま通さない設計のため resolved は意図的に少ない。

## 主な改善

- `ぬ・ね・ば・む` を context-required に追加。
- `なむ・らむ・にて・ばや` 等の内部にある短い表面形を、長い意味単位があるときは抑制。
- 形容詞監査例 `かひなけれ` / `みしかゝり` では `けれ` / `しか` の内部一致を正しく抑制。
- 係り結び30例を `kakari_musubi_routes.json` に接続。

## 係り結びの重要判断

一度、係助詞らしい文字列と近い表面形を距離だけで結んで shadow signal を出したところ、
長文の `とぞ申しける` で、`申し` 内部の `し` や `ける` 内部の `る` に候補支持が飛んだ。

このため **raw文字列距離による自動係り先推定は採用しない**。

現在は:

1. 係助詞を品詞として同定
2. 係り先の範囲を決める
3. その後 `kakariSupportForResolvedParticle()` を呼ぶ
4. 候補を「支持」するだけで正解確定はしない

という設計に変更した。

ルートAPIの回帰テストは8/8成功。
形容詞内部一致抑制は2/2成功。

# koten: contributor / AI agent entrypoint

Read this small file first. Historical handoff documents are **evidence**, not automatically the current instruction. The latest `main`, open PRs, and CI results must be read before editing.

1. **Authority:** `CONSTITUTION.md` > verified primary text / review evidence > app-specific design and README > active PR scope. Preserve the source Markdown and user learning records; generated JSON is rebuildable, not a canonical source. Never claim unreviewed historical forms or source text are verified.
2. **Independent apps sharing this repository:** `packages/hyakunin/` (百人一首), `conj/` (古典活用), `vintage-kana/` (変体仮名), `checkpoint/` (Checkpoint). Identify the app and exact file scope before editing. `checkpoint` has its own `checkpoint-main` integration rules: follow `checkpoint/README.md` and `checkpoint/PRODUCTION_INTEGRATION.md`.
3. **Concurrent work:** check open PRs and compare current `main`/target branch before writing. Use an isolated branch/PR per purpose. Never overwrite, rebase, merge, close, or change someone else's PR or in-progress files just to simplify work. Do not automatically archive or delete anything.
4. **Shortest path to context:** read the relevant app README and the **recent entry section** of its HANDOFF, not the complete legacy timeline. In particular `docs/HANDOFF.md` is a large historical log, and older “next task” claims can be obsolete. For `conj` use `conj/HANDOFF.md`; for `vintage-kana` use `vintage-kana/HANDOFF.md`; for `checkpoint` use `checkpoint/HANDOFF.md`.
5. **Verification:** select proportional tests per `CONSTITUTION.md` §9, and report the exact command/check, revision, PASS/FAIL, and unverified scope. Don't call compilation, CI green, Pages deployment, or an iPhone physical-device check equivalent. Avoid expensive full checks for text-only changes, but don't skip source correctness, saving, or privacy tests when changing those domains.
6. **Publishing:** keep secrets, real student records, raw corpus inputs of uncertain rights, unreleased review notes and internal session events out of public Git history/Pages. Observe `publish-allowlist.txt` and `tools/pages-assemble`; never treat an obscure URL as protection. No auto-merge/publish outside the approved request.
7. **Chat progress footer (one compact line on each substantive reply):** `koten/<area> | 状態:<stage> | 確認:<HH:MM JST or 未取得> | 証拠:<PR/commit or 未保存> | 次:<one action>`. This is a communication convention, **not proof that the current AI session's start/end time or context usage is observable**. Show detailed START/CHECKPOINT/HANDOFF only on meaningful milestones. Link the common public conventions in `moyashimisosoup/session-deck/docs/CLOUD_SESSION_PROTOCOL.md`.

This file contains public-safe technical contributor guidance only. Actual private session IDs, claims, work locks, internal handoff material and credentials belong in a separately permissioned store.

# ADR-0003: 公開境界 — 新規履歴での移管と現リポジトリの非公開維持

- 状態: 採択
- 日付: 2026-08-30
- 決定者: 依頼者（裁定）／実装計画に基づく
- 関連: `docs/IMPLEMENTATION_PLAN.md` §2.3、§2.3.1、§14.1〜§14.3、`CONSTITUTION.md` §4、`docs/HANDOFF.md` §7、裁定 D-03、裁定 H-01

## 文脈

現リポジトリ `github.com/moyashimisosoup/koten` の Git 履歴には、コミット `d001ce5` に再配布許可を確認していない原資料 PDF 3 点（合計 5,192,469 バイト、桐原書店の教科書付録を含む）が含まれている（実装計画 §2.3）。`CONSTITUTION.md` §4 は「公開」を公開 URL だけでなく、公開リポジトリ・Git 履歴・raw URL・配布物にまで及ぶものと定義している。したがって、このリポジトリの履歴をそのまま公開経路に乗せることはできない。

一方で、依頼者の確認により次が判明した（実装計画 §2.3.1、`docs/HANDOFF.md` §7）。

- 現リポジトリは非公開（private）である。
- 用途は原資料 PDF の置き場と、Codex との共有経路である。
- 停止条件 S-1（`origin` が公開設定で PDF が配信されている）は発動していなかった。非公開リポジトリは憲章 §4 の「公開」に当たらない。

Git の仕様として、いったんコミットしたファイルは `git rm` して commit しても履歴からは消えない。過去のコミットを指定すれば取得できる。履歴から消すには `git filter-repo` 等での履歴書き換えと force push が必要で、さらに GitHub 側の fork・PR・キャッシュ経由の参照は GitHub Support への依頼が要る場合がある。この事実を前提に、公開境界をどう引くかを決める必要があった。

## 決定

- **公開は新規履歴で行う（裁定 D-03）。** 新しい GitHub アカウントに空のリポジトリを作り、`git init` から始める。現リポジトリに remote を足さない。`git push` で現リポジトリの内容を移さない。
- **`git filter-repo` 等による現リポジトリの履歴書き換えは行わない。** 書き換え後も参照が残る経路（fork・PR・キャッシュ）が存在し、実益（非公開リポジトリの容量削減）に対してリスクが見合わない。新規履歴のほうが確実に安全である。
- 新規リポジトリへ移す対象は `docs/PUBLISH_MANIFEST.md` の**許可リスト**で決める。除外リスト（`.gitignore` 方式）にはしない。
- **現リポジトリ `moyashimisosoup/koten` は非公開のまま存続させる（裁定 H-01）。** 削除もしない。原資料 PDF の置き場であり、かつ Codex との共有経路であるために必要とする。
- 現リポジトリを維持する条件は次の 1 点のみとする。
  > このリポジトリを public にしない。public アカウントへ transfer しない。fork を公開しない。
- `docs/HANDOFF.md` と `docs/IMPLEMENTATION_PLAN.md` は現リポジトリで追跡する（`.gitignore` で除外しない）。Codex がこれらを読めるようにするためである。公開側への流出は、これらのファイルを許可リストに載せないことで防ぐ。

## 却下した案

| 却下案 | 却下理由 |
|---|---|
| `git filter-repo` 等での履歴書き換え＋force push | 書き換え後も fork・PR・GitHub 側キャッシュに旧履歴の参照が残り得る（消去には GitHub Support への依頼が要る場合がある）。Codex 側のクローンを壊す副作用もあり、得られるのは非公開リポジトリの容量削減だけで実益がない |
| 現リポジトリをそのまま public 化する案 | 履歴に許可未確認の原資料 PDF 3 点が含まれる。`git rm` して commit しても、過去のコミットを指定すれば PDF を取得できてしまう。`CONSTITUTION.md` §4 の「公開」の定義（Git 履歴・raw URL・配布物を含む）に反する |
| 除外リスト（`.gitignore` 方式）で公開範囲を決める案 | 除外リストは「書き忘れた新規ファイルが既定で公開される」向きに倒れる。内部資料や秘密情報の混入は、列挙漏れが公開側に**出ない**向き（許可リスト）で防ぐ必要がある。実装計画 §14.1 および §10（P0 ブロック）も同じ理由で `PUBLISH_MANIFEST.md` を許可リストとして設計している |

## この決定が守るもの

- `CONSTITUTION.md` §4（公開範囲）: 公開の定義（公開リポジトリ・Git 履歴・raw URL・配布物）に照らし、許可未確認の原資料 PDF が公開経路に一切乗らない構成にする。
- `CONSTITUTION.md` §1（裁定の優先順）1 位「校正済み本文と根拠資料を損なわない」: PDF を作業ツリーから削除せず、非公開の場のまま原資料として参照し続けられるようにする。
- 確定事項 F-17（原資料 PDF は再配布許可を確認するまで公開対象外）。
- 裁定 H-01・D-03 で確定した「現リポジトリは非公開のまま Codex 共有用として存続」という運用。

## 変更条件

次のいずれかが観測されたら、この決定を見直す。

- 原資料 PDF 3 点の再配布許可が別途確認され、公開してよいと判定された場合（この場合でも、履歴に混在させず許可リストへ明示的に追加する手順を経る）。
- 現リポジトリの可視性設定が誤って public に変更されたことが確認された場合（維持条件の違反。直ちに非公開へ戻す）。
- Codex との共有経路が別の手段（現リポジトリを介さない方法）に置き換わり、非公開リポジトリを維持する理由が消滅した場合。
- 新規履歴側の公開リポジトリで、許可リストに列挙されていないファイルが公開されたことが確認された場合（許可リストの運用不備。原因を特定し手順を修正する）。

## 影響

- 実装計画 P0（境界固定と公開衛生）が、本決定に基づき `docs/PUBLISH_MANIFEST.md`（許可リスト）を作成する。
- 実装計画 P12（移管）が、本決定の方式（新規アカウント・新規履歴・`git init`）で実行される。
- 2 プロダクト構成（ADR-0004）では、公開リポジトリを 1 つに保つ決定と合わせて、許可リストが共通部（正本 Markdown・LICENSE 一式・`review/`）と公開単位別部（`packages/hyakunin`・`packages/kanazukai`）に分かれる。

## 追補: D-10（2026-08-31）— 公開リポジトリの著者名義

2026-08-31、依頼者が新規 GitHub アカウントの取得にあたり、D-03（新規履歴での移管）を再確認したうえで
「メールアドレスは記載しない方針としてよいか」と問うた。現リポジトリの全 23 コミットには実メール
アドレスが著者情報として埋め込まれており、コミットの著者情報はハッシュに含まれるため、公開後の
除去は履歴書き換えと force push を要し、それでも fork・キャッシュ経由の参照は残る（本 ADR 本文と同じ理由）。

ただし Git は空の `user.email` を `empty ident` として拒否するため、「記載しない」は実現できない。
**依頼者の意図（実アドレスを公開経路に出さない）を実現する形として、次を裁定する。**

### D-10: 公開リポジトリのコミットは noreply 名義で行う

- 公開リポジトリでは `user.email` に `<ID>+<アカウント名>@users.noreply.github.com` を設定する。
  実メールアドレスは設定しない。
- GitHub アカウント側で `Keep my email addresses private` と
  `Block command line pushes that expose my email` を有効にする。後者は、実アドレスのままの
  push をサーバ側で拒否させるための機械的な歯止めであり、人の注意力に依存しない防御として採用する。
- 現リポジトリ（非公開）の既存 23 コミットは書き換えない。D-03 により公開側は `git init` から
  始まるため、既存履歴は公開経路に一切乗らない。本 ADR 本文が `filter-repo` を却下した理由が
  そのまま当てはまる。
- 採用形式の理由: アカウント名は公開 URL（`https://<アカウント名>.github.io/...`）に必ず現れるため、
  この形式による追加の開示はゼロである。アカウントに紐付かない形式（例:
  `koten-contributors@users.noreply.github.com`）は開示こそ同じだが、上記の push 拒否が働かない。
- この裁定は、`NOTICE` の著作権表示を個人名でなく `koten contributors` とする扱い、および
  `review/**` の確認者を役割表記（`reviewer: "human-01"`）とする §3.3 の規定と同一の原則に立つ。
  **公開物のいかなる経路にも個人を特定できる情報を置かない。**

### 変更条件（D-10）

- 依頼者が実名・実アドレスでの帰属を望むと明示した場合（この場合も、既存履歴の書き換えではなく
  公開側の新規コミットからの適用とする）。
- GitHub が noreply 形式または当該設定項目を廃止した場合。

## 0. この仕事は何で、何ではないか

| これは | これではない |
|---|---|
| **監査**。「満たしているが、これでよいか」を設計原則に照らして問う | **検収**。「受入条件を満たしているか」を再実行して確かめる（別セッションが済ませている） |
| **指摘と推奨を出す** | **判定を出す**（合格／差し戻しは書かない） |
| **裁定は Sol へ戻す** | **自分で直す**（コードを1行も変えない） |

**指摘はこの発注の受入条件ではない。** 直すかどうかは Sol が裁定し、必要なら別発注にする。
**「ついでに直す」ことをしないこと。**

## 1. 画面を実際に描いて見ること（**ソースを読むだけにしない**）

**このリポジトリには、320px・文字200% までの実描画を回す仕組みが既にある。**

```
npm run build            # 先に必ず走らせる。preview は dist/ を配る
npm run check:overflow   # tools/overflow-check/index.ts。8つの走査群が実際に画面を開く
```

`tools/overflow-check/index.ts` は Playwright で各画面を開き、幅 320/375/414/768 × 文字 100%/200% で測っている。
**同じやり方で自分でも開いて見ること。** 走査は「切れていないか」しか見ていない。
**切れていないことと、読みやすいことは別である。** そこが本監査の領分である。

**必ず 320px・文字200% を見ること。** 対象は中学生・高校生の自主学習で、**スマートフォンが中心**である。

## 2. 見る順序（**画面単位ではなく、人が通る順に見ること**）

依頼者の求めは「**経路の円滑さ**」である。1枚ずつ採点しても、それは出てこない。

1. **初回起動** → 「はじめに」ダイアログ（統計の説明＋学年・必須）
2. **ホーム** → 範囲を選ぶ／入口を選ぶ（歌本文・作者・本番・とりあえず・閲覧）
3. **本番を選んだ場合** → 設定面（範囲の確認・歌の順番・答え方・作者問題）
4. **出題** → 進捗の帯・歌・答え・答え合わせ
5. **結果** → 習熟度の変化・歌ごとの状態・次の一手
6. **中断して戻る** → ホームの復元カード
7. **これまでの記録** → 要確認の歌・全100首・記録の持ち出し

**各段で次の3つを見ること。**

- **いま何をする画面なのかが、最初の一瞥で分かるか。**
- **次に押すものが1つに定まるか。** 同格の候補が並んでいないか。
- **前へ戻れるか。** 行き止まりが無いか。

## 3. とくに見てほしい点（**これまでに出た指摘の型**）

### 3.1 最初の一瞥（ホーム画面）

**帯・カード・ダイアログが立て続けに増えた。** 復元カード、進捗、ホーム画面追加の案内、「これまでの記録」、
フッタの注記、「この版でまだできないこと」。**何が主役かを言えるか。**
**設計原則1**「内容を主役にする。装飾は意味を持つ小さな印に限る」に照らすこと。

### 3.2 歌本文の余白

**進捗の帯を出題画面のヘッダ直下に足した。** 歌の表示領域が削れていないか。
**320px・文字200%で、歌が何行に見えるか**を実際に見ること。原則1 に直結する。

### 3.3 縦書きと横書きの役割

**設計原則2**：「歌・設問・**選択肢の対象**は縦書き、ボタン・設定・進捗・説明・エラーは横書き。
**レイアウト都合で本文を横書きにしない。**」

069 の工程1・2 は、まさにこの原則違反を直したものである（作者問題の歌が横書き右揃え、選択肢が横書き）。
**直したあとで、役割が本当に揃っているかを見ること。** 混在が残っていないか。

### 3.4 見た目のストレス（依頼者の言葉）

具体的に次を数えて見ること。**印象で書かない。**

- **墨色べた塗り（`.primary`）の面積と個数。** 1画面に主要操作の印がいくつあるか。
  **069 以前は、作者問題の選択肢5つが全部べた塗りだった。**
- **初回に目に入る要素の数。**
- **視線の飛び。** 左右・上下に何度往復させているか。
- **同じ数字・同じ語を2度言っていないか。** 発注066・069 で2度出た型である
  （復元カードの残り数、本番の範囲）。

### 3.5 同じ判断を2回させていないか

**069 工程8 で直したのがこれである**——ホームで範囲を選んだのに、本番の設定面でもう一度入力欄が出ていた。
**他に同じ型が残っていないか。**

### 3.6 色だけで伝えていないか

**設計原則5**。習熟度の色、正誤の印、選択中の状態。**文言・記号・数値の併記が外れていないか。**
**灰色にした文字が、本当に補助情報か。**

### 3.7 押せるものの大きさ

**44px 以上か。** とくにチェックボックス、ラジオ（069 でボタン化した）、小さな「閉じる」。

## 7. 出力の形（**この形で返すこと**）

各件を次の形で書く。**印象ではなく、再現できる形で書くこと。**

| 欄 | 中身 |
|---|---|
| **どこで見たか** | 画面名・幅・文字倍率（例：出題画面／320px／200%） |
| **何が起きているか** | 見えたものを書く。**評価語（うるさい・古い・美しくない）だけで終わらせない** |
| **どの原則に反するか** | `DESIGN_SYSTEM.md` の原則番号、または「原則には無いが経路上の問題」と明記 |
| **推奨** | **直す／直さない**のどちらかを必ず書く。「検討の余地がある」は使わない |
| **優先度** | 高（利用者が詰まる・誤解する）／中（読みにくい）／低（揃っていない） |

**最後に「もし1つだけ直すなら」を1件挙げること。** 全部直せない前提で、順位を付けさせるためである。

**費用の見積もりは不要。** 実装量の見立ては Sol が行う。

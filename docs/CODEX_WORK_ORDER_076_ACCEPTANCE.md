## 3. 何をどう変えたか

### 3-1. 回答の器（発注076 §3）

`.answer-controls` を **出題・採点の両方で同じ位置に出す**ようにし、`width: min(100%, 30rem); margin-inline: auto`
を書字方向に依らず当てた。従来は縦書きのときだけ 30rem 中央で、横書きと採点後は全幅だった。

### 3-2. 同じ入力欄を使い回す

従来は出題用の `<input>` と採点後の `<input>`（`.answer-retained` の中）が**別の要素**で、開示のたびに
回答欄が生まれ直していた。今回は 1 つの `<label class="answer-field">` を両方の段階で描き、
保存が成功したら同じ要素を `readOnly` に切り替える。値は**保存した文字列**（`displayFlow.submitted.input`）で、
入力中の状態ではない。

### 3-3. 印の列を出題時から確保する

`grid-template-columns: 2rem minmax(0, 1fr)` を固定にした。従来の `auto` では、印が付いた瞬間だけ左の列が
生まれ、その分だけ入力の x と幅がずれていた。印の画像も 2rem に揃えている。
**高さは入力側が決める**——文字200%では印（64px）が素の入力（55px）より高く、開示のたびに行が 8.8px 伸びたので、
入力の下限を `max(44px, 2.5rem)` にして印を行の内側へ収めた。

### 3-4. 順序と読み上げ

回答欄 → 判定・正解・仮名遣い補足・注記 → 「次へ」の順にした（従来は判定が先）。
判定の文言は判定欄が持つので、**印は読み上げから外した**（`aria-hidden`）。従来は印にも
「正解」「要確認！」の名前が付いており、新しい順序では同じ判定を続けて二度読み上げることになる。

### 3-5. 表示切替の状態行

原文のときだけ状態行が消え、切替ボタンが進捗の罫線に接していた（実測 0px）。
`ReadingToggle` に `showState` を足し、**出題画面だけ**が「原文を表示中」を出す。
ホームは呼び出しを変えていないので、見え方は従来のままである（§6 の破壊試験 N8 で両方向を確認）。

### 3-6. 旧構造を固定していた試験の置換（1件）

`session: 開示では正誤画像を自分の答えにだけ一つ重ね、文言は残す` は
「**判定欄のあとに回答欄が来る**」ことを固定していた。発注076 §3 がこの順序を逆にするため、
その 1 行だけを外し、**順序の釘は 076 の試験 1 本が持つ**ようにした。
同じ試験の残りの主張（画像は 1 つだけ、しかも自分の答えの側）はそのまま残している。
保存・原文・開示・問題選定の試験は 1 つも緩めていない。

**文字200%で、空欄が正解で埋まると本文が折り返し直し、回答欄の y が下がる。**

- 該当は 30 件中 9 件（すべて文字200%、うち 8 件は横書き）。最大 164.36px（横書き・414px・△・ku2）。
- **文字100%では 30 件すべて 0 である。** x・幅・高さは倍率に依らず 0。
- 原因は回答欄側ではなく**本文側**である。`.blank-slot` は伏せている間 `min-inline-size: 3em` で、
  開示で答え（例：「いひしばかりに」）が入ると行が増える。その分だけ下の要素が押し下がる。
- 0 にする方法は 2 つしか見つからなかった。**どちらも発注076 §6 の停止条件に当たる。**
  1. 伏せている段階で正解の幅（＝文字数）を先に確保する → **正解の長さを先出しすることになる。**
     学習上のヒントを増やす変更なので、裁定なしには入れられない。
  2. 本文へ全問共通の大きな固定高を入れる → §6 が名指しで禁じている。
- したがって着手せず報告する。**「揃って見える」で代替せず、上の実測値をそのまま残す。**

## 9. 測定スクリプト（再実行用）

リポジトリの外（作業用ディレクトリ）に置いて実行した。`tools/` へは置いていない（発注076 §2 の変更境界の外）。
**実行前に `npm run build` を済ませること**（`dist` を測るため）。

```bash
node measure-076.mjs after.json
```

要点だけ記す（全文は 075 検収書 §9 と同じ骨組みで、測る対象が違うだけである）。

- `vite preview` を起動し、Playwright（Chromium・headless）で `?from=21&to=21` を開く。
- 「学習方法を選ぶ」→「歌本文」→「この範囲で始める」。`hyakunin:orientation` を書いてから
  `button.writing-toggle` で器の向きを揃える。
- **いま伏せている句**は `.question-poem` の中で `.blank-slot` を持つ `.question-line` の位置から求める。
  その句の `questionId`（`p021-blank-ku{n}`）で台帳を引き、正答は `answerHistorical`、
  △は `partialAnswers[0]`、誤答は `あいうえおかきくけこ` を入れる。
  △は `partialAnswers` を持つ句にしか無いので、無ければ「次へ」で進めてから測る。
- 測る値：`.answer-field`（無ければ `.answer-retained`）とその中の `input` の矩形、印の矩形、
  判定欄の矩形、`input.value` / `readOnly` / `placeholder` の有無、
  `input.clientWidth / field.clientWidth`、印が入力の左にあるか・交差しないか、
  判定欄が入力より下か、`.session-progress` の下端から `button.reading-toggle` の上端までの距離、
  `.reading-state` の文字、`main` 配下の切れ（`sr-only` と `INPUT` は除く）、ページの横あふれ。
- 座標は `getBoundingClientRect` にスクロール量を足した文書座標。文字倍率は
  `document.documentElement.style.fontSize = '32px'` で当て、測り終えてから戻す。
  **比の計算は倍率を戻す前に行う**（既存 `check:overflow` はここで戻してから測っており、§5 の穴になっている）。

基準線を測るときは `Session.tsx`・`styles.css`・`FeedbackMark.tsx`・`ReadingToggle.tsx` を
076 適用前へ戻し、**`npm run build` をやり直してから**同じスクリプトを走らせる。戻したファイルは `cp` で復元する。

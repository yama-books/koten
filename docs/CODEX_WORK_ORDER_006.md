# Codex向け発注文書 006: 公開staging全体のallowlist検査

発注日: 2026-08-31
階層: **Luna**（既存ツールの機械的拡張。新規裁定・新規依存なし）
優先度: 高（公開前の必須ゲート。ただし公開そのものは含まない）
対象: `tools/scan-publish`

---

## 0. 目的

`tools/scan-publish` は現在、限定的な対象しか走査していない。これを **公開staging全体**（ビルド成果物ディレクトリ配下の全ファイル）に対する allowlist 方式の検査へ拡張する。

**allowlist方式とは**: 「公開してよい」と明示された拡張子・パスだけを許可し、それ以外が1件でもあれば終了コード1で落ちること。denylist（禁止語を探す）方式へ退行させないこと。

これは公開判断そのものではない。**公開してよいか人が判断するための機械的な材料**を作る仕事である。

---

## 1. 先に読むもの

| 順 | 文書・ファイル | 確認すること |
|---|---|---|
| 1 | `docs/HANDOFF.md` 全文 | 現在の状態と絶対に守る境界。**このファイルは変更しない。** |
| 2 | `CONSTITUTION.md` | 検証・公開の不変条件 |
| 3 | `docs/PUBLISH_MANIFEST.md` | 公開してよいものの正本。allowlist の根拠はここに限る |
| 4 | `tools/scan-publish/**` 全体 | 現在の走査対象、判定、終了コード、出力書式 |
| 5 | `package.json` の `scan:publish` / `build` | 実行方法とビルド出力先 |

allowlist の内容を自分で発明しないこと。`docs/PUBLISH_MANIFEST.md` に書かれていない許可を足さない。

---

## 2. 変更境界

### 変更してよいファイル

```text
tools/scan-publish/**
tests/unit/scan-publish-*.test.ts     （新規の狭い unit test）
package.json                          （既存 scripts への安全な接続のみ）
```

### 絶対に変更しないファイル・領域

```text
docs/ 配下の全ファイル（本書を含む）
CONSTITUTION.md
百人一首_*.md / 古典文法_*.md / 仮名遣い規則_*.md / USB-*.pdf
packages/**            （全パッケージのソース）
tools/build-data/**
tests/data/**
.github/**
```

### 禁止事項

1. `git commit` / `git push` をしない。
2. 依存パッケージを増やさない。既存依存だけで実現できないときは停止して報告する。
3. 公開先URL、リポジトリ名、正式名称、フォント、ライセンスを扱わない・決めない。
4. 検査に落ちたファイルを「消して通す」ことをしない。**落とすのが仕事であり、通すのが仕事ではない。**
5. 既存の未コミット変更を消去・復元・上書きしない。他担当の成果物である。

---

## 3. 実装範囲

1. ビルド成果物ディレクトリ配下を**再帰的に全件**走査する。走査件数を出力に必ず出す。
2. 各ファイルを allowlist（拡張子とパス形の組）に照合し、**許可に一致しないものを違反として列挙**する。
3. 違反が1件以上なら終了コード1、0件なら終了コード0。
4. 出力には、違反ごとに「相対パス・理由・どの許可規則にも一致しなかったこと」を1行で書く。
5. 走査対象が0件だった場合も**異常として終了コード1**にすること（ビルド忘れを成功と誤報しないため）。
6. 絶対パス、内部資料名、スクリーンショット名を出力へ出さない。相対パスのみ。

---

## 4. 受入条件

1. `npm run build` 後に `npm run scan:publish` が終了コード0で完走し、走査件数が出力される。
2. 一時的にビルド出力へ許可外の拡張子のファイルを1つ置くと、終了コード1で当該ファイルが列挙される。**確認後、置いたファイルは必ず削除すること。**
3. ビルド出力が存在しない状態で実行すると終了コード1になる。
4. allowlist の各項目が `docs/PUBLISH_MANIFEST.md` のどの記述に対応するかを、完了報告に対応表として書く。
5. 次がすべて終了コード0で完了する。

```text
npm run typecheck
npm run lint
npm test
npm run build
npm run data:check
npm run scan:publish
```

6. `git status --short` で、本発注の差分と既存の未コミット変更が区別できる。禁止領域に変更がない。

---

## 5. 停止して報告する条件

| # | 条件 |
|---|---|
| S-A | `docs/PUBLISH_MANIFEST.md` に allowlist の根拠がなく、自分で許可範囲を決める必要が生じた |
| S-B | 既存依存だけでは再帰走査または判定が実現できない |
| S-C | ビルド出力先が複数あり、どれが公開stagingか判別できない |
| S-D | 公開先、リポジトリ、正式名称、フォント、ライセンスの判断へ入る必要が生じた |
| S-E | 既存の未コミット変更と差分が重なり、安全に最小変更を加えられない |

---

## 6. 完了報告に含めること

1. 変更ファイル一覧と各々の変更内容。
2. §4 の受入条件1〜6を一項目ずつ、実際に確認した方法と**観測結果**。
3. allowlist と `docs/PUBLISH_MANIFEST.md` の対応表。
4. §4-2 で置いた検査用ファイルの名前と、削除したことの確認。
5. 停止条件に当たった項目。なければ「なし」と明記。
6. 独自に決めたことがあれば全件。なければ「なし」と明記。

**推測・予定ではなく観測結果を書くこと。**

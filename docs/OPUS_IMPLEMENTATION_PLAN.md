# Opus 実装計画

最終更新: 2026-08-30  
対象: 『古典学習帳』初回公開（百人一首の本文・読み・作者の反復確認）

「古典学習帳」は仮称である。コード内の表示名は一箇所の設定から変更できるようにし、公開準備時の名称変更を全画面の手修正にしない。

この文書は実装の順序、成果物、受入ゲートを定める。`CONSTITUTION.md` と README の内容がこの文書より優先される。一次資料（`*一次データ.md`、読みの正本、原資料 PDF）と既存の旧設計書は読み取り専用であり、この計画のために編集しない。

## 1. 公開目標と非目標

初回公開は、利用者が URL で範囲を選び、説明をほとんど読まずに「とりあえず始める」から本文・読み・作者を確認でき、端末内に履歴を残せることを目標とする。縦書きの本文と横書きの操作、○△×の自己評価、苦手の再確認、JSON または文字列による端末移行、匿名統計と問題報告を含める。

初回公開では成績・学校アカウント・必須ログイン・クラウド履歴同期・QR共有・対戦・詳細な現代語訳・生成 AI による公開問題生成は扱わない。助動詞機能はデータ監査が済んだ範囲から、公開を遅らせない段階追加とする。

## 2. 技術構成の決定事項

Vite + TypeScript + Preact は2026-08-30の裁定で採用した。実装開始時に短い ADR（決定理由、却下案、変更条件）として固定する。その他は実装前の確認事項とする。

| 論点 | 推奨案 | 確認方法・変更条件 |
|---|---|---|
| UI スタック | **Vite + TypeScript + Preact（採用済み）** | GitHub Pages の base path、バンドル量、アクセシビリティを検証。変更が必要なら再裁定 |
| 保存 | IndexedDB を local-first の正本とする | 320px〜iPad、Safari/Chrome の再読込・容量・アップグレードを実機確認 |
| 統計・報告 | Firebase の匿名認証 + Firestore/Functions 等の最小構成 | 個人特定不可、送信失敗が学習を妨げない、test/official 分離を Emulator で確認。初回公開の必要機能とし、外す場合は依頼者の裁定を要する |
| 配信 | 静的ビルドを GitHub Pages へ | 公開リポジトリと非公開運用リポジトリを分離し、base path とキャッシュ更新を確認 |
| データ | Markdown 正本から検証済み JSON を生成 | 正本を変換・問題生成が上書きしないこと、生成物の再現性を CI で確認 |

推奨案を採用しないときも、利用者の履歴を守り、公開を遅らせる機能を後段へ回し、憲章のプライバシー・正本・アクセシビリティ要件を満たすことを変更の最低条件とする。

## 3. 構成方針

### 3.1 アプリとデータ

- アプリは静的配信可能な SPA とし、本文・読み・作者の生成 JSON を同梱する。
- `source -> parse -> normalize -> validate -> generated` の一方向パイプラインにする。正本 Markdown は入力であり、手編集する生成 JSON としない。
- 各首に一意な番号、五句、本文、歴史的/現代仮名遣い、作者、根拠・確認状態を持たせる。異同は primary / alternative / note を潰さず保持できる形にする。
- 句切れ、穴埋め候補、助動詞判定、注意文は別フィールドとし、未確認データを正解として公開しない。
- 問題生成はデータの確認状態と問題タイプを入力にし、生成結果に正本を書き戻さない。

### 3.2 local-first 履歴

- IndexedDB にスキーマバージョン付きの学習記録（歌 × 学習項目）と、設定・移行用の outbox を保存する。
- 回答・閲覧・自己評価の直後に保存し、ネットワーク不通でも学習を継続する。統計送信キューは履歴とは別物にする。
- インポートは既存記録を消さず、イベント ID または `(songId, item, occurredBucket, clientEventId)` 等で重複を除いてマージする。破壊的な初期化は対象を画面に示して確認し、表示設定は残す。
- エクスポートには学習に必要な最小履歴のみを含め、統計送信情報、認証情報、内部メモを含めない。形式変更時は移行と旧形式の拒否理由を明示する。

### 3.3 Firebase の境界

- Firebase は匿名統計と問題報告の受け皿に限定する。履歴本文、入力回答、手書き内容、正確な時刻、氏名・学校名・連絡先は送らない。
- 統計は承認済みの簡潔な案内文を初回に表示して送信する。個別のオプトアウト機能は初回公開に設けない。失敗時はローカルに短期間バッファしても通常画面に警告せず、送信できなくても学習機能を欠損させない。
- 同じブラウザ保存領域で継続する無作為な利用番号、日単位の区分、学年区分、ページ・ボタン・機能・問題種別、集計値のみを送る。利用番号は端末固有情報から作らず、実人数とは表示しない。payload はイベントごとに許可フィールドを固定し、未知・過大・自由文を拒否する。
- test と official をデータ上で明確に分離し、正式公開日時以前を正式統計へ混ぜない。Firebase 設定は一箇所の環境設定から読み、秘密鍵を静的バンドルへ入れない。
- Blaze 契約下でも無料枠内を運用目標とし、書込み数・読取り数・保存量に予算上限と警告基準を置く。公開用 Firebase Web 設定は秘密情報ではないが、管理者資格情報・サービスアカウント鍵とは厳密に分離する。

## 4. 段階、成果物、受入ゲート

各段階のゲートを満たしてから次へ進む。ゲート不通過のまま機能を積み増さない。

### 0. 憲章・データ・公開境界の固定

成果物: ADR、公開/非公開ファイル境界、ライセンス確認表、未確認データ一覧、採用スタックの決定記録。コードのApache-2.0、独自コンテンツのCC BY 4.0、フォントの元ライセンス、原資料PDFの非公開境界を維持する。

受入ゲート:

- README、CONSTITUTION、旧設計書との矛盾が列挙され、重大なものが裁定済みである。
- 100首の正本と各読みの番号対応、原資料の再配布可否、未確認の文法判定が分類されている。
- 公開リポジトリに含めない原 PDF・内部発注文書・実利用データ・秘密情報が明確である。

### 1. 最小実行基盤

成果物: Vite/TypeScript/Preact の起動、型・Lint・テスト、GitHub Pages 用 build、エラー時の利用者向け画面。

受入ゲート:

- ローカル build と Pages 相当の base path で再読込できる。
- 320 / 375 / 414 / 768px で横あふれがなく、キーボードの可視フォーカスと 44px 以上の操作領域がある。
- 本文は縦書き、操作は横書きで、読み上げ用の自然な DOM 順序を持つ。

### 2. 一次資料派生パイプライン

成果物: パーサ、正規化処理、スキーマ、JSON 生成、100首・五句・番号・作者・読みの validator、差分レポート。

受入ゲート:

- 正本を変更せず同じ入力から同じ生成物を再現できる。
- 欠落、重複、番号不一致、空の必須項目、未確認状態の公開混入、参照切れを CI が失敗として検出する。
- 差異がある場合に primary / alternative / note と根拠を表示できる。

### 3. 学習の最短導線

成果物: ホーム、「とりあえず始める」、範囲 URL（`?from=10&to=20`）、見るだけ/おぼえる/全体確認/試験前の確認、穴埋め、作者確認、入力・四択・確認、○△×、結果画面。

受入ゲート:

- 初回利用者が URL 範囲を失わずに一問目へ到達できる。
- 正誤を色だけに頼らず、文言・記号・％/メーターで伝える。閲覧だけで高い習熟度にならない。
- 不正解から次の一件を推薦し、終了・別範囲の選択を妨げない。

### 4. IndexedDB と移行

成果物: DB スキーマ、バージョン移行、保存/再読込、重複除去マージ、JSON/文字列エクスポート・インポート、対象を示す初期化。

受入ゲート:

- 回答直後の再読込、ブラウザ再起動、容量不足/DB upgrade の代表エラーで記録を失わない。
- 同一ファイルを二度読み込んでも二重加算されず、既存記録が消えない。
- 初期化は学習履歴だけを対象にし、本文・表示設定・正本を消さない。

### 5. 匿名統計・問題報告

成果物: 案内文、匿名認証のライフサイクル、イベントレジストリ、許可 payload、送信 outbox/retry、問題報告フォーム、Firestore ルールと Emulator テスト。

受入ゲート:

- 案内表示、オフライン、Firebase 障害のいずれでも学習が完了する。個別オプトアウト画面は設けない。
- payload privacy invariant テストが、自由文・回答本文・正確な時刻・端末固有ID・広告ID・フィンガープリント・秘密情報を拒否する。承認済みの無作為な利用番号だけを許可する。
- test/official を混同せず、問題報告はレート制限・TTL・管理者認証の境界を通る。

### 6. 品質・実機確認

成果物: リスクベースのテスト結果、アクセシビリティ記録、既知の制約、スクリーンショットまたは実機確認表。

受入ゲート:

- iOS Safari、Android Chrome、iPad Safari と主要デスクトップで主要導線を一巡する。
- 画面幅、200% 拡大、キーボード、読み上げ順、prefers-reduced-motion、縦書きの可読性を確認する。
- 正本変換、習熟度、履歴統合、統計/ルールを触った変更には関連自動回帰がある。

### 7. 公開判定と移管

成果物: 公開 build、Pages URL、公開前チェックリスト、運用引継ぎ、ロールバック手順、別 GitHub アカウント移管記録。

受入ゲート:

- 100首の参照整合、範囲 URL、履歴/統合/初期化、縦書き、匿名統計区分、秘密情報除去を満たす。
- README、仕様、使い方、画面文言が一致し、未対応を完全対応と表現していない。
- 公開リポジトリは別 GitHub アカウントの所有権・Pages・Actions・Secrets・Firebase 環境を確認し、旧アカウントの認証や未追跡ファイルを残さない。移管後に clone/build/Pages/問題報告を再確認する。

### 8. 公開後の段階追加

成果物: 助動詞監査済み問題、文法ライブラリー、将来の任意同期等を独立した小さなリリースで追加する。

受入ゲート: 各機能について一次資料の根拠、影響する保存/統計スキーマの移行、アクセシビリティ、ロールバック、憲章の再評価が済んでいる。かるた・対戦・クラウド同期はこのゲートを満たすまで初回公開へ戻さない。

## 5. リスクベーステスト方針

変更の危険度に応じて検証を選ぶ。小さな CSS、色、余白、文言だけの変更では、型/静的検査と変更画面の代表幅 smoke test までとし、無関係な全 suite は毎回回さない。ただし公開直前は全テストと実機一巡を必須とする。

| 変更 | 必須検証 |
|---|---|
| 文言・色・余白 | lint/typecheck、該当画面の 320/375/414/768px、キーボード確認 |
| 表示・問題生成 | 代表首、縦書き、正解/不正解、読み上げ順、validator |
| 正本変換・スキーマ | fixture、100首全件、差分、再現性、欠落/参照切れ CI |
| 習熟度・履歴・統合・削除 | unit、DB migration、重複、再読込、初期化、エクスポート/インポート |
| Firebase payload/送信/ルール | 許可・拒否、Emulator、test/official 分離、失敗/再試行/TTL、privacy invariant |
| リリース | 全 suite、production build、秘密情報 scan、3種実機、Pages 配信、ロールバック |

不安定なネットワーク、Firebase 利用不可、端末時刻のずれ、DB upgrade、低容量、二重タップ、ブラウザ再起動を重点シナリオに含める。

## 6. 停止して裁定を求める条件

次のいずれかが起きたら実装を進めず、事実、影響、代替案、暫定回避策を記録して裁定を求める。

- 正本と原資料の不一致を、根拠なしに一方へ潰す必要がある。
- 本文・読み・作者・文法判定の欠落や未確認を、正解または「確定」として公開する必要がある。
- IndexedDB の移行で既存履歴の消失、重複加算、復元不能が疑われる。
- 統計 payload が個人特定、自由入力、個別の問題別履歴、正確な時刻、端末固有ID・広告ID・フィンガープリントにつながる、または案内/匿名区分が検証できない。
- Firestore ルール、認証、TTL、test/official 境界を Emulator で再現できない。
- 依存パッケージ、Pages、Firebase のライセンス・設定・費用・利用規約が確認できない。
- 主要実機・320px・キーボード・読み上げで操作不能が残る。
- 公開アカウント移管時に秘密情報、内部資料、未許可原資料、実利用データが履歴や配布物に残る。
- 重大な仕様変更が初回公開を遅らせるのに、段階実装または安全な縮小案がない。

## 7. 完了の定義

Opus の初回公開は、上記 0〜7 のゲート、CONSTITUTION の公開判定、リスクベーステスト、実機確認、別 GitHub アカウント移管後の再確認をすべて記録した時点で完了とする。完了していない機能は README と画面で明示し、将来計画へ置く。

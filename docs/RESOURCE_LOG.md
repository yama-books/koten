# 資源消費の台帳（内部資料。公開しない）

**目的**——**どの工程を誰に出すのが安いかを、印象ではなく数字で決める。**
`docs/HANDOFF.md` §10.1 の配置は現在ベンチマークの公表値から推定しており、**この案件での実測が無い。**

**記録の規律**

1. **単位を揃える。** 工程まるごとではなく **「破壊試験 1 行あたり」「釘 1 本あたり」** で書く。揃えないと比較にならない。
2. **失敗回数を必ず書く。** 上位モデルの単価差が買っているのは**やり直しの少なさ**である。**失敗が 0 の工程では、その差は回収できない。**
3. **出所を書く。** トークン数は各ツールの自己申告、費用は公表単価からの概算、**どちらも親担当の実測ではない。** 混ぜない。
4. **一致検査を兼ねる回を作る。** 別々の担当が**同じ行を測り**、赤くなった試験名が一致するかを見る。**一致しなければ、安いほうを選ぶ判断そのものが成り立たない。**

## 5. 判明したこと（2026-09-05）

**「長い文書を書く工程を上位階へ移す」の値段が測れた**——**発注056 の起草 1 本で Astra の 5 時間枠の 9%。**
**その直後に枠が尽き、発注055 が 1 行も測れないまま止まった。**

**教訓は 2 つ。**

1. **書く工程は、どの担当にとっても高い。** 親担当の枠を守るために移したが、**移した先でも同じだけ高い。**
   **「余裕のある側へ移す」は、移した先の残量を確かめてから言うこと。**
2. **「別の主体が測る」ために上位階を選ぶ必要は無かった。** **証人の性質は context の独立性から来るのであって、
   モデルの階層から来るのではない。** **新しい Terra セッションで足りる。**
   **上位階を先に消費したせいで、安い工程まで止まった。**

## 5.2 当て直す 2 行を差し替えた理由（**発注書の欠陥。次に効く**）

**§4 と `docs/CODEX_WORK_ORDER_054.md` の末尾（`発注055（Astra の抜き取り 4 行）→ 親担当が M-11 と M-15 を当て直す`）に、
親担当がどの 2 行を監査するかが書いてあった。**
**発注055 §3 は「壊し方は発注054 §6 に書かれたものをそのまま当てる」と定めており、
Terra は 054 を読む。つまり監査対象は被監査者に漏れていた。**

**発注055 §2 では「どの 2 行かは書かない」と直したのに、参照先の 054 に残っていて意味が消えていた。**
**同じ制約が 2 箇所にあると、片方しか直らない。**
**そこで、漏れていない M-8 と M-14 へ差し替えた。** 手を抜いた行があるとすれば、
**監査されないと思っていた行のほうだからである。**

**規律として残す**——**監査対象を伏せるときは、被監査者が読む文書を全部 `grep` してから伏せたと言うこと。**

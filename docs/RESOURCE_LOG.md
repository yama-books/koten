# 資源消費の台帳（内部資料。公開しない）

**目的**——**どの工程を誰に出すのが安いかを、印象ではなく数字で決める。**
`docs/HANDOFF.md` §10.1 の配置は現在ベンチマークの公表値から推定しており、**この案件での実測が無い。**

**記録の規律**

1. **単位を揃える。** 工程まるごとではなく **「破壊試験 1 行あたり」「釘 1 本あたり」** で書く。揃えないと比較にならない。
2. **失敗回数を必ず書く。** 上位モデルの単価差が買っているのは**やり直しの少なさ**である。**失敗が 0 の工程では、その差は回収できない。**
3. **出所を書く。** トークン数は各ツールの自己申告、費用は公表単価からの概算、**どちらも親担当の実測ではない。** 混ぜない。
4. **一致検査を兼ねる回を作る。** 別々の担当が**同じ行を測り**、赤くなった試験名が一致するかを見る。**一致しなければ、安いほうを選ぶ判断そのものが成り立たない。**

## 3. 読み方（**この表から何を決めるのか**）

**問いは 1 つだけである**——**「Astra の単価差（Sol の約 2.5 倍）を、この工程で回収できるか。」**

| 観測 | 読み |
|---|---|
| **#4 の失敗が 0** | **回収できていない。** 手順が全部書いてある工程では、上位モデルの差が出る余地が無い。**次から Terra か親担当へ戻す** |
| **#4 の失敗が数件あり、#3 や過去の Terra 作業より明らかに少ない** | **回収できている。** 抜き取りを Astra に置く |
| **#4 と #5 の試験名が食い違う** | **費用の比較は保留。** 一致しない報告は、安くても使えない。**まず食い違いの原因を見る** |
| **#5 の所要が #4 と大差ない** | **親担当がやってよい。** 移す理由は費用ではなく「証人を分ける」ことだけになる |

**注意**——**「速かった」を「安かった」と読まない。** 所要時間と費用は別の資源であり、
**依頼者にとって最も希少なのは Claude の週次枠である。** その枠が空いたかどうかを最優先で見る。

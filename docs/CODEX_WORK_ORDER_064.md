## 1. 直すこと

**発注062が入口 `author`（作者）を新設したが、統計側は5つのままである。**

| 場所 | 現状 |
|---|---|
| `packages/shared/src/telemetry/registry.ts` の `ENTRY_KEYS` | `['quick','view','learn','review','exam']`。**`author` が無い** |
| `packages/hyakunin/src/domain/stats.ts` の `entryCounts` | 同じ5つ。`session.entry in entryCounts` で弾く |
| `firebase/firestore.rules` | `hasAll` で同じ5つを要求し、**`size() == 5` で固定** |

**結果、作者入口の利用は統計に1件も現れない。** 「指導のために正確な集計を得たい」という目的に直接反する。
作者は独立した学習入口であり、使われた回数が見えないのでは入口ごとの利用を比べられない。

**これは発注062の落ち度ではない。** 062の準備書が「統計は対象外」と境界を引いたためで、
**境界の引き方を誤ったのは起草者（Sol役）である。**

## 2. 2026-09-06 に前提が変わった（**必読**）

コンソール作業で判明した——**それまでコンソールには全拒否ルールしか入っていなかった。**
`stats_days_test` / `stats_days_official` への `match` が無く、`allow read, write: if false;` だけだった。

- **統計はこれまで一度も書き込めていない。** App Check とは無関係に全て拒否されていた。
- 同日、リポジトリの `firebase/firestore.rules` を貼り付けて公開した。**いまは5キーの規則が生きている。**

**この変化が本発注の難所を作る。** 以前は「規則が無いから何をしても届かない」だったが、
**いまは規則が生きているため、規則とクライアントの食い違いがそのまま送信の失敗になる。**

## 3. 順序と、その理由（**ここを外すと公開中の利用者が書けなくなる**）

素朴に「規則を6キーへ、次にコードを6キーへ」とすると事故になる。**理由**——

現行規則は `hasAll([5キー])` に加えて `size() == 5` を課している。
**6キー必須の規則へ差し替えると、いま公開されている版（5キーを送る）が全て拒否される。**
新しい版を公開するまでの間、**既存利用者の統計が丸ごと落ちる。**

したがって**3段階で進める。**

1. **規則を「5キーでも6キーでも通る」形にして配置する。**
   `size()` の固定をやめ、**`hasOnly([6キー])` かつ `hasAll([5キー])`** とする——
   知らないキーは拒み、`author` は在っても無くてもよい、という形。**コンソール作業。**
2. **配置を確認してから**、`ENTRY_KEYS` と `domain/stats.ts` に `author` を足し、公開する。
3. **公開版が入れ替わったことを確認してから**、規則を6キー必須へ締める。**別発注。本発注に含めない。**

**段階1と2を同時に出さないこと。** 規則の配置とアプリの公開は別々に効くため、
順序を守らないと必ず隙間ができる。

## 4. 受入条件

- `ENTRY_KEYS` が6つになり、`isStatsPayload` が6キーの `entryCounts` を通す。
- **5キーの古い形も通ること**（段階3が済むまでは両方を受ける）。**両方向で確かめる**——
  6キーを通し、5キーも通し、**知らないキーを混ぜたものは拒む**。
  「緩めただけ」の変更になっていないか、拒否側を必ず1本置く。
- `summarizeDailyStats` が作者入口の回を数える。**数えるだけでなく、他の入口の数を変えないこと。**
- `firebase/firestore.rules` の更新分が**リポジトリにも入っていること。** 配置とリポジトリを食い違わせない
  ——**今回の相違は、まさにそれが食い違っていたために起きた。**
- `tests/rules/` の規則試験があれば更新する。無ければ、**この機会に1本置くこと**を検討する。
- 既存の全ゲートが緑。**node 518件・画面183件を下回らないこと。**

## 5. 破壊試験（2件）

1. `author` を数えない実装へ戻す → **作者入口を数える試験だけ**が赤くなること。
2. 規則の `hasOnly` を外す（知らないキーを許す）→ **拒否側の試験だけ**が赤くなること。

**各回で何件赤くなり、何件緑のまま残るかを記録すること。** 全部赤くなる破壊は別の欠陥を叩いている。

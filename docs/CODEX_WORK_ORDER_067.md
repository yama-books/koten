# 発注067準備書：統計の送信から匿名認証を外し、積み上がる匿名アカウントを止める

- 作成：2026-09-06、Sol役＝Opus 5。**依頼者の起草許可を得た。**
- 状態：**裁定済み・着手可。** 基準線は commit `ac34b5b`（発注066の検収まで反映済み）。
- 由来：発注065 の検収で見つけた2件。**どちらも「実装が自分に課した前提」であって、規則が求めたものではない。**

## 0. この発注が直す2つの実害

**(1) 匿名アカウントが際限なく積み上がる。**
統計を送るたびに `accounts:signUp` を呼び、匿名アカウントが1つできる。
**`transport.ts` の `anonymousDeleteRequest` はどこからも呼ばれていない**（参照は `tests/unit/telemetry/transport.test.ts` の1件だけ）。
**1端末につき1日1個**ずつ Authentication に積み上がる。利用者が増えるほどコンソールが使えなくなる。

**(2) 設定が1つ欠けただけで統計が全部止まる。**
`sendStats` は `signUp.status !== 200` で `retry` に落ちる。**規則は認証を要求していない**——
`firebase/firestore.rules` に `request.auth` は**0件**である（2026-09-06 に実測）。
**規則上は不要な認証を実装が必須にしているため、コンソールの設定漏れだけで全部止まった**（065 工程3 で実際に起きた）。

## 1. 裁定（**選択肢ではない。この形で作ること**）

- **匿名認証を送信経路から外す。** `accounts:signUp` を呼ばない。`idToken` を送らない。
- **理由は「削除を配線するより安い」ではなく、「守っていないものを守っているように見せない」である。**
  匿名認証は誰でも何個でも作れるため、**書き込み口の保護にならない。**
  保護は **App Check（`request.app`）と規則**が担う。これは D-62 の方針であって、本発注で変えない。
- **`anonymousSignUpRequest` と `anonymousDeleteRequest` は削除する。** 呼ばれない送信口を残さない。
  対応する試験（T-13 の delete に関する行など）も、**消えた機能の試験として一緒に落とす。**
  **これは試験を弱めることではない。** ただし §3 の陰性試験を必ず置くこと。
- **App Check トークンの取得と送信は残す。** `getAppCheckToken` の経路は触らない。
- **規則は本発注で変えない。** `request.auth` を足すのも、6キー必須へ締めるのも別発注である。

## 2. 変更の境界

**許可**：`packages/hyakunin/src/telemetry/stats-sender.ts`、
`packages/shared/src/telemetry/transport.ts`、対応する試験（`tests/unit/telemetry/**`）、
`docs/HANDOFF.md`。
**対象外**：`firebase/firestore.rules`、`app-check.ts`、`sanitize.ts`、`registry.ts`、
`domain/stats.ts`、画面（`ui/**`）、保存スキーマ、統計の項目。
**弱めないこと**：061 の送信の門（`allowed` が偽なら1度も `send` を呼ばない）、
`sanitizeStats` を必ず通すこと、W-10・T-17・`no-pressure` の静的走査、
**例外を投げないこと**（通信の失敗で学習の画面を壊さない）。

## 3. 受入条件（**すべて機械判定できること**）

- **`accounts:signUp` と `accounts:delete` が `packages/**` のソースに 0 件**であること（`grep -rn`）。
  **走査対象が空でないことを先に示すこと**——`packages/shared/src/telemetry/` に他のファイルが実在する状態で数える。
- `sendStats` の成功経路で **`send` の呼び出しが 1 回だけ**になること（統計の作成のみ）。
  **「2回から1回へ減った」ことを試験で見ること。** 回数を数える試験を1本置く。
- **`Authorization` ヘッダを送らないこと。** `statsCreateRequest` が `idToken` を要求しなくなる、
  または呼び出し側が渡さない形にする。**どちらでもよいが、送っていないことを試験で見ること。**
- **App Check トークンは従来どおり送ること。** `getToken` が返した値がヘッダに載ることを1本で見る。
- **`allowed` が偽のとき `send` が 0 回**であること（061 の門。**既存の試験が残っていること**を確認する）。
- **例外を投げないこと。** `send` が投げても `retry` を返す既存の試験が緑のまま残ること。
- 全ゲート：`npm test`（node・画面）、`typecheck`、`lint`、`build`、`data:check`、
  `scan:publish` 違反0、`check:eol` 違反0。**画面を触らないので `check:overflow` は不要。**

## 4. 破壊試験（3件。**各回で何件赤くなり、何件緑のまま残るかを報告に書くこと**）

1. `sendStats` の先頭にある `allowed` の判定を外す → **061 の門の試験だけ**が赤くなること。
2. App Check トークンをヘッダに載せるのをやめる → **トークンを見る試験だけ**が赤くなること。
3. `accounts:signUp` を呼ぶ行を1行戻す → **§3 の「0件」の陰性試験だけ**が赤くなること。
   **これが赤くならなければ、陰性試験が何も走査していない。**

## 5. Solへ戻す条件（**満たせないときに条件を緩めない**）

- 匿名認証を外すと `firestore.rules` が拒否すると判明した場合。**規則を変えて通さない。止まって報告する。**
- `statsCreateRequest` から `idToken` を外すと、`transport.ts` の既存の釘（T-17 など）と衝突する場合。
- App Check トークンの取得が匿名認証の副産物に依存していると判明した場合。

## 6. 検収で繰り返し出ている型（**着手前に読むこと**）

- **追加・変更した検査を実際に完走させ、出力を報告に貼ること。**「追加した」だけの報告が3度あった。
- **破壊試験の結果を報告に含めること。** 何件赤くなり、何件緑のまま残るかまで。

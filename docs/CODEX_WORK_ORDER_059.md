## 1. F-1：公開リポジトリの CI が3リリース連続で赤

### 1.1 事実

公開直後に気づいた。**`Deploy Pages` は緑、`CI` は赤**という組み合わせが続いている。

| 公開 | Deploy Pages | CI |
|---|---|---|
| Publish the first test release | success | **success** |
| Fix device-review learning flows | success | **failure** |
| Refine device-review labels and question order | success | **failure** |
| 再確認を問題単位にし…（058） | success | **failure** |

失敗は毎回1件で、内容も同じである。

```
FAIL tests/screen/stats-onboarding.test.tsx > N-1: 統計案内の確定文は APP_SPEC §11 の引用と完全一致する
Error: ENOENT: no such file or directory, open '/home/runner/work/koten/koten/docs/APP_SPEC.md'
```

原因は単純である。**この試験は `docs/APP_SPEC.md` を読むが、`docs/` は公開許可リストに無い**（発注書・引き継ぎメモは内部資料、`MIGRATION_LOG` §7.3 の点検1がそれを毎回確かめている）。**公開ツリーでは構造上いつも落ちる。**

### 1.2 なぜ見えていなかったか

`Deploy Pages` と `CI` は別ワークフローで、**公開手順（`MIGRATION_LOG` §7.6）は「Pages のバッジで判定しない・公開URLを自分で開く」とは書いているが、CI の結果を見よとは書いていない。** 画面は正しく出るので、赤に気づく契機が無かった。**公開の門が3回続けて機能していなかった。**

### 1.3 これは新しい欠陥ではない

058 の変更が壊したのではない。初回公開の次から赤である。**058 の実装・検収の結論は変わらない**（非公開側では同じ試験が緑である。`docs/` があるため）。

## 2. F-1 の扱い

公開ツリーで `docs/` を読む試験をどう扱うか。**許可リストを「通すため」に広げるのは作業ではなく裁定である**（`MIGRATION_LOG` §7.7）。

| 案 | 内容 | 影響 |

## 3. F-2：出題画面が文字200%・狭い幅で切れる

### 3.1 事実

発注058で `check:overflow` の走査を session の出題画面へ広げた1回目の実行で観測した。**ページ全体の横あふれは0だが、要素が器の中で切れている。**

| 幅 | 文字100% | 文字200% |
|---|---|---|
| 320px | （`sr-only` のみ。設計どおり） | `nav-edge`・`back-link`・`wordmark`・`session-controls` |
| 375px | 同上 | `back-link`・`wordmark`・`question-text question-text--vertical` |
| 414px | 同上 | `back-link`・`wordmark`・`question-text question-text--vertical` |
| 768px | 同上 | 違反なし |

`sr-only` は 1px に潰す視覚的隠し要素なので切れていて正しい。**問題は上部のヘッダ（戻る／画面名／進捗）と、縦書きの器である。**

その後この走査は 057・058 が足した表示（`.answer-retained` / `.answer-feedback` / `.kana-supplement` / `.grade-list`）だけへ絞ってあるため、**現在の `check:overflow` はこの欠陥を見ていない。** 走査を広げ直すところから始める。

### 3.2 未確定なこと

**縦書きの器（`question-text--vertical`）が横方向にスクロールすること自体は、仕様違反とは限らない。** 縦書きは行が右から左へ伸びるため、拡大時にスクロールが要る場面がある。WCAG 1.4.4 が禁じるのは「2方向のスクロールを強いること」である。**ヘッダの切れと縦書きの器の切れを同じ違反として扱わないこと。** 器の方は、切れているのか、意図したスクロールなのかを先に切り分ける。

### 3.3 受入条件（F-2）

- `tools/overflow-check/index.ts` に **session の出題画面を対象とする走査**を足す。幅 320/375/414/768 × 文字 100%/200% の**8件ちょうど**で、件数が合わなければ非0で終えること（既存の走査群と同じ作り）。
- `sr-only` は対象外とする。**除外する要素は名前で持ち、ディレクトリや「main配下すべて」で括らない**（住人が増えたときに正しい実装を赤にしないため）。
- ヘッダ（`nav-edge`・`back-link`・`wordmark`）と `session-controls` の切れが**0件**になる。
- 縦書きの器については §3.2 の切り分け結果を書き、意図したスクロールと判断した場合はその根拠を発注書へ残したうえで走査の対象から名指しで外す。**「通らないから外す」は認めない。**
- 既存の走査 1232件（閲覧1200・ホーム拡大8・本番採点一覧8・057の新しい表示16）が違反0のままであること。

## 3A F-3：「はじめに」の通知と学年選択を、統計を送るまで出さない

### 3A.1 事実（読み取りで確認）

- **統計はいま1件も送っていない。** `packages/hyakunin/src` は telemetry を**一度も参照していない**。`packages/shared/src/telemetry/transport.ts` は送信リクエストの「形」を作る関数を持つだけで、呼び出す配線が無い。056の試験に「`transport.ts` は送信 API を呼ばない」という釘が明示的に打ってある。
- **学年の使い道も統計だけである。** `settings.grade` は保存と書き出しを除けば、`telemetry/registry.ts` の `StatsPayload.grade` にしか流れない。
- **通知と学年選択はタイトルより前に描画される。** 公開版の実測順は「はじめに → 利用状況の文 → 確認する → 学年（任意）→ 中一/中二/中三/その他 → 百人一首練習帳（タイトル）→ 範囲…」。
- **「確認する」は通知の確認だけで、学年を選ばなくても押せる。** `pendingGrade === undefined` なら学年を保存しない分岐がある（`Home.tsx`）。**「任意」と書いてあるが、選ばずに進めてよいことが画面から分からない。**
- **再表示の条件は `settingsLoaded && !settings.noticeConfirmed` であり、一度確認すれば出ない。** 依頼者の「毎回は出ないでほしい」は、端末・ブラウザを変えた場合か保存が消えた場合の観察と思われる。**毎回出る不具合としては再現していない。** 実装を直す前に、まず再現するかを確かめること。

つまり現状は、**送っていないものへの同意を、起動直後にタイトルより先に求めている。**

### 3A.2 裁定（依頼者・2026-09-05）

- **R1：統計の送信を実装するまで、「はじめに」の通知と学年選択を出さない。**
- **R2：戻すときは、同じダイアログで学年を必須で聞く。**

**部品と設定の形は消さないこと。** `StatsNotice`・`GradePicker`・`telemetry/**`・`UserSettings` の `noticeConfirmed`／`grade`、保存と書き出しの扱いはそのまま残す。**戻すときに作り直さないためである。** 出さないのは表示だけである。

戻すときの形（**本発注では実装しない。R2として記録する**）：タイトルより下に出るコンパクトなダイアログ。学年は必須で、選ぶまで OK を押せない。OK で消え、確認済みなら再表示しない。

### 3A.3 受入条件（F-3）

- 起動直後の画面に「はじめに」の通知と学年選択が**出ない**（画面試験）。タイトルが最初の見出しになる。
- **`StatsNotice`・`GradePicker`・`telemetry/**` のいずれも削除されていない。** 名指しで実在を確かめる試験を1本置く（「使っていないから消す」を防ぐ）。
- `UserSettings` のスキーマと移行が変わらない。既存の `settings-migration` 系の試験が緑のままであること。
- **`noticeConfirmed` が未確認の保存データを壊さない。** 既存利用者の設定を書き換えないこと。
- 058までの画面試験159件が減っていないこと。減らす場合は、どの試験がなぜ不要になったかを1件ずつ書く。

### 3A.4 F-1 との関係（**取り違えないこと**）

公開版CIを落としている `tests/screen/stats-onboarding.test.tsx` の N-1 は、**通知の文言が `APP_SPEC` §11 の引用と一致するか**を見る試験である。F-3 で通知を「出さない」ようにしても、**文言そのものは残るので N-1 は成立し続ける。** したがって **F-1 の裁定（§2.1）は F-3 では消えない。** 別々に片付けること。

# 発注068準備書：初回設定をダイアログへ戻し、学年を必ず受け取る。進捗バーをゲージへ整える

- 作成：2026-09-06、Sol役＝Opus 5。**依頼者の実機確認（公開版 `ce1c596`）から出た。**
- 状態：**裁定済み・着手可。** 基準線は commit `ac34b5b` ＋ 発注067の差分（**067 は画面を触らないので衝突しない**）。
- 由来：初回の「はじめに」で**学年を選ばずに確認でき、押すと学年選択が二度と出ない**。

## 0. まず直すもの（**実害のある欠陥。工程1が最優先である**）

`Home.tsx` の `confirmNotice()` は、**学年が未選択でも `noticeConfirmed: true` を保存する。**
しかも `pendingGrade === undefined` のときは **`grade` を削除して保存する。**
`onboarding` の枠は `!settings.noticeConfirmed` でしか出ないため、**一度押したら学年選択は二度と出ない。**

**結果として、学年区分の入った統計が1件も集まらない。**
`APP_SPEC` §1.1 ⑥ は「**学年区分を含む**匿名統計」を正式公開の条件に挙げている。
**配線はあるのに、実際には常に空になる**という、065 で「規則が配置されていなかった」のと同じ型である。

## 1. 工程1：初回設定をダイアログへ戻し、学年を必須にする

### 1.1 裁定（**2026-09-05 の裁定へ戻すだけである。新しく決めていない**）

`HANDOFF` §8 の 2026-09-05・依頼者裁定（059 F-3）は次のように書いてある——
**「戻すときは、タイトルより下のコンパクトなダイアログで学年を必須にし、OKで消え、確認済みなら再表示しない。」**
**いまの実装はこの3つのうち「タイトルより下」しか満たしていない。**

- **ダイアログにする。** 既存の `.interrupt-dialog` と同じ作り方でよい（`--radius-md`・`--rule-thin`・`--color-surface`）。
  **タイトル（`h1.wordmark`）より上に出さない。** 058・059 で同じ失敗を2度している。
- **学年を選ぶまで「確認する」を押せないようにする。** `disabled` にし、**理由を1行で書く**
  （押せない理由が見えないボタンを置かない）。
- **押したら `grade` を必ず保存する。** `delete withoutGrade.grade` の経路は**消す。**
- **確認済みなら再表示しない。** ここは現状のままでよい。
- **`statsCollectionEnabled` が偽のときは、いまと同じく何も出さない。** ここを変えない。

**「必須にすると使い始められない」については、止める手段が別にある**——
「これまでの記録」から統計を止められる（061 の裁定）。**初回に断らせない代わりに、あとで止められる。**

### 1.2 受入条件（工程1）

- **学年が未選択のとき「確認する」が押せないこと。** かつ、**押せない理由が画面に出ていること。**
- **学年を選ぶと押せるようになること。両方向で確かめる**——片方だけでは判定が死んでいても緑になる。
- **押したあと、保存された設定に `grade` が入っていること。** **「`noticeConfirmed` が真になった」だけを見ない。**
- 再読み込みで再表示されないこと。
- **案内がタイトルより後ろにあること**（DOM 順で確かめる）。
- 320px・文字200%で違反0。**ダイアログを出した状態で測ること。** 出していない状態を測っても何も証明しない。
  **走査群を足し、件数の門を付けること。**

## 2. 工程2：進捗バーをゲージへ整え、ヘッダのすぐ下へ移す

### 2.1 裁定（**依頼者が2026-09-06に選択**）

- **見た目**：**角を丸く、ふちのあるゲージにする。** `--radius-sm` と `--rule-thin`／`--color-rule` を使う。
  **既存の設計トークンから外れた値を新しく作らない。**
- **適用範囲**：**`MasteryMeter` のすべての使い方に適用する**（結果画面・履歴の習熟度バーも同じ見た目にする）。
  **依頼者の選択である。**「進捗バーだけ整える」は採らない——同じ部品で見た目が2種類になるため。
- **位置**：出題画面では**ヘッダのすぐ下に、画面幅いっぱいの細い帯**として置く。
  数字（「進み 3問/10問」）は**帯の右端に小さく添える。**
  **操作ボタン（「読みを確認する」「横書きにする」）と同じ段に置かない**——押せるものに見える。
- **復元カードのバーは現状の位置でよい。** 見た目だけ揃える。

### 2.2 弱めないこと

- **色だけで伝えない**（§5.2 の既存規則）。**数字の併記を外さない。**
- `role="meter"` と `aria-valuenow`/`min`/`max` を外さない。**`aria-valuenow` は進んだ量である**（残りではない）。
- 結果画面・履歴の**既存の試験を1本も落とさない。** 文言（「習熟度 ◯%」）を変えない。

### 2.3 受入条件（工程2）

- 4入口すべてでバーがヘッダの直下にあること（**DOM 順で確かめる。見た目の位置だけを言わない**）。
- 結果画面・履歴の習熟度バーが**同じ CSS クラスで同じ見た目**になっていること。
- 0%と100%の両端が従来どおりであること（**既存の釘が緑のまま残ること**）。
- 320px・文字200%で違反0。**出題画面の走査群は既にある。**

## 3. 工程3：ホーム画面への追加の案内

### 3.1 裁定（**依頼者が2026-09-06に選択：「別にする」**）

- **初回設定のダイアログと一緒にしない。** 統計の説明と学年は「必ず読ませる」もの、
  追加の案内は**任意**のものである。**混ぜると、断る力が対等でない相手（中学生を含む）に、
  任意のものまで必須に見せることになる。**
- **初回設定のダイアログが出ている間は、追加の案内を出さない。** 初回に2枚重ねない。
  **ダイアログを閉じたあとに、いまの下部カードを出す。**
- カードの中身・閉じ方・記憶の仕方は**発注066 のままでよい。** 変えるのは**出す時機**だけである。

### 3.2 受入条件（工程3）

- **初回設定が出ている間、追加の案内が出ないこと。** 確認後には出ること。**両方向で確かめる。**
- 066 の受入条件（standalone では出ない／閉じられる／閉じたら再読み込みしても出ない／
  保存が使えない環境で例外を投げない）が**すべて緑のまま残ること。**

## 6. 破壊試験（5件。**各回で何件赤くなり、何件緑のまま残るかを報告に書くこと**）

1. 学年が未選択でも「確認する」を押せるようにする → **押せないことを見る試験だけ**が赤くなること。
2. 保存から `grade` を落とす → **保存された `grade` を見る試験だけ**が赤くなること。
   **`noticeConfirmed` しか見ていない試験は緑のまま残るはずである。**残らなければ試験が重複している。
3. バーをヘッダの下ではなく操作ボタンの下へ戻す → **DOM 順を見る試験だけ**が赤くなること。
4. 初回設定が出ている間も追加の案内を出す → **時機を見る試験だけ**が赤くなること。
5. 習熟度バーだけ元の見た目に戻す → **見た目が揃っていることを見る試験だけ**が赤くなること。
   **これが赤くならなければ、工程2の「全部揃える」は誰も見ていない。**

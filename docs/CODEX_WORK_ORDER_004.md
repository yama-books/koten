## 0. 背景と作業の目的

実機確認で、狭い画面幅の縦書き表示が破綻していることが報告された。具体的には、五句が自然な右→左の
5 列にならず、**各句の文字列が横書きのまま、句だけ右→左へ並んでいる**。これは単なる配置の不自然さ
ではなく、縦書きとして読めない重大な破綻である（重大度: **高**）。上の句・下の句の分割、列高、作者の
位置も不自然である。閲覧中に範囲選択へ明示的に戻る経路もない。

この発注は、百人一首の**先行実機確認版**を読める状態に戻すための限定修正である。新しい学習機能を
追加する仕事ではない。仕様・データ・公開境界の裁定を行わず、既存の動作を保持したまま表示と導線を直す。

添付スクリーンショットは不具合の報告根拠であり、発注書・コード・テストに画像ファイルの絶対パスを
記載してはならない。

## 3. 実装範囲

### 3.1 狭幅縦書きの五句レイアウト

対象幅は **320 / 375 / 414 / 768 CSS px**。縦書き時に、本文は五・七・五・七・七の各句を一つずつ
独立した列として扱い、画面の右から左へ自然に読める **5 列**にすること。

- **最優先受入要件**: 各句の文字が上→下へ縦に並び、句の列が右→左へ進むこと。横書きの文字列を
  右→左へ5本並べただけの状態は、列数・横あふれが正しくても**不合格**とする。
- 上の句（最初の 3 句）と下の句（後ろの 2 句）の区別は、句を崩して列を折り返す・別の順序にする方法で
  表現しない。必要なら列間の控えめな余白、罫線なしの間、又は DOM 上のグループで視覚的に保つ。
- 句内で意図しない改行を起こさない。長さの異なる句でも、列高を固定して文字が切れる実装にしない。
- `writing-mode: vertical-rl` を維持し、5 列の読順（右→左）と支援技術用の自然な本文順が一致すること。
- 作者は本文 5 列と視覚的に衝突せず、本文より従属した位置に置く。狭幅でも本文の列を押し潰したり、
  横方向のはみ出しを生じさせたりしない。
- 横書き表示の既存レイアウトを壊さない。

実装時は、`writing-mode` の継承先と flex の主軸・交差軸を必ず確認する。親だけに指定して子の句 `span` が
横書きのままになる実装を残さない。

**禁止する近道**: 本文を極端に縮小する、`overflow: hidden` / `clip` で歌・作者を隠す、横スクロールに逃がす、
表示文字列を削る、特定の代表首だけに個別 CSS を当てる、横書き句を右→左へ並べただけで縦書き完了とすること。

### 3.2 範囲選択へ戻る明示的導線

閲覧画面に「範囲を選び直す」等、目的が単独で分かる横書きのボタンを追加すること。

- どの閲覧状態でも見つけやすい位置に常時置き、タップ領域は **44px × 44px 以上**。
- 既存の表示名（wordmark）を戻る導線の唯一の手段にしない。表示名は残してよいが、明示ボタンを必須とする。
- 戻った後、開始前の入力欄と有効な範囲は、閲覧していた `from` / `to` を保つこと。
- 範囲 URL（例: `?from=57&to=76`）は維持し、戻る操作が無効値への正規化や範囲の初期化を起こさないこと。
- キーボード操作、可視フォーカス、読み上げ可能な名前を満たすこと。

### 3.3 保持する既存機能

次を回帰させないこと。

1. ルビなし／歴史的仮名遣い／現代仮名遣いの読み 3 表示。
2. 縦書き／横書き切替と、既存の向き保存。
3. 範囲内の前の歌／次の歌への移動と先頭・末尾での無効化。
4. `from` / `to` の URL 指定、片側指定、逆順の正規化、無効値時の安全な復帰。
5. 本文・作者・異同注記の表示。

## 4. 検証と回帰検査の足場

### 4.1 必須の代表確認

少なくとも第 **57 / 76 / 91 首**で、読み 3 表示それぞれについて、4 幅すべてを確認する。これらは
短中長・作者名・読みの差を代表する首として扱い、特別扱いの CSS を追加する根拠ではない。

各組合せで次を確認する。

- 縦書きの本文で、各句の文字が上→下に組まれ、句の列が右→左の 5 列で読める。
- 各句 `span` の computed `writing-mode` が `vertical-rl` であることを確認する。句が2文字以上なら、
  縦方向の表示寸法が横方向より大きいことも確認し、横書き文字列の混入を検出する。
- 句内改行、文字切れ、本文と作者の重なり、横あふれがない。
- 横書きへ切り替えても本文・作者が読め、横あふれがない。
- 明示的な戻る導線で範囲選択へ戻り、範囲値が残る。

### 4.2 自動 overflow 回帰検査

既存の `tools/overflow-check` が利用可能なら、それを百人一首閲覧画面へ接続・補強する。
可能なら次のマトリクスを自動検査する。新規のブラウザ自動化依存を追加してはならない。

```text
100 首 × 読み 3 表示 × 幅 320 / 375 / 414 / 768px
```

最低限、各対象で `document.documentElement.scrollWidth > clientWidth`、本文・作者の切断又は重なり、
各句 `span` の computed `writing-mode === "vertical-rl"` を検出できる足場を置く。複数文字の句は、
表示矩形の高さが幅を適切に上回ることも検査し、横書き文字列を右→左へ並べただけの破綻を検出する。
全件自動化が既存ツールの制約でこの発注内に収まらない場合でも、代表首
57 / 76 / 91 × 読み 3 × 4 幅の検査は必須である。その場合は全100首化に足りない既存基盤を完了報告へ
具体的に記すこと。推測で「検査済み」としない。

unit test では少なくとも、戻る操作が閲覧状態のみを終了し、`from` / `to` を保持すること、既存 URL
正規化を壊さないことを検査する。画面の実寸・CSS に関する合否は、実ブラウザ検査又は既存 overflow
検査で確認すること。

## 5. 受入条件

すべて満たすこと。

1. **最優先**: 320 / 375 / 414 / 768px の縦書きで、各句の文字が上→下へ並び、五句の列が右→左に
   自然な 5 列となる。横書き文字列を右→左へ並べただけの状態は不合格とする。
2. 同じ 4 幅で、上の句／下の句の視覚的な区別が破綻せず、句内改行・文字切れ・作者との衝突・横あふれがない。
3. 閲覧中に、44px 以上の明示的な「範囲を選び直す」導線がある。戻っても現在範囲の値と URL 範囲を保持する。
4. 第57・76・91首 × 読み3表示 × 4幅で、§4.1 の目視確認に加え、句 `span` の computed
   `writing-mode: vertical-rl` と、複数文字句の縦長寸法を確認・記録する。
5. 読み3表示、縦横切替、前後移動、URL 範囲の既存テストが緑である。追加した回帰 test も緑である。
6. 可能な範囲で全100首 × 読み3表示 × 4幅の overflow 検査を実装又は既存基盤へ接続する。できない場合、
   代表検査を通したうえで、未達理由と次に必要な最小作業を報告する。
7. 次のすべてが終了コード 0 で完了する。

```text
npm run typecheck
npm run lint
npm test
npm run build
npm run data:check
```

8. 一次データ・生成 JSON・禁止領域・`docs/HANDOFF.md` に変更がない。既存の未コミット変更を保持している。

## 7. 検証の進め方

`CONSTITUTION.md` の検証原則に従い、広い検査の前に変更箇所を狭く確認する。

1. 代表首と 4 幅で、縦書き・横書き・戻る導線を実ブラウザで確認する。
2. 追加・既存の unit test を実行する。
3. `typecheck`、`lint`、`test`、`build`、`data:check` を実行する。
4. 全100首の自動 overflow 検査を実装できた場合は最後に実行する。

実機（iOS Safari、Android Chrome、iPad Safari）の最終確認は人の工程に残る。本発注のブラウザ確認を
「実機確認済み」と表現しない。

## 8. 停止して報告する条件

次に当たったら、自分で仕様を拡張・変更せず停止して報告すること。

| # | 条件 |
|---|---|
| S-A | 五句の正しい区切り、本文、読み、作者の正本に誤り又は矛盾を見つけ、一次データ編集が必要になった |
| S-B | 320px で 5 列と可読性を両立できず、書体・フォントサイズ・デザインシステムの裁定変更が必要になった |
| S-C | overflow 検査に必要な既存の置き場・実行基盤がなく、新規ツール・依存・設定の追加が必要になった |
| S-D | 範囲を維持して戻る導線が、既存の URL 仕様又は閲覧状態の設計と両立しない |
| S-E | 既存の読み3表示、縦横切替、前後移動、URL範囲のいずれかを保持できない |
| S-F | フォント取得、公開先、ライセンス、一次資料、正式 MVP 機能の範囲へ入る必要が生じた |
| S-G | 本発注の差分と重なる未コミット変更の所有者・意図が判別できず、安全に最小変更を加えられない |

停止時は、再現幅・首番号・読み表示・向き・観測した結果・必要と判断した裁定を簡潔に残すこと。

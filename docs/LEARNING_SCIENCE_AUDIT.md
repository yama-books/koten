# 古典学習帳 学習科学監査

更新日: 2026-08-30

## 結論（先に読む）

古典学習帳の「穴埋め・作者確認・読み確認を思い出して答える」「答えを確認して短いフィードバックを見る」「別の日に再確認する」という方向は、検索練習（retrieval practice）、間隔を空けた学習（spacing）、逐次再学習（successive relearning）と整合する。ただし、研究の多くは語彙・事実・授業内容を対象にした実験であり、中高生が百人一首・古典文法を学ぶこのアプリにそのまま効果量や最適日程を移せるとは言えない。

本監査は、実装の妥当性とリスクを点検するもので、学習効果の保証や因果効果の確定ではない。習熟度％は能力、評定、将来の記憶確率を表さない。実装後は、匿名・テスト運用と遅延テストを含む試験で確かめる。

## 根拠とアプリへの含意

| 論点 | 一次研究が示すこと | アプリへの含意 | 限界・過剰主張を避ける線 |
|---|---|---|---|
| Retrieval practice | Roediger & Karpicke (2006) は、文章を学習した大学生で、直後は再学習が有利でも、2日・1週間後はテスト経験が再学習より高い保持を示した。テストは測定だけでなく学習機会になり得る。 | 「答えを見る前に思い出す」を主導線にする。入力・四択・上の句→下の句等を混ぜ、閲覧だけで高い習熟度にしない。 | 文章材料、大学生、実験条件であり、百人一首や中高生への直接効果ではない。直後成績を改善するとは限らない。 |
| Repeated retrieval | Karpicke & Roediger (2007) は、学習中の反復テストが反復学習より1週間後の保持に有利で、想起済み項目の再想起が重要と報告した。 | 一度正解した項目を即座に永久除外せず、別試行・別セッションで再度想起する。 | 研究の材料・試験形式と本アプリの日本語文・作者・文法は異なる。回数や効果量をそのまま仕様値にしない。 |
| Self-regulated choice / overconfidence | Karpicke (2009) では、自分で選ばせると、正しく思い出せた項目を「学習済み」と見なし、検索練習を打ち切りやすかった。 | 「できたから終了」だけでなく、間隔を空けた再確認を自動で一件提案する。自己評価は答えの後に取り、正解でも低信頼なら再確認候補に残す。 | 研究は外国語語対と統制された選択課題。自動推薦が最適とはまだ言えない。押し付けや利用圧力を避ける。 |
| Spacing | Cepeda et al. (2008) は、1,350人超の事実学習で、学習間隔と最終保持間隔の組み合わせにより成績が変わり、最適間隔は固定値ではなく遅延との比率に依存した。 | 1日・数日・1週間など間隔のある再確認を作る。固定スケジュールを「最適」と表示せず、期限と履歴を見て試験運用する。 | 事実材料、成人中心、最大1年の遅延。学校の試験日・利用可能日・難易度を含む実環境に外挿できない。 |
| Successive relearning | Rawson & Dunlosky (2022) は、各セッションで想起成功の基準まで練習し、別の日にも同じ基準まで再学習する方法をレビューした。研究はまだ少なく、所要時間も評価対象とすべきとする。Rawson et al. (2013)（ERIC記録）は授業試験と長期保持の改善を報告した。 | その日の正解数だけで終了せず、各歌×学習項目を「今回の基準達成」「次回に再確認」と分ける。負担や中断は試験運用の使いやすさとして確認する。 | 有望だが研究数は少ない。授業・語彙・概念課題が中心で、百人一首の全項目を同じ基準で扱えるとは限らない。 |
| Feedback | Butler, Karpicke, & Roediger (2008) は、誤答の修正に加え、正しいが自信の低い回答にもフィードバックが保持を高め得ることを示した。 | 正誤だけで終わらず、正答と必要最小限の注意を提示する。正解＋「あやしい」も再確認対象として残す。初回公開後の文法機能では、承認済みの短い文法解説を追加できる。 | 一般知識の選択問題での研究。説明量、タイミング、古典文法の誤概念への最適形は試験が必要。 |
| Self-rating / calibration | 上記研究は、学習者の判断が検索練習の利益に敏感でないこと、再学習で自信が高まっても遅延保持が同じとは限らないことを示す。 | ○「確認できた」／△「あやしい」／×「まだ分からない」を記録する。見るだけの自己評価は小さく加点するが、客観的正答より低い上限を置く。 | 自己評価の文言・文化・年齢差がある。自己評価だけで高習熟度にせず、学習者を採点する指標にも使わない。 |
| Handwriting | Ibaibarriaga, Acha, & Perea (2025) は、50人の就学前児が新しい文字・擬似語を手書き／なぞりした群で、タイピング群より複数の事後課題の正確さが高かった。 | 「試験前の確認」で紙や画面に答えを書き、答えを表示する前に想起する。高い重みの主根拠は手書き動作そのものではなく、手がかりの少ない想起である。 | 就学前児の新規文字・擬似語学習で、古典日本語・中高生・タブレット手書きへの直接根拠ではない。入力困難、認識誤り、運動障害への配慮が必要。 |

## 現行仕様との照合

### 妥当な点

- 「見るだけ」「穴埋め」「作者確認」「入力／四択／確認」を分離している。閲覧と想起を同じ成果として扱わない。
- 「○△×自己評価」「苦手のみ」「範囲指定」は、学習者が次の対象を選ぶための情報になり得る。
- 端末内保存、削除・統合、匿名統計の境界は、学習科学の検証データと個人情報の最小化を両立しやすい。
- 不正解を罰ではなく次回対象とする方針は、誤りを修正するフィードバックと整合する。

### 未確定で、実装前に固定すべき点

1. **想起単位:** `歌 × 学習項目`（本文、上→下、下→上、読み、作者、文法）を独立した履歴単位にする。歌全体の正解を、作者や助動詞の正解に流用しない。
2. **正答定義:** 表記ゆれ、歴史的仮名遣い、漢字／かな、作者別名、句切れ・文法の注意を正本と別の判定データに保持する。未確定の解釈を正解にしない。
3. **セッション境界:** 同じ日に連続正解した回数と、別日・遅延後の想起を別に記録する。
4. **フィードバック時点:** まず回答を保存し、その後に答え・根拠・注意を表示する。答えを先に見せてから自己評価させない。
5. **初回閲覧:** 閲覧イベントは保存してよいが、客観的な想起成功とは別カウントにする。

## 習熟度ロジック v0 の監査（仮説、未検証）

### 表示と内部データを分ける

内部では次のイベントを保存する。個人を特定する情報、入力した歌詞・手書き画像そのもの、正確な時刻を匿名統計へ送らない。

```text
itemKey = poemId × skill
event = { sessionId, itemKey, mode, outcome, selfRating,
          answeredAt, sessionDate, delaySinceLastSession, feedbackShown }
```

`outcome` は `correct / incorrect / skipped / viewed`、`selfRating` は `remembered / unsure / not_remembered` とする。正解判定は検証済みの派生データから行い、AI出力を根拠にしない。

### 承認済みの初期係数

| 学習イベント | 基本加点 | その方法だけで到達できる上限 |
|---|---:|---:|
| 評価せず閲覧 | +1 | 20% |
| 見るだけ・× | +1 | 20% |
| 見るだけ・△ | +2 | 30% |
| 見るだけ・○ | +3 | 35% |
| 4〜5択で正解 | +5 | 65% |
| 漢字候補からひらがなで正解 | +7 | 80% |
| 自由入力で正解 | +9 | 90% |
| 紙・手書き想起で自己評価○ | +9 | 90% |

- 読み表示・ヒントを使った正解は一段軽い方法として扱う。
- 不正解・自己評価×は3〜5ポイント下げ、近い時期の再確認候補にする。
- 同一回で同じ問題へ再回答した場合、2回目以降の加点は半分にする。
- 90%を超えるには、別の日の自由入力または紙・手書き想起での正解を必要とする。
- 時間経過だけで％を下げず、「そろそろ確認」を別に表示する。

この順序は、閲覧より想起、手がかりの多い再認より手がかりの少ない再生を強く扱う点で研究と整合する。一方、+1〜+9、上限20〜90、減点3〜5という数値自体を直接支持する研究はない。したがって「科学的に証明された点数」ではなく、試験運用で校正する設計係数として版管理する。

### 推薦の優先順

次に確認する一件は、次の順で選ぶ。利用者は終了、別範囲、見るだけへ戻れる。

1. 期限を過ぎた項目で、遅延後の想起が未達のもの。
2. 誤答、スキップ、「△」「×」が直近にあるもの。
3. まだ別セッションでの想起成功がないもの。
4. 正解済みだが、一定期間再確認していないもの。

同点時は歌番号の偏りを避ける程度の安定した順序にする。毎回ランダムにして「学習済み」と錯覚させない。推薦理由を「前回から間隔が空いたため」「もう一度思い出してみましょう」と短く示す。

### 表示％の扱い

％は上記イベントから求める内部指標であり、記憶確率・試験得点・能力ではない。固定した短い段階名を付けず、数値、メーター、灰・赤・黄・青・緑の5色を併用する。未着手は灰、初期境界は1〜29%赤、30〜59%黄、60〜84%青、85〜100%緑とし、試験運用後に調整する。画面には、％だけでなく「最近要確認になった箇所」「別の日にも思い出せた回数」等の根拠を必要十分な量で示す。

### 自己評価の位置づけ

見るだけの自己評価は表のとおり小さく加点するが、上限20〜35%により想起成功とは区別する。正解×△、正解×○、不正解×○などの校正パターンは次の推薦と説明にも使う。

- 正解×△: フィードバックを強調し、別セッションで再確認。
- 不正解×○: 「思い出せたつもり」と実際の差を責めず、短い答えと次の確認を提示。
- 正解×○: その場の成功として保存するが、間隔後の成功まで安定とは呼ばない。
- 不正解××: 赤の状態にし、同日の再試行だけで緑へ戻さない。

## 間隔スケジュールの試験案

1日・3日・7日・14日を**初期の試験候補**とするが、最適スケジュールとは呼ばない。Cepeda et al. (2008)が示した通り、適切な間隔は目標とする保持遅延との関係で変わり得るため、試験日や利用可能日を考慮する。

試験運用では、少なくとも次を記録する。

- 別セッションでの正答率（7日後、可能なら28日後）。
- 入力／四択／確認の形式別の遅延後成績。
- 1項目あたりの再学習回数と中断率。所要時間を扱う場合は、試験運用の別記録または粗い区分に限定し、通常の匿名統計へ正確な時刻を送らない。
- 正解×自己評価と不正解×自己評価の組み合わせ。
- 画面幅、読み上げ、キーボード、手書き補助の利用時に操作を完了できた割合。
- 表示％を見たことで、必要以上に終了・反復したかという利用上の副作用。

初期の試験運用では、係数・色境界・おすすめが不自然な動きをしないかを依頼者自身の利用と匿名集計で確認する。条件比較や学校・クラス単位の研究を行う場合は、このアプリの通常運用とは分け、目的、説明、同意、分析計画を別途定める。少人数の結果から「効果がある／ない」と断定しない。初期版の目的は、実装が安全に動き、遅延後の想起を記録できることの確認である。

## リスクと対策

| リスク | 起こること | 対策 |
|---|---|---|
| 閲覧＝習熟と誤認 | カードを見ただけで緑や高％になる | 閲覧を別イベントにし、想起成功を必須条件にする |
| 直後正解の過大評価 | 同じ日に連続正解して安定と表示 | 別セッション条件を状態の中心にする |
| 自己評価の過信 | 見るだけの○を重ねて高％になる | 小幅加点と35%上限を守り、想起正答と区別する |
| スケジュールの圧力 | 期限・連続利用が不安を増やす | 「今日の一件」を提案し、延期・終了・別範囲を許す |
| フィードバック過多 | 答えを読むだけになり想起が短くなる | 回答保存後に、正答と必要な注意だけを表示 |
| 文法の誤判定 | 未確認の句切れ・助動詞が正解扱いになる | 正本・判定根拠・注意表示・レビュー状態を分離 |
| 手書きの排除効果 | 認識ミスや運動上の困難で学習を完了できない | 入力／四択／確認を常に残し、手書きは任意にする |
| 不透明な統計 | 学習履歴や回答が外部へ送られる | CONSTITUTIONどおり匿名集計、テスト／正式を分離、失敗は学習を妨げない |

## 公開前の判定基準

次を満たすまでは、習熟度ロジックを「研究で証明された」と説明しない。

1. 正本と派生判定データの照合テストがある。
2. itemKey、イベント、統合、初期化、再計算の自動テストがある。
3. 直後成績と遅延成績を分けて記録できる。
4. 習熟度が5色だけでなく％・メーター・必要時の説明でも伝わる。
5. 320 / 375 / 414 / 768px、iOS Safari、Android Chrome、iPad Safari、キーボード、読み上げ、Reduced Motionを確認した。
6. 手書きなしで同じ学習目的を完了できる。
7. 試験運用の事前計画、欠測の扱い、匿名性、問い合わせ窓口が決まっている。

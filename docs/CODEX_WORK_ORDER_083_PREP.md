## 1. 何をするのか

**本文（`-blank-ku*`）で、漢字とかなを途中まで混ぜて書いた形を ○ にする。**

いまは「全部漢字（正本表記・許容表記）」と「全部ひらがな（歴史的仮名遣い）」の**両端しか受理していない。**
途中で混ぜた形は `partial` ですらなく **`incorrect`** である。

```
p071-blank-ku2  門田の稲葉     -> correct
p071-blank-ku2  かどたのいなば   -> correct
p071-blank-ku2  門田のいなば    -> incorrect   ← これを ○ にする
p071-blank-ku2  かどたの稲葉    -> incorrect   ← これも
```

**依頼者が例に挙げた歌そのものである**（「夕さればかどたのいなばおとづれて」）。

### D-10 読みの割り付け（2026-09-14・**裁定済み**）

**漢字のかたまりを読みへ割り付けるとき、機械では一意に決まらない表記が3本ある。**
**機械任せにすると、誤った読みの形を ○ にする。** 例——`吉野の里に` を `吉野＝よし` と割ると、
`よしの里に`（「の」が1つ足りない）が受理集合へ入る。

| 句 | 表記 | 歴史的読み | 親担当が正しいと見る割り付け |
|---|---|---|---|
| `p031-blank-ku4` | 吉野の里に | よしののさとに | 吉野＝**よしの** ／ 里＝**さと** |
| `p038-blank-ku4` | 人の命の | ひとのいのちの | 人＝**ひと** ／ 命＝**いのち** |
| `p039-blank-ku2` | 小野の篠原 | をののしのはら | 小野＝**をの** ／ 篠原＝**しのはら** |

**2026-09-14・依頼者裁定。上の表の割り付けで確定。** あわせて依頼者は
**「いちばん右の形は絶対に不可」**と明言した。よって受入条件は「正しく割り付ける」ではなく、
**誤形が受理集合に入らないことを名指しで確かめる**形にする。

| 句 | 入ってはならない文字列 | なぜ入りうるか |
|---|---|---|
| `p031-blank-ku4` | `よしの里に` | 吉野＝よし と割ると、かな側の「の」が1つ足りないまま受理される |
| `p038-blank-ku4` | `ひとのいの命の` | 人＝ひとのい と割ると出る |
| `p039-blank-ku2` | `をの篠原` | 小野＝を と割ると、「の」が1つ足りないまま受理される |

**この 3 本は、走査対象が空でないことと対で見ること。** 受理集合が 0 件でも
「入っていない」は緑になる——**まず当該 3 句の受理集合が非空であることを確かめてから**、
上の 3 文字列が無いことを見る。

**割り付けは台帳に持たせ、機械に推測させない。** 区切り自体は
`百人一首_句未満ランダム空欄候補_v3.md` に既にある（`[吉野]の/[里]に`）。
**決まっていなかったのは読みをどこで切るかだけ**であり、それをこの裁定で閉じた。

**発注書は「全組み合わせを入れること」を要求し、実装に件数を報告させる。**
親担当は §3 に封じた予測値と突き合わせる——**これが独立した検算になる。**

- `npm run data:check` が exit 0

- 依頼者の例が通ること: `p071-blank-ku2` で `門田のいなば` と `かどたの稲葉` が `correct`

## 6. 破壊試験（**未検算。発注書を起こすときに全行を自分で通すこと**）

`work-order-cross-check-conditions` に従い、**各行について「何が赤くなるか」を実測で埋める。**
**予想で書いた行は1行も残さない。** 現時点では候補を挙げるにとどめる。

| 壊す操作 | 赤くなった試験 | 実測 |
|---|---|---|
| 中間形の列挙を外す | 中間形の釘 5 本 | **5件**（2026-09-14） |
| 割り付けの後戻りを外す（貪欲一致に戻す） | 割り付けの釘 4 本 | **4件**（2026-09-14） |
| 裁定の表を空にする | ほぼ全件 | **分離しない**（下記） |
| 裁定の表を誤った割り付けに差し替える | **D-10 の釘と表の写しの 2 本だけ** | **2件**（2026-09-14） |
| 本文の現代読みを ○ にする | 既存4本＋`questions.test.ts` の新しい釘 | **5件**（2026-09-13 実測済み） |

**表を空にする破壊は分離しない。** 止め口が働いて `buildData` がデータを 1 件も作らないため、
`buildData` を呼ぶ試験がすべて赤くなる。**別の欠陥を叩いているのではなく、設計どおりである。**
代わりに**誤った割り付けへ差し替える**破壊で分離を測った。

**その差し替えは「読みを組み立て直せるか」の検査を通り抜ける**——`よし＋の＋のさと` は
`よしののさとに` に戻るので、整合性としては正しい。**捕まえたのは D-10 の名指し 3 文字列だけ**である。
裁定を「正しく割り付けよ」ではなく**「この形を入れるな」**と書いたことが、そのまま効いた。

**貪欲一致の罠は実測済みである。** 親担当の最初の実装がこれを踏んだ——
`いく野の道の`（`野`＝`の` の直後に `の` が続く）と `ふるき軒端の`（`軒端`＝`のきば` が `の` で始まる）で、
`indexOf` が漢字自身の読みの位置を拾って割り付けに失敗した。**後戻りが要る。**

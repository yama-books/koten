### 既存裁定から変える理由を先に記す

対象範囲全体の記録が再練習操作を押し下げ、今回の学習を続けるために必要のないスクロールを生んでいる。このため、従来の「変化表と歌一覧を常時展開し、その後に操作を置く」表示構成を改める。記録を削除せず、一段の開閉で参照できる位置へ移す。

HANDOFF §4 の2026-09-05裁定（起草時354行）は変化表の小数第1位表示を、D-57（426行）は既存メーターの整数表示と計算維持を定めている。本発注はその数値規則を維持する。D-55（424行）のボタン名「まちがえた歌だけをもう一度」も維持する。074で整えた操作と説明の所属関係は維持する。

## 3. 確定する表示仕様

結果画面のDOM順序と視覚順序を、次の順に一致させる。

1. 現在のヘッダーと「今回の結果」。対象範囲・問題数・内訳・全問正答時の花丸を残す。内訳は簡潔に配置する。閲覧0件の行を出さない等の現在の規則を維持する。
2. 「次の操作」。既存の再練習ボタン2種と、それぞれに属する説明を置く。詳細の展開は不要。再確認対象が0問ならそのボタンだけを出さない。「同じ範囲をもう一度」は常に表示し、既存のprimary指定を維持する。操作をページ末尾にも複製しない。
3. おすすめがある場合の「次に確認する」。歌番号を「○番」と示し、現在の理由を残す。ここには習熟度%を併記しない。推薦対象や推薦計算は変えない。
4. 初期状態で閉じた単一の `details`。`summary` は「学習記録の詳細」。中に現在の「習熟度の変化」「歌ごとの状態」をこの順で残す。今回は10番区切りや入れ子の開閉を追加しない。

詳細の先頭には「習熟度は、これまでの学習記録をもとにした目安です。今回の正答率ではありません。」を表示する。変化表の前・後、空状態、整数メーター、未着手、作者未確認の意味と表示規則を保つ。

再確認ボタンの説明は「答えを見た問題・正答にならなかった問題を、同じ出題内容で{n}問くりかえし練習します。」とする。`n` は実際に受け渡す `retryQuestionIds.length`。説明は必ず当該ボタンと同じ `.practice-choice` 内に置く。「同じ範囲をもう一度」の説明と処理は維持し、「同じ問題をもう一度」へ改名しない。前者は範囲から新たに出題する操作であり、問題固定の保証がないため。

常時表示部分に、全体平均%、増加%、新しい達成段階、順位、連続日数、根拠のない称賛を追加しない。全問正答の既存花丸は残す。色・文字・余白は既存トークンを使い、新しい装飾カード、固定フッター、画面に追従する操作帯は追加しない。

## 5. 受入条件

### 行動と内容

- 詳細を閉じたまま、再練習操作が使える。キーボードでも詳細を開かず到達・実行できる。
- 再確認は渡された問題IDと順序をそのままコールバックへ渡す。閲覧のみの回、作者問題を含む回、飛び飛びの問題でも、対象が失われない。
- 同じ範囲の再出題、ホーム遷移の呼び出しは各クリックにつき1回。見せ方の変更が保存や集計を再実行しない。
- 詳細を開くと従来の変化表・対象範囲の歌一覧を読める。数値と件数は変更前の同一fixtureと一致する。0→0.8等の表記と整数メーターの丸めを維持する。
- 初期の視覚表示とアクセシビリティツリーに詳細内部の数値は出ない。閉じた詳細内にDOMテキストがあること自体は失敗ではない。
- `summary` はキーボードで開閉でき、開閉後も操作できる。隠すためだけの `aria-hidden` で操作可能な要素を残さない。

### 実描画

- 幅320・375・414・768・1024px、文字100%・200%で、横切れ・重なり・文字欠けを生じない。文字拡大は既存検査と同じ方式を使用する。
- 375×812px・文字100%、範囲1番〜100番・8問すべて閲覧の結果で、初期スクロール位置から両方の再練習ボタンの全体が見える。説明を切り捨てず、書体を小さくして合わせない。全問正答時も常設ボタンが見える。
- 320px・文字200%では、1画面への詰め込みを強制しない。ただし再練習操作は詳細より前にあり、対象範囲の首数を増やしても操作の上端が押し下がらない。同じ内訳・同じ桁数の範囲表示で10首fixtureと100首fixtureを比較し、差は1 CSS px以内。
- ボタン・開閉操作のタップ領域は44px以上。ボタンと所属説明が一組として並び、別ボタンの説明が間に入らない。
- 変更前後の結果画面高、各再練習ボタンのx/y/幅/高さ、詳細の閉・開の状態を検収書に記録する。画像だけで合否を判断しない。

## 6. 検証と停止条件

対象試験を先に実行し、その後 `npm test`、`npm run typecheck`、`npm run build` → `npm run check:overflow`、`npm run check:eol` を実行する。画面変更後のoverflow検査は必ず新しいbuildの後。無出力の時間を失敗と判断しない。既存検査をすべて繰り返すのは製品変更後の検収であり、本発注書だけの起草時には実行しない。

074の静的なDOM順序・説明文字列の試験が本発注で明示した変更と衝突する場合は、対応を検収書に1件ずつ記して変更する。対象問題ID、数値、保存、アクセシビリティ等の試験は弱めない。既存合格件数を転記せず、今回の実行結果を記録する。

次の場合は該当作業を止め、原因と最小の追加変更案を報告する。

- 境界外のロジック変更、記録移行、裁定の新たな変更が必要になる。
- 受入条件を満たすために文字縮小、内容削除、共通スタイルへの無差別な上書きが必要になる。
- 既存不具合を含め検査が失敗する。未変更基準線の失敗と今回の回帰を切り分け、未検証を合格扱いしない。
- 他者の製品差分が入り、比較基準を確定できない。

完成報告には変更範囲、受入条件別の証拠、未確認事項、実際に使用したモデル名・版・推論強度を含める。commit・push・公開は別指示まで行わない。

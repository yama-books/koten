# 古典学習帳 デザインシステム

更新日: 2026-08-30

## 目的と適用範囲

本書は「歌は縦書き、操作は横書き」を中心に、古典学習帳の画面・部品・状態を一貫させるための実装契約である。README、CONSTITUTION、正本データ、今後のAPP_SPECと矛盾する場合は、CONSTITUTIONと校正済み本文を優先する。本書は本文・作者・読み・文法の正本を変更しない。

対象は中学生・高校生の自主学習である。雰囲気を「和風」に寄せることではなく、本文を読み、思い出し、確認し、次にもう一度試すための静かな道具をつくる。

## 設計原則

1. **内容を主役にする。** 歌本文には余白と読める大きさを与え、装飾は意味を持つ小さな印に限る。
2. **縦横の役割を混ぜない。** 歌・設問・選択肢の対象は縦書き、ボタン・設定・進捗・説明・エラーは横書き。レイアウト都合で本文を横書きにしない。
3. **想起を入口にする。** 「見るだけ」は残すが、開始後の主要導線は穴埋め、作者確認、読み確認などの想起を優先する。
4. **数値は案内であり判定ではない。** 習熟度％は端末内履歴から算出する表示上の指標で、能力・評定・記憶確率・他者比較とは表現しない。
5. **正誤を色だけで伝えない。** 文言、記号、読み上げテキスト、％を必ず併用する。習熟度に固定の短い段階名は付けない。
6. **迷いを記録できるようにする。** 不正解や「△」は罰ではなく、次の確認対象を決める情報として扱う。
7. **アクセシビリティを機能要件にする。** タップ、キーボード、拡大、読み上げ、色覚、低速端末、オフラインを先に設計する。

## タイポグラフィ

### 役割とウェイト

| 役割 | 書体 | ウェイト | 用途 |
|---|---|---:|---|
| UI本文 | Zen Maru Gothic | 500 | ボタン、ラベル、設定、説明、進捗 |
| UI強調 | Zen Maru Gothic | 700 | 画面タイトル、主要操作、重要な結果文言 |
| 和歌本文 | Klee One | 600 | 本文、設問中の歌、句の引用 |

UIは丸みを含むが幼すぎないZen Maru Gothic、和歌は筆記の気配があるKlee Oneとし、役割を混ぜない。見出しを常時斜体にしない。本文の強調はウェイト、墨色、下線、藤色の小さな印で表す。

### self-host WOFF2

Google Fonts等の外部CSSを実行時に読み込まず、ライセンスを確認したWOFF2を公開物へ同梱する。日本語サブセットを分割する場合も、表示に必要な範囲を欠落させない。ファイル名は実ファイルに合わせて確定し、以下は配置契約の例である。

```css
@font-face {
  font-family: "Zen Maru Gothic";
  src: url("/assets/fonts/zen-maru-gothic-500.woff2") format("woff2");
  font-weight: 500;
  font-style: normal;
  font-display: swap;
}

@font-face {
  font-family: "Zen Maru Gothic";
  src: url("/assets/fonts/zen-maru-gothic-700.woff2") format("woff2");
  font-weight: 700;
  font-style: normal;
  font-display: swap;
}

@font-face {
  font-family: "Klee One";
  src: url("/assets/fonts/klee-one-600.woff2") format("woff2");
  font-weight: 600;
  font-style: normal;
  font-display: swap;
}

:root {
  --font-ui: "Zen Maru Gothic", "Hiragino Maru Gothic ProN", sans-serif;
  --font-poem: "Klee One", "Yu Mincho", serif;
}
```

実装時はフォント配布条件、サブセット、フォールバック時の行送り、200%拡大時の折返しを確認する。システムフォントだけの画面や、本文とUIを同じ役割で装飾する構成にはしない。

Zen Maru Gothic または Klee One のself-host・容量・縦書き品質に問題がある場合は、源柔ゴシック系と `word` リポジトリで採用済みのフォントを比較候補にする。ライセンス、表示速度、スマホ縦書き、濁点・旧字体を実物で比較してから裁定し、見た目だけで差し替えない。

## カラートークン

色値はOKLCHでトークンに集約し、画面中で直接値を書かない。温白と墨を基礎に、藤とコーラルを小さなアクセントとして使う。アクセントは1画面の約3%以内を目安にし、面全体の塗りや大きなグラデーションには使わない。

```css
:root {
  --color-paper:        oklch(97.5% 0.012 78);  /* 温白 */
  --color-surface:      oklch(99% 0.006 80);    /* カード */
  --color-surface-soft: oklch(94% 0.018 78);    /* 淡い区切り */
  --color-ink:          oklch(22% 0.018 55);    /* 墨 */
  --color-ink-muted:    oklch(46% 0.015 55);
  --color-rule:         oklch(84% 0.016 78);
  --color-wisteria:     oklch(60% 0.14 305);    /* 藤 */
  --color-coral:        oklch(66% 0.16 32);     /* コーラル */
  --color-focus:        oklch(47% 0.16 300);
  --color-accent-ink:   oklch(98% 0.008 80);

  /* 習熟度: 固定段階名を付けず、％・メーター・必要時の説明と併用する */
  --mastery-gray:   oklch(54% 0.012 75);
  --mastery-red:    oklch(56% 0.16 28);
  --mastery-yellow: oklch(78% 0.15 86);
  --mastery-blue:   oklch(56% 0.14 250);
  --mastery-green:  oklch(56% 0.14 145);
}
```

### 使用規則

- 本文と通常のUIは `--color-ink` と `--color-paper` の組み合わせを基本にする。
- 習熟度は未着手を灰、1〜29%を赤、30〜59%を黄、60〜84%を青、85〜100%を緑とする。境界は試験運用で調整できるが、％・メーターを常に併記する。
- 藤はリンク、選択中、控えめな区切りに使う。コーラルは主要な注意や行動の印に使う。
- 黄色面の文字は墨色など十分に暗い色を使い、黄色だけを状態の根拠にしない。
- 本文はWCAG 2.1 4.5:1以上、UI境界と大きな文字は3:1以上を最低ラインとし、可能ならAPCAでも確認する。
- 赤／緑の対比だけで正誤を表さず、「正解」「要確認」、○／✓／！などを併記する。
- 純粋な黒・白、紫から青／シアンへのグラデーション、金箔風の光彩、全面ガラス表現を使わない。

## 余白・レイアウト

4ptを基礎とする意味づけたスケールを使う。等間隔のカードを大量に並べず、本文の余白、設問、操作の順に視線が自然に進む非対称をつくる。

```css
:root {
  --space-2xs: 0.25rem; /* 4px */
  --space-xs:  0.5rem;  /* 8px */
  --space-sm:  0.75rem; /* 12px */
  --space-md:  1rem;    /* 16px */
  --space-lg:  1.5rem;  /* 24px */
  --space-xl:  2.5rem;  /* 40px */
  --space-2xl: 4rem;    /* 64px */
}
```

ホームは「とりあえず始める」を第一操作とし、詳細設定を初手で同時に開かない。学習画面は、(1)範囲と対象の短い横書き情報、(2)縦書きの問題、(3)横書きの回答・確認、(4)次にすること、の順に置く。

```css
.poem,
.question-text {
  writing-mode: vertical-rl;
  text-orientation: mixed;
  font-family: var(--font-poem);
  font-weight: 600;
}

.controls,
.progress,
.explanation {
  writing-mode: horizontal-tb;
  font-family: var(--font-ui);
}
```

縦書きの見た目と読み上げ順を分ける。DOM上の本文は自然な読み順で保持し、視覚層だけに `writing-mode` を適用する。読み上げ用の自然なテキストを重複して読ませない。句読点、行末、注記、選択肢の順序はiOS SafariとAndroid Chromeで実機確認する。

### 和歌の収め方

- 上の句・下の句を原則2つの縦書きまとまりとして配置する。
- まず余白と列間を調整し、それでも入らない場合は文字サイズを可読範囲内で一段だけ下げる。
- さらに必要な場合は、人間確認済みの改行候補を使い、上の句を初句・第二句または句切れで2〜3列に分ける。下の句も句の途中を切らずに分ける。
- 改行後の列は一段下げ、前列との関係が読める字下げ・列間を実機で比較する。無理に重ねず、5列構成も正式な候補とする。
- 句切れは表示上の便宜であり、問題の正解や唯一の解釈として見せない。
- 320 / 375 / 414 / 768pxそれぞれで100首を機械検査し、あふれ候補を抽出した後、人が実機で確認する。

## レスポンシブ契約

320 / 375 / 414 / 768pxを必須確認幅とする。最小幅を起点に、内容が崩れる地点でブレークポイントを置く。`max-width`中心のデスクトップ設計にしない。

- ルートの横スクロールを発生させない。`overflow-x: hidden`や`clip`で隠して解決しない。
- ボタン、主要リンク、タブ、パンくず、CTAは一行のままにし、長い文言は短くする。
- タップ領域は44px以上。アイコンだけの操作にも視認できる名前を付ける。
- 画像やフィードバック素材を含むグリッドは `minmax(0, 1fr)` を使い、裸の `1fr`で押し広げない。
- 長い見出しは `min-width: 0; overflow-wrap: anywhere;` を持つ。
- 画面幅が狭いときは設定パネルを折りたたみ、歌本文の読みやすさを削らない。
- iOS Safari、Android Chrome、iPad Safariで、縦書き・キーボード・拡大・向き変更を一巡する。

## 状態設計

### 操作部品の8状態

すべてのボタン、入力、選択肢、タブ、確認操作に次の8状態を実装する。

| 状態 | 表現 | 実装上の注意 |
|---|---|---|
| default | 境界線と本文が見える | 44px以上のタップ領域 |
| hover | 背景または下線を小さく変える | `hover`対応機器だけ。タップに依存しない |
| focus-visible | 2–3pxの即時フォーカスリング | リング出現をアニメーションしない |
| active | 押下中に軽く沈む | `transform`のみ。レイアウトを動かさない |
| disabled | 低いコントラスト、説明、操作不可 | 透明度だけに頼らず`aria-disabled`も付ける |
| loading | ラベルを保ったインライン進行表示 | 二重送信防止。完了まで結果を予告しない |
| error | 何が・なぜ・どう直すかを文言で示す | 色だけでなく`aria-invalid`／`aria-describedby` |
| success | 静かな✓と「保存しました」等 | 見える結果に祝賀トーストを重ねない |

画面状態としては、初回、読み込み中、空、オフライン、保存失敗、統合競合、完了、再試行可能を別途設計する。問題の正誤状態は、正解／要確認／未回答を文言と記号で表す。

## 手書き風フィードバック素材

既存の提供素材を使用し、学習効果を示す装飾とは扱わない。

| 素材 | 用途 | 必須テキスト |
|---|---|---|
| `assets/feedback/correct-maru.png` | 1問ごとの正解 | 「正解」または同等の読み上げ文言 |
| `assets/feedback/needs-review-check.png` | 不正解・自己評価× | 「要確認」＋短い次の行動 |
| `assets/feedback/perfect-hanamaru.png` | 全問正解の結果画面 | 「今回の範囲を確認しました」等 |

透過PNGの縦横比を維持し、代替テキストまたは隣接する状態文を置く。表示は約0.3秒の控えめな`opacity`／`transform`に限り、`prefers-reduced-motion: reduce`では停止する。元PNGは保持し、WebP/AVIFはライセンスと見た目を確認した派生物として扱う。手書き素材の見た目を「覚えやすくなる」と因果的に主張しない。

## アクセシビリティと文言

- `lang="ja"`、見出しレベル、ラベルと入力の関連、フォーカス順、読み上げ順を確認する。
- プレースホルダーをラベルの代わりにしない。エラーは補助文を置換し、同じ位置で読ませる。
- ドラッグ、音声、手書き認識を必須操作にしない。入力・四択・確認の代替を常に残す。
- 操作名と説明文で同じ語を使う。「次へ」「答えを見る」「もう一度確認」など、画面で行うことを書く。
- 低速通信や端末内保存の失敗を、回答や履歴の消失につなげない。
- 効果音は初期状態で使わず、動きは`prefers-reduced-motion`を尊重する。

## 禁止事項（AIスロップ回避）

- 紫〜青／シアンのグラデーション、白文字を置いた中央揃えヒーロー。
- 和紙・桜・鳥居・水墨・金箔を意味なく重ねた「古典風」装飾。
- 全画面中央揃え、同じ寸法の3枚カード、アイコン→見出し→2行説明の反復。
- 絵文字を機能アイコンの代わりにすること。必要なら既存素材か一貫したSVGを使う。
- 画面の角をすべて大きく丸める、カード内にカードを重ねる、多重の影・発光。
- ブラウザやスマートフォンの枠をHTML/CSSで描き直すこと。
- 斜体見出し、常時表示の章番号・アイブロウ、装飾目的の「01 / 02」。
- ホバーだけの機能、2行に折れる主要ボタン、`transition: all`、弾むイージング。
- 習熟度を順位・偏差値・連続利用圧力・「あなたの能力」として表すこと。
- 根拠のない数値、学習効果、AI生成の正本・正解判定を出すこと。

## 実装前後の確認

実装前にこの文書のトークン・フォント・状態表を部品一覧へ写し、実装後に次を確認する。

1. 320 / 375 / 414 / 768pxで、本文・操作・フォーカス・結果画面に横あふれがない。
2. 8状態、空・失敗・オフライン・統合競合が確認できる。
3. 縦書きの見た目と自然な読み上げ順が両立している。
4. 色、記号、文言、読み上げのいずれか一つに依存していない。
5. 実機でフォント読込失敗、長い歌、拡大、キーボード、Reduced Motionを確認した。

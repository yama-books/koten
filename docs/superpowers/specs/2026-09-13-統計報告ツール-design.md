# 統計報告ツール 設計（2026-09-13）

**目的。** Firestore に溜まった統計を、依頼者が手元で読めるようにする。いま確認する手段が1つも無い。

**前提（この日の実測）。** `firestore.rules` は `allow get, list, update, delete: if false;` で読み出しを全部閉じている。
App Check は**モニタリング（非適用）**で、同日の裁定（案2）により `appConfig.appCheckEnabled` は偽。
**規則は触らない。** 管理者権限で読む。

## 1. 形

**取得と描画を分ける。**

```
node --experimental-strip-types tools/stats-report/fetch.ts --key <鍵のパス>   取得 → stats-report/raw.json
node --experimental-strip-types tools/stats-report/report.ts                  集計と描画 → stats-report/report.html
```

**鍵は `--key` で渡す（2026-09-14 に追加）。** 環境変数 `KOTEN_STATS_KEY` でも受けるが、
`KOTEN_STATS_KEY=... node ...` は **bash の書式で PowerShell では通らない**——
依頼者の窓（PowerShell 7.6.6）で「用語 … は認識されません」で止まった。
**引数ならどちらのシェルでも同じ 1 行で済む。** `--key` が環境変数に勝つ。

**root の npm script は持たない。** `package.json` は公開側へ複写される（`publish-allowlist.txt`）ので、
script を足すとツールも公開しなければ**公開版で壊れた script が残る**——
`tests/unit/scan-publish-allowlist.test.ts` の「root の script が呼ぶツールは許可リストに載っていること」が
これを赤にする。**2026-09-13 の裁定でこのツールは公開しない**と決めたので、script も作らない。
`tools/publish-transfer` と同じ扱いである。

**一体にしない理由は検収である。** 一体だと、集計の正しさを確かめるのに毎回ネットワークと鍵が要る。
分ければ集計と描画は純粋関数になり、**fixture で試験でき、破壊試験を当てられる。**
生の JSON が残るので、**数字が怪しいときに元を当たれる**——一体型では再取得しか手が無い。

```
tools/stats-report/
  fetch.ts           入口①  鍵 → トークン → Firestore REST → 生 JSON
  access-token.ts            サービスアカウント鍵 → アクセストークン（node:crypto のみ）
  decode.ts                  Firestore の Value 形式 → 素の値
  report.ts          入口②  生 JSON → 集計 → HTML
  aggregate.ts               文書の配列 → 合計と日別（純粋関数）
  render.ts                  集計 → HTML 文字列（純粋関数）
```

**依存は1つも増やさない。** `T-18 dependencies は preact だけである` を守る。
JWT の署名は Node 内蔵の `node:crypto` で行う。既存の `transport.ts` と同じ REST 経由で、家の作りに合う。

**復号器は `tools/` に置く。** `packages/shared/src/telemetry/` へ入れると X-8/X-9 の 7 ファイル目になって赤くなる。

**出力は `stats-report/`（`.gitignore` に追加）。** `scan:publish` は 2 つの `dist/` しか走査しないので公開検査には入らない。
**Artifact として公開しない**——実利用データである。

## 2. 資格情報

サービスアカウント鍵の JSON を環境変数 `KOTEN_STATS_KEY` で受け取る。
`.gitignore` は `**/service-account*.json`・`*.key` を既に除外済みなので、置いても追跡されない。

**鍵の作り方（コンソール作業・依頼者が行う）。**

1. Google Cloud コンソール → IAM と管理 → サービスアカウント → 作成。
2. 役割に **Cloud Datastore 閲覧者**（`roles/datastore.viewer`）を与える。**書き込みの役割は与えない。**
3. 鍵 → 鍵を追加 → JSON → ダウンロード。**リポジトリの外**に置く。
4. `KOTEN_STATS_KEY` にそのパスを入れて §1 の取得コマンドを走らせる。

トークンは JWT bearer で交換する。scope は `https://www.googleapis.com/auth/datastore`。

## 3. 取得するもの

`stats_days_test` と `stats_days_official` の**両方**。いまは test 側だけに溜まるが、
正式公開で切り替わったときに取り忘れないため。文書ごとにどちらから来たかを記録する。

`raw.json` には**取得日時を必ず入れる**——古い HTML を今日のものと読み違えないため。

## 4. 出す数・出さない数

**出す。** 端末数（異なる利用番号）・日数・閲覧数・解答数・ボタン 6 項目・入口 6 項目・出題形式 2 項目。
それぞれ**合計と日別**。

**出さない: 習熟度（`masteryAvg`・`masteryMax`）。** 端末ごとの平均を足して割ると**平均の平均**になり、
端末の利用量が違えば実態とずれる。正しく出すには重み付けが要るが、求められたのは回数である。
**誤った数を 1 つ増やすより出さない。**

**ラベルは画面の文言から取る。** 入口は `ENTRY_LABELS`（`packages/hyakunin/src/domain/entry.ts`）を
**import する**——複製すると片方だけ古くなる。ボタン側は定数が無いのでツールに作り、
**鍵集合が `BUTTON_KEYS` と一致することを釘で押さえる。**

| key | 画面の文言 | 数えているもの |
|---|---|---|
| `start` | （画面の語なし） | 学習セッションの開始数 |
| `answer` | （画面の語なし） | 解答数 |
| `hint` | （画面の語なし） | ヒントを使った解答数 |
| `reveal` | 答えを確認する | 押した回数 |
| `history` | これまでの記録 | 開いた回数 |
| `report` | 問題を報告 | 押した回数 |

**`attemptCount` は `buttonCounts.answer` と同じ数である。** 同じ数を 2 つの名前で並べると読み違えるので、
報告に注記を出す。

## 5. 気をつける点（いずれも過去に起きた型）

**`integerValue` は文字列で返る。** `Number()` を忘れると `"3" + "4"` が `"34"` になり、**合計だけが静かに壊れる。**

**旧 5 キーの文書が混ざる。** `author` 入口は後から足した（`LEGACY_ENTRY_KEYS`）。
古い文書に項目が無く、**欠けを `0` として扱わないと `NaN` が伝播して合計が全部消える。**

**知らないキーは黙って捨てず、警告に出す。** `FIREBASE_CONSOLE_TODO.md` §5b で
「入口が 1 つ足りない」が起きたのと同じ型である。捨てると次も気づけない。

**0 件を空の表にしない。**「0 件だった」と明記する。空の表は「使われていない」と読めるが、
実際は鍵の権限不足かもしれない。**403 も 0 件も黙って成功にしない。**

## 6. 試験

**fixture を手書きしない。** 既存の `encodeStatsFields()` を呼んで作り、**復号して元に戻ることを見る**（往復試験）。
手書きすると、送信側の形が変わったときに fixture だけ古い形のまま緑を出し続ける。
**値は項目ごとに全部違う数にする**——全部 0 や同じ値だと、取り違える実装でも往復が通る。

**`fetch.ts` は試験しない。** ネットワークと鍵が要るものを混ぜると赤の意味が薄まる。
代わりに**取得以外を全部純粋関数へ押し出し**、`fetch.ts` に残るのは「呼んで書き出す」だけにする。
**試験しない部分を小さくするのが、試験しない判断の対価である。**

**`tests/**` は公開される。** ところがこのツールは公開しない。素直に import すると**公開側の CI が壊れる。**
`tests/unit/stats-report/guard.ts` が `existsSync` で守る（`tools/publish-transfer` の試験と同じ形）。
**この守りは赤ではなく skip で失敗する**ので、番人を 1 本だけ守らずに置いた——
`docs/` も公開の許可リストに無いため、**在ることが「ここは作業用リポジトリである」の印**になる。

### 破壊試験（2026-09-13 実測・すべて復元済み）

| 破壊 | 赤くなった試験 |
|---|---|
| `decode`: `Number()` を外す | 復号の往復／integerValue が数（**2 件**） |
| `aggregate`: 欠けたキーの `0` を外す | 旧 5 キーの文書（1 件） |
| `aggregate`: 日付の並べ替えを外す | 日別は昇順（1 件） |
| `aggregate`: 未知キーの検出を外す | 集計の警告／描画の警告 2 件（**3 件**） |
| `render`: 0 件の分岐を外す | 0 件の断り（1 件） |
| 守り: ツールを隠す | 番人 1 件が赤・21 件 skip |
| 守り: ツールと `docs/` を隠す（公開ツリーの再現） | **0 件**（公開側は緑のまま） |

**`render` の 0 件は、最初 1 件も赤くならなかった。** 試験が `0 件` を探しており、
見出しの「文書 0 件」に当たっていた——**断りを消しても緑**だった。
探す語を断りの本文へ変えて、狙った 1 件だけが赤くなることを確かめ直した。

## 7. やらないこと

- **`firestore.rules` を触らない。** 読み出しを開けると、URL を知っている誰でも全統計を読める。
- **偽造の穴を塞がない。** それは App Check の施行の別発注である（`HANDOFF_DIFFICULTY_LADDER_PLAN` 参照）。
- **習熟度の集計。** §4 のとおり。
- **自動実行。** 依頼者が見たいときに手で走らせる。

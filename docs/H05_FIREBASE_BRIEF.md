## 0. このセッションの役割

### 0.1 やること・やらないこと

**やること**: 依頼者を Firebase コンソールの手続きに**案内する**。**それだけである。**

**やらないこと。**

- **コードを書かない。** リポジトリのファイルを 1 つも変えない（**`docs/` も含む**。記録は親担当が次回行う）。
- **`firestore.rules` を書かない。** P9-B の範囲である。
- **コレクションやドキュメントをコンソールで手作りしない。** Rules の試験と実体がずれる。
- **`packages/shared/src/app-config.ts` を編集しない。** P9-B の配線の仕事である。

> **⚠ 発注043 が Terra（Codex）で走行中である。**
> **`tests/unit/telemetry/` と `packages/` に触れないこと。** 触ると検収の基準線が壊れる。
> このセッションはリポジトリを読むだけでよい。

## 2. 絶対に守ること

### 2.1 鍵の扱い（**このプロジェクトには秘密検出の検査が無い**）

**親担当が `tools/scan-publish/index.ts` を読んで実測した**——
**`scan:publish` はビルド成果物の「拡張子」しか見ておらず、ファイルの中身を一切走査しない。**
つまり **`app-config.ts` に秘密鍵を書いても、どの検査も止めない。**
`.js` にビルドされ、GitHub Pages へそのまま公開される。**人が気をつけるしかない。**

| 種別 | 公開してよいか | 置き場所 |
|---|---|---|
| Firebase Web 設定（`apiKey` `authDomain` `projectId` `appId` `messagingSenderId` `storageBucket`） | **公開してよい。** クライアントに埋め込む前提の識別子であり、秘密ではない。守るのは Rules と App Check であって、この値を隠すことではない | P9-B が `app-config.ts` へ入れる |
| reCAPTCHA の **サイトキー**（App Check 用） | **公開してよい。** クライアントに埋め込む | 同上 |
| reCAPTCHA の **シークレットキー** | **絶対に公開しない** | **リポジトリに入れない。** Firebase コンソール側に登録するだけ |
| サービスアカウントの JSON 鍵 | **絶対に公開しない** | **リポジトリに入れない。** この案件では**そもそも不要である** |
| App Check の**デバッグトークン** | **絶対に公開しない** | 開発端末のローカルのみ |

**依頼者へ伝えること**: 「上の 2 行はコードに入る前提の値なので、そのまま持ち帰って構いません。
下の 3 行は、この会話にも貼らないでください。」

### 2.2 取り返しがつかないもの

- **Firestore のロケーションは後から変更できない。** 決める前に一度手を止め、依頼者に確認する。
- **プロジェクト ID も後から変更できない。**

## 4. 手順（**親担当の未確認の理解。一次情報で確かめてから案内すること**）

> **⚠ この節は実機で確認していない。**
> **Firebase のコンソールは変わる。**
> **案内する前に、その手順の一次情報（Firebase の公式ドキュメント）を確かめること。**
> **確かめた結果ここと違っていたら、S-5 として記録し、一次情報のほうに従うこと。**

### 手順 1: プロジェクトの作成

1. Firebase コンソールでプロジェクトを新規作成する。
2. **請求先を既存のアカウント**（`shukudai-kanri` と共有しているもの）にする。
3. **控える値**: プロジェクト ID、プロジェクト名。

**ここで S-1 の確認をする**——カードの新規登録を求められないこと。

### 手順 2: 予算アラート（**H-05 の中心**）

1. **スコープを「プロジェクト」にして**予算を作る。
2. 金額は**無料枠相当＝実質 0 円超過**で通知が飛ぶように置く。
3. 通知先（メールアドレス）を設定する。
4. **控える値**: 閾値、通知先、**スコープがプロジェクトであることの画面の記録**（スクリーンショットが望ましい）。

**ここで S-2 の確認をする**——スコープがアカウントにしかできないなら止まる。

### 手順 3: Firestore の有効化

1. **Native モード**で有効化する。
2. **ロケーションを決める前に、依頼者へ「これは後から変えられません」と伝えて確認を取る。**
3. **控える値**: ロケーション、モード。

### 手順 4: App Check の登録

1. Web アプリを登録し、**App Check のプロバイダを選ぶ**。
2. **迷いが出たら S-4 で止まる。**
3. **控える値**: プロバイダ名、**サイトキー**（公開してよい値）。
   **シークレットキーは控えない。会話にも貼らない**（§2.1）。

### 手順 5: 無料枠の実条件を確かめる（**§4.2 の上書き**）

`docs/HANDOFF.md` §4.2 は次のように書いているが、**これは親担当の未確認の理解である。**

> Functions は gen1 / gen2 で無料枠の数え方が違う。どちらを使うかと、その無料枠の実際の条件は
> P9-C の起票時に一次情報で確かめること。ここに書いた理解を転記しない。

**一次情報で確かめ、実際の条件を持ち帰ること。** これが P9-C の起票の前提になる。

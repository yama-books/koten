当初は3件（入口の再編／出題画面／配点の復帰）と見積もった。**しかし3つは互いに依存しており、別々に出荷できない。**

## 2. 裁定

### 裁定1：出題形式は**4〜5択のみ**

生成済みの作者問題は3形式ある（各100問）。

| 形式 | `questionId` | 中身 |
|---|---|---|
| **4〜5択** | `-author-choice` | 歌本文を示し、作者名5件から選ばせる |
| 漢字候補→ひらがな | `-author-kana` | 歴史的仮名遣いで読みを答えさせる |
| 自由入力 | `-author-free` | 作者名を自由に書かせる |

**初回は `-author-choice` だけを出す。**

- **目的は「歌と作者を結びつける」ことであり、作者名を漢字で書けることではない。**
  自由入力は綴りの壁で正答率が落ち、**習熟度が実力を反映しなくなる。**
- 読みを問う `-author-kana` は、穴埋め側で仮名遣いを扱っているため、初回は重複する。

**費用の断り**：`-author-free` なら**新しいUIが要らない**（既存の入力欄で足りる）。
選択肢UIを作らない方が安いが、**上の理由で採らない。** 依頼者が費用を優先するなら `-author-free` へ差し替えてよい——
その場合は本裁定を取り直し、受入条件の「選択肢」を「入力欄」へ読み替えること。

### 裁定2：習熟度の配点を **本文80%＋作者20%** へ戻す

`packages/shared/src/domain/mastery/poem.ts` の `TEXT_WEIGHT` / `AUTHOR_WEIGHT` を `0.8` / `0.2` へ戻す。
**戻し方は同ファイルのコメントに書いてある。**

**「作者 未確認」の併記も復活させる**（`Result.tsx`・`History.tsx`）。**外す手段が無い印ではなくなる**ためである。

### 裁定3：入口は **歌本文／作者／本番** の3択

「学習方法を選ぶ」を左右に並べた3択にする。内部の入口IDは既存のものを充てる。

| 画面の名前 | 内部ID | 中身 |
|---|---|---|
| 歌本文 | `learn` | 穴埋めのみ（現行のまま） |
| **作者** | **新設または `quick` の転用** | **作者問題のみ** |
| 本番 | `exam` | 穴埋め＋作者を混ぜる |

**「とりあえず始める」は穴埋め＋作者のミニテストへ戻す**（`quick` の当初計画）。
`ENTRY_RULES.quick` は既に `{ questionCount: 8, blankWeight: 3, authorWeight: 1 }` を持っている。

**「歌を確認する」「作者名を確認する」の閲覧2つは残す。** 3択とは別の場所に置く。

## 3. 工程1：作者問題を出せるようにする（**単独で出荷できる**）

### 3.1 出題画面

**現在の `Session` は穴埋め専用である。** 歌を縦書きで出し、1句を空欄にする作りで、**選択肢を選ばせるUIが存在しない**（`packages/hyakunin/src/ui/` に `candidates` の参照は0件）。ここが本発注で最も大きい。

- 作者問題の `prompt` は**歌の本文そのもの**である。空欄は無い。`type === 'author'` で分岐する。
- 候補は `question.candidates`（5件）。**並びは生成済みで固定**——画面で並べ替えないこと。
  誤答候補は近い番号の首から採ってあり、並べ替えると難度が変わる。
- 選んだ候補で即時に答え合わせする。**正誤の表示は穴埋めと同じ部品を使う**（`AnswerFeedback`）。
- **本番（`exam`）では解答中に正誤を出さない**——既存の禁止をそのまま守る。

### 3.2 出題規則

`planQuestions` は `learn`・`exam` とも `type === 'blank'` に絞っている。**この絞り込みを入口ごとに変える。**

- `learn`（歌本文）：穴埋めのみ。**現行の挙動を変えないこと。**
- 作者：作者問題のみ。
- `exam`（本番）：穴埋めと作者を混ぜる。`ENTRY_RULES.exam` は既に `blankWeight: 1, authorWeight: 1` を持つ。
- `quick`（とりあえず）：`ENTRY_RULES.quick` のまま（8問・穴埋め3：作者1）。

### 3.3 受入条件（工程1）

- **作者問題が実際に出題され、答えられ、記録される。** `itemKey` が `<poemId>:author` で保存されること。
- **配点が本文80%＋作者20%に戻っている。** 本文100・作者0が **80%で止まる**ことを単体で確かめる
  （058で「85でも緑」へ書き換えた試験を元へ戻す。**書き換えた試験の一覧は058 §4.2にある**）。
- **「作者 未確認」が、作者問題に答えると消える。** 両方向で確かめること——
  答える前は付き、答えたあとは消える。**片方だけでは、印が常に消えている実装も通ってしまう。**
- 候補の並びが生成データと一致する（画面で並べ替えていない）。
- **本番の解答中に正誤が出ない**（既存の禁止。056 F-1〜F-2 を弱めない）。
- 320px・文字200% で作者問題の画面に違反0。**`tools/overflow-check/index.ts` に走査を足すこと**——
  既存5群は穴埋めしか測っていない。**件数の門（過不足で非0）を必ず付ける。**
- 既存の全ゲートが緑。**画面試験180件・node 514件を下回らないこと。**

### 3.4 破壊試験（工程1、3件）

1. 配点を本文100%へ戻す → 「本文100・作者0は80%で止まる」だけが赤くなること。
2. 候補を画面で並べ替える → 並びを見る試験だけが赤くなること。
3. 作者問題の `itemKey` を `:text` にする → 「作者未確認が消える」だけが赤くなること。

**各回で「何件が赤くなり、何件が緑のまま残るか」を記録する。** 全部赤くなる破壊は別の欠陥を叩いている。

## 4. 工程2：入口を3択へ再編する

- 「学習方法を選ぶ」を **歌本文／作者／本番** の3択にし、左右に並べる。

- 「歌を確認する」「作者名を確認する」は残し、3択とは別の場所に置く。

### 4.1 受入条件（工程2）

- 3択が320px・文字200%で**横に並んだまま器を超えない**か、超えるなら縦へ落ちること。**切れないこと。**
- 「とりあえず始める」から**穴埋めと作者の両方が出る**こと。**8問であること。**
- 入口ごとの出題種別が裁定3の表と一致すること（**4つとも**確かめる。1つ代表では足りない）。
- `ENTRY_LABELS` を使い、画面の名前を2か所に書かないこと。

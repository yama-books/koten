## 裁定 15: M-15 の弱化は「`onComplete` が受け取った件数」で行う（**§6 の書き方を訂正する**）

**§6 の M-15 は「`T-9` を『保存関数が呼ばれた回数』の比較に書き換える」と書いてある。この書き方は誤りである。**

**理由**——**親担当が指定した M-11**（`result: await port.appendEvent(event),` → `result: {} as never,`）**は
`port.appendEvent` を呼ばなくする。** したがって「呼ばれた回数」を数える弱い試験も**赤くなる**。
**M-15 は緑で通るはずの破壊なので、そのままでは S-6 が誤爆する。**
**Terra が勝手に別の弱い試験へ置き換えず保留したのは正しい。**

### 正しい弱化の形

**`T-9` を「`onComplete` が問題数と同じ件数の outcomes を受け取ったか」を見る試験に書き換える。**
**保存されたイベントは数えない。**

```ts
// 弱化した T-9（M-15 のあいだだけ。測ったら cp で戻す）
let received: readonly unknown[] = [];
// …本番を最後まで解いて採点を確定させる…
expect(received).toHaveLength(questions.length);   // onComplete が受け取った件数だけを見る
// port に入ったイベントは数えない
```

**両方向の assert（確定前 0 件）も、`onComplete` が呼ばれていないことで代用する。**

### なぜこれで差が出るか（**当てる前に読んで納得しておくこと**）

`Session.tsx` の `finalizeExam` は、保存の成否を **`saved.some(({ result }) => "reason" in result)`** だけで見ている。
**`result: {} as never` は `reason` を持たないので「成功」として通る。**
その先で `nextOutcomes` は**問題数と同じ長さで組み立てられ、`onComplete(nextOutcomes)` がそのまま呼ばれる。**

| 見ているもの | M-11 を当てたとき |
|---|---|
| **`createMemoryPort` に入ったイベントの件数**（本来の `T-9`） | **0 件。赤くなる** |
| **`onComplete` が受け取った件数**（弱化した `T-9`） | **問題数と同じ。緑のまま通る** |

**これが M-15 で見せたかったことである**——**部品が値を渡すことだけを見ると、その先を壊しても緑のままになる。**

### 手順

1. **`T-9` の控えを `cp` で取る。**
2. **`T-9` を上の形に書き換える**（弱化）。
3. **M-11 をもう一度当てる**（`result: {} as never,`。`grep -c` で 1 を確認）。
4. **測る。** **緑のまま通るはずである。**
5. **`cp` で両方戻す**（試験と実装。1 つずつ）。
6. **報告に「緑で通った／赤くなった」を明記する。**

**赤くなったら S-6 である。** そのときは**弱化した試験の実際のコードを報告に貼ること**——
親担当の想定と、あなたが書いた弱化がずれている可能性が高い。

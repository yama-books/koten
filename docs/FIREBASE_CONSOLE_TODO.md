## 5b. 【2026-09-06 追記】規則の入口一覧が実装より1つ足りない

**発注062が入口 `author`（作者）を新設したが、統計側は5つのままである。**

- `packages/shared/src/telemetry/registry.ts` の `ENTRY_KEYS` は
  `['quick', 'view', 'learn', 'review', 'exam']`。**`author` が無い。**
- `firebase/firestore.rules` も同じ5つを `hasAll` で要求し、**`size() == 5` で固定している。**
- 集計側（`domain/stats.ts`）は `session.entry in entryCounts` で弾くため、
  **作者入口の利用は統計に1件も現れない。**

**「指導のために正確な集計を得たい」という目的に直接反する。** 作者は独立した学習入口であり、
それが使われた回数が見えないのでは、入口ごとの利用を比べられない。

**今日は直さないこと。** 直す順序が決まっている——

1. **先に規則を6キーへ広げて配置する**（`size() == 6`、`hasAll` に `author` を追加）。
2. **そのあとコード側の `ENTRY_KEYS` に `author` を足す。**

**逆順にすると、配置済みの規則が6キー目を拒否し、統計の書き込みが全部失敗する。**
（失敗しても学習は止まらず送信待ちへ積まれるだけだが、その間の統計は1件も残らない。）

**これは発注062の落ち度ではない。** 062の準備書が「統計は対象外」と境界を引いたためで、
**境界の引き方を誤ったのは起草者（Sol役）である。** 別発注として起票すること。

## C. 作業B：匿名認証を有効にする（**必須**）

実装が実際に送信を試したところ、**`400 CONFIGURATION_NOT_FOUND` で止まった。**
Identity Toolkit の `accounts:signUp` がこれを返すのは、**匿名認証が有効になっていないとき**である。

1. Firebase コンソール → 構築 → Authentication → Sign-in method。
2. **「匿名」を有効にする。**

**なぜ要るのか**：規則そのものは認証を要求していない（`request.auth` は書かれていない）。
しかし**アプリ側の送信が匿名認証を先に通す作りになっており**、そこで止まっている。

## D. 【重要】匿名アカウントが積み上がる問題（**有効にする前に読む**）

**送信のたびに匿名アカウントが1つ作られ、消されない。**

- `packages/hyakunin/src/telemetry/stats-sender.ts` は送信ごとに `accounts:signUp` を呼ぶ。
- **`transport.ts` には `anonymousDeleteRequest`（削除要求）が用意されているが、どこからも呼ばれていない。**
  設計側は使い捨てにする前提で関数を置いたのに、**配線が抜けている。**
- このまま有効にすると、**1端末あたり1日1個**の匿名アカウントが増え続ける。

**判断**——

- **有効にしてよい。** ただし**削除の配線は別発注で必ず入れること。** 起票済みにしておくこと。
- 当面はテスト公開で端末数が少ないため、増加は緩やか。**放置してよいという意味ではない。**
- 有効にしたあと、**Authentication のユーザー数を時々見ること。** 想定より増えるようなら報告する。

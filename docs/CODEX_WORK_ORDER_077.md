# 発注077案 — 作者問題の「わからない！」で保存後に正解を開示する

起草: 2026-09-08 / Codex（設計監査継続）
状態: 起草済み・実装未着手。U1だけを扱う限定修正案。U2の表示案、U3、A〜I、commit・push・公開は含まない。

## 1. 問題と根拠

基準HEADは `0c21dbf0c5b88dc93d25ddc51e376e0c151b17b4`。起草時に製品の追跡ファイル差分は無い。既存の文書差分と未追跡資料は他者作業として保持し、本発注では変更・削除しない。

再現条件は、画面入力の通常練習で作者選択問題を表示し、候補を選ばず「わからない！」を押し、閲覧イベントの保存が成功すること。`quick`（「とりあえず始める」）で作者問題に到達した場合を利用者経路の代表とする。

2026-09-08に、既存の作者問題fixtureとメモリ保存を使った限定再現を実行した。結果は次のとおり。

- 保存イベントは1件で、`kind: "view"`、`outcome: "viewed"`、作者問題の `questionId` を保持した。
- 保存成功後の画面には「答えを確認しました。」が出た。
- 同じ画面に「正解：持統天皇」は出なかった。作者候補も開示後に消えるため、正しい作者名を確認できない。
- 再現用の一時試験はこの4点を検出した後に削除し、製品・恒久試験は変更していない。

原因は `packages/hyakunin/src/ui/screens/Session.tsx:478-515` と `575-580`、`739-749` の組合せである。`showUnknown()` は保存成功後に `phase: "revealed"` とする一方、`judgement` と `submitted` は `null` のままにする。そのため `feedback` は `null` となり、正解表記を持つ `AnswerFeedback` ではなく固定文だけの `unknown-feedback` 分岐へ入る。作者問題は本文穴埋めと異なり、`Session.tsx:625-661` の問題本文側にも正解を埋める場所がない。

この原因は現行コードから確認でき、075または076が原因だとは断定しない。075は結果画面、076は回答欄配置の発注であり、本件の修正境界にも含めない。

読んだ範囲は `docs/DESIGN_AUDIT_CONTINUATION.md`、`docs/HANDOFF.md` の2026-09-08実機報告と関係裁定、`docs/APP_SPEC.md` の入口・作者問題・本番・閲覧・再確認規則、発注075・076の変更境界、現行 `Session.tsx`、`AnswerFeedback.tsx`、`flow.ts`、`ports.ts`、Session・結果集計・開示時機の対象試験である。矛盾が無かったため、既存監査全件には範囲を広げていない。

## 2. 採る仕様

通常練習または再確認の作者問題で「わからない！」を押した場合、閲覧イベントの保存成功後に、現在の「答えを確認しました。」に加えて正しい作者を開示する。作者の正解表記は、同じ問題を誤答したときに既に使う表示規則と同じものとし、少なくとも `正解：{正式な作者名}` を読めること。現代読みと、それと異なる歴史的仮名遣いの扱いも既存 `AnswerLines` / `AnswerFeedback` の作者表示規則に揃え、別の文字列組立てを増やさない。

開示は保存成功後だけとする。保存待ち・保存失敗では正しい作者名を出さず、「答えを確認しました」と成功を名乗らない。失敗後は現在の再試行可能な状態を保つ。

本文穴埋めの「わからない！」は、保存成功後に問題本文の空欄へ正解が入る現行動作を維持する。本件を理由に、本文の正解行を追加・重複させることは必須にしない。

本番では、作者問題を含め、解答中に正答を開示しない。「わからない！」は空の回答として記録して次へ進み、全問終了後の採点一覧で初めて正しい作者を確認できる現行時機を維持する。

依頼者要望のうち、✓、空欄風の表示、「要確認！」、自分の答え欄を組み合わせる案はU2として分離する。本発注では現行の状態文「答えを確認しました。」を維持し、正解欠落だけを直す。`viewed` を `incorrect` へ変えず、架空の選択、空文字の `submitted`、自分の答え用textboxを作らない。

- `tests/screen/session.test.tsx` のU1対象試験。開示時機の既存試験に作者問題の条件を加える必要がある場合は `tests/screen/feedback-timing.test.tsx`。
- 実装後の検収記録 `docs/CODEX_WORK_ORDER_077_ACCEPTANCE.md` と、本発注で実際に変更した仕様の該当文書。

変更不可:

- `domain/flow.ts` の判定、問題データ・作者表記、候補生成、出題比率・順序、本番の採点時機、保存ポート。
- 作者候補の選択UI、本文回答欄、紙回答、結果・履歴・ホーム、他製品、共通スタイルの一括変更。
- U2の表示デザイン、U3、A〜I、075・076の再実装。

原則として `Session.tsx` と対象試験だけで完結させる。正解データやイベントの変更が必要に見えた場合は実装せず、停止条件に従う。

## 4. 受入条件

1. **作者・通常練習の陽性例:** `quick`、`author`、または`review`相当の非本番Sessionで、作者問題の「わからない！」を押し保存が成功すると、状態文と `正解：{その問題の正式な作者名}` が表示される。作者読みがあるfixtureでは既存作者表示規則どおりの読みも表示される。
2. **本文の回帰例:** 本文穴埋めで同じ操作をすると、保存成功後に空欄の正解が開示され、閲覧イベントは1件だけである。正解表示の重複を新たに生じさせない。
3. **本番の陰性例:** 本番の作者問題で「わからない！」を押しても、その問の正しい作者名、読み、正誤は解答中のDOMと読み上げに出ない。全問終了後の採点一覧には正解が出る。
4. **保存失敗の陰性例:** 作者問題の閲覧イベント保存が失敗した場合、正しい作者名と「答えを確認しました。」は出ない。失敗案内が出て、利用者は同じ問題で再試行できる。失敗した試行を保存済みとして次へ進めない。
5. **記録意味の維持:** 保存成功時のイベントは `kind: "view"`、`outcome: "viewed"` のままで、作者の `itemKey` と元の `questionId` を保持する。結果集計ではその問題IDが再確認対象に含まれ、`incorrect`、架空のsubmitted、架空の回答文字列へ変換されない。
6. **076回帰の維持:** 作者問題にtextboxや空の「自分の答え」欄を新設せず、途中まで入力した文字列や存在しない選択を採点済み回答として表示しない。「わからない！」の1操作でイベント、通知、遷移を重複させない。
7. **アクセシビリティと表示:** 開示された正解は見た目だけでなくテキストとして読み上げ可能で、保存成功後の通知は過不足なく1回である。既存幅320〜1024px・文字100%/200%で横切れ、重なり、44px未満の操作を新たに生じさせない。

恒久試験は少なくとも、作者の保存成功、作者の保存失敗、本番作者の先行非開示、`viewed`と再確認対象の維持を直接検出する。本文用fixtureだけを作者修正の証拠にしない。

## 5. 停止条件

次の場合は変更を広げず、事実と最小の代案を報告する。

- 正しい作者の開示に、正解データ、候補生成、判定、イベント、保存、結果集計の変更が必要になる。
- 保存成功前または本番の解答中に正解がDOM、アクセシビリティツリー、疑似要素へ漏れる。
- `viewed`を`incorrect`へ変える、空のsubmittedや架空の自分の答えを作る必要が生じる。
- 既存作者表示の再利用が別画面・本番・本文の表示を変え、`Session.tsx`内の限定分岐で止められない。
- 他者の製品差分が入り基準を特定できない、または対象試験・必須ゲートに未解決の失敗がある。

U2の文言・印・空枠の判断はU1を止める理由にしない。正解欠落を直した上で別発注に残す。

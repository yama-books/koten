## 3. 表示仕様

### 回答の枠組み

画面入力の回答領域は、縦書き／横書き、出題／採点後で共通の外枠を用いる。外枠は既存の30remを基準に `min(利用可能幅, 30rem)` とし、中央に置く。本文が長いときは本文側で自然な折返し・必要なスクロールを許し、回答欄まで全幅へ広げない。

印の列と入力の列を出題時点から確保する。印がない段階の列は視覚的に空でよく、読み上げ内容を追加しない。○／チェックは回答の左に表示し、入力文字と重ねない。印の寸法と間隔は既存トークンから選び、印のために入力幅を過度に削らない。

本文の入力欄は、同じ問題の採点前後で同じDOM要素を維持し、保存成功後にreadOnlyへ移行する。値は送信した原文字列のまま。ラベルを「答え」から「自分の答え」へ変える場合も、一行分の場所と欄の位置を変えない。回答欄の下に、判定・正解・仮名遣い補足・注記、その後に「次へ」を置く。読み上げ順もこの順序とし、判定通知は1回にする。

「わからない！」では存在しない送信文字列を作らない。入力途中の文字列を採点済みの回答として表示しない。作者の選択式では入力用textboxを新設せず、既存の候補と選択結果を保持する。紙回答でも架空の入力欄を作らない。

### 位置と余白

同じ問題・表記・書字方向において、採点前後で回答欄のx/y/幅/高さを維持する。印や正解の説明を理由に欄を押し出さない。問題本文内の空欄が正解表示で伸びる場合も調べ、本文の必要な領域を確保する。正解文字列を非表示DOM、アクセシビリティツリー、疑似要素へ先出しして高さを測らない。画面外へ回答欄を絶対配置して位置を偽装しない。

書字方向・表記を利用者が切り替えた場合は、回答欄のxと幅を維持する。縦書きと横書きの本文の自然な高さは異なるため、切替時のyの完全一致は今回の必須条件にしない。本文を切り捨てたり、全問に過大な固定高を設けたりして揃えない。切替時のyの差は計測・報告し、残課題として区別する。

進捗下の罫線と表示切替ボタンの間には既存の最小8px相当の余白トークンを設ける。原文表示でも状態行を確保し、「原文を表示中」等、実際の状態を示す。読みの各状態では既存の正確な状態名を維持する。同一幅で状態行の文字が折り返す場合は自然に高さを増やすが、罫線とボタンは接しない。結果画面や本番に不要な読み切替を追加しない。

## 4. 受入条件

### 位置の数値

- 幅320・375・414・768・1024px、文字100%・200%、縦書き／横書きで確認する。計測は同一viewport・同一文字倍率、フォント読み込み後の文書座標（DOM矩形にスクロール量を加算）で行う。
- 本文入力の出題→正答、△、誤答の各遷移で、同一inputのx/y/幅/高さの差がそれぞれ1 CSS px以内。保存中・保存失敗でも入力値と入力位置を失わない。
- 同一問題で縦書き↔横書きに切り替えたとき、回答外枠と入力欄のx/幅の差が1 CSS px以内。yの差は別列に記録する。
- 入力幅は、印を含む回答外枠幅の70%以上を確保する。印と入力の矩形は交差せず、印は左にある。文字200%でも満たす。
- 進捗罫線下端から表示切替ボタン上端まで8 CSS px以上。原文・歴史的仮名遣い・現代仮名遣いの各状態を測る。
- 横切れ・文字欠け・本文と回答の重なりを生じない。操作は44px以上。余白を削るための書体縮小はしない。

21番の実際の問題IDを記録して代表例にする。さらに原文／読みの長い問題、最初と最後の句の空欄、作者問題を含める。21番だけ通る固定値で合格としない。

### 学習と記録

- 歴史的仮名遣いの入力案内、○／△／誤答の意味、正解と注記を残す。正解開示前のDOM・読み上げに新たな正解漏洩がない。
- 誤答の自分の文字列、前後の空白等を勝手に正規化・正解へ置換しない。
- 保存失敗の再試行、連打、本番の回答記録、紙の自己採点、再確認途中の中断について既存の保存・遷移規則が維持される。
- 本番では解き終わる前に正解や採点を開示しない。紙の自己採点の未採点問題がある場合に結果へ進めるようにはしない。
- 作者問題の選択肢の書字方向と操作性を維持する。見かけ上の共通化のために本文入力として扱わない。

## 5. スマートフォンのキーボード

今回、OSキーボードの高さをアプリから固定したり、強制スクロールを繰り返したりしない。キーボードで歌が隠れる問題は、この配置修正後に実機で評価する後続項目である。

ただし今回の変更が入力を壊していないことは確認する。iOS Safari・Android Chromeの実機で、かな入力、変換確定前、採点、次問、キーボードを閉じて歌へ戻る操作を確認する。実機が使えない場合は「実機未確認」と明記し、この項目の検収は保留する。デスクトップのviewport縮小やエミュレーションを実機確認の代用と報告しない。

OSによるviewport変化・スクロールを、上記の文書座標1px条件の対象と混同しない。実機では入力欄・案内・採点操作への到達、意図しない強制移動やフォーカス消失の有無を判定する。

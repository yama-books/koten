## 2.4 MVP④ の内訳（2026-09-06 実測）

`packages/shared/src/storage/` の輸出21個のうち、`packages/hyakunin/src` が参照しているのは**3個だけ**である。

| 輸出 | 使用状況 |
|---|---|
| `openDatabase`・`readFallback`・`writeFallback` | IndexedDB ポートが使用。**保存自体は動いている** |
| `createExport`・`makeExportDocument`・`serializeExport`・`summarizeExport` | **未参照** |
| `parseImport`・`applyImport` | **未参照** |
| `mergeEvents`・`mergeSessions`・`mergeReports` | **未参照** |
| `resetRecords`・`previewReset`・`makeResetConfirmation` | **未参照**（記録の削除も導線が無い） |

`tests/unit/storage/` は35件すべて緑であり、**関数そのものは動く。欠けているのは画面からの導線だけである。**

**作者問題と同じ型の見落としである**（生成・実装・試験はあるが、UIから到達できない）。`npm test` は緑のままなので、試験だけでは気づけない。**「実装がある」と「使える」を分けて数えること。**

**検証方法**（再実行できる形で残す）：

```
grep -hoE "export (async )?function [A-Za-z0-9_]+|export const [A-Za-z0-9_]+" packages/shared/src/storage/*.ts   | sed -E 's/export (async )?(function|const) //' | sort -u
# 出た名前を1つずつ packages/hyakunin/src で grep -rlw する
```

**推測した関数名で grep して空だったことを未配線の証拠にしないこと。** 最初にそれをやり、輸出名を確かめて引き直した。

## 2.5 MVP④ の配線（2026-09-06、Opus 5）

**画面**：`RecordTransfer.tsx` を新設し、「これまでの記録」の**着手した歌の直後**へ置いた。最初は全100首の一覧の下に置いたが、**100行スクロールしないと届かない**ため上へ移した（320px の実機相当で気づいた）。記録が空のときも出す——別の端末から持ち込む人には、そこが唯一の入口だからである。

**取り込みは2段階**にした（`APP_SPEC` §9「読み込み前に件数を示して確認する」）。ファイルを選ぶと件数・対象製品・書き出し版を表示するだけで、**下見の段階では1件も書かない。**「この内容で読み込む」を押して初めて `applyImport` が走る。結果は「◯件を追加し、◯件は同じ記録なので重ねませんでした」と出す。

**ポート**：`ApplicationPort` に `exportRecords`／`previewImport`／`commitImport` を足した。`packages/shared/package.json` の輸出マップに **`./storage/export`・`./storage/import` が無く**、そもそも import できない状態だったので追加した（未配線の裏付けでもある）。

**任意型にした代償と、その埋め合わせ**：3つの口は `Partial<TransferPort>` で任意にしてある（`Home.tsx` の簡易ポートに実装を強いないため）。**本番のポートから落ちても型は通り、画面は黙って機能ごと消える。** そこで `tests/screen/history-transfer.test.tsx` に「本番のポートは3つの口をすべて持つ」を名指しで置いた。破壊試験で `exportRecords` を落とすと、**この1件だけが赤くなる**ことを確認した。

**320px・文字200% の実測**：違反0、測定対象6件、ページのあふれ0。途中で2つ直した——(1) ネイティブのファイル入力が固有幅で縮まず器を548pxへ広げていた。入力を `sr-only` で隠し、ラベル自体をボタンとして見せる形にした（入力はラベルの子なので押せば選択画面が開き、支援技術にはそのまま見える）。(2) ボタンの文字が器を2px超えていたので折り返しを許した。
**一度、測定対象0件で「違反なし」が出た。** HMR で画面が戻り、`.record-transfer` が存在しないまま数えていた。**測定件数を必ず併記していたので気づけた。**

**記録の削除も同日に配線した**（依頼者裁定・2026-09-06）。範囲は**百人一首の記録だけ**——この画面は百人一首のものなので、他製品まで消えるのは予期に反する。**設定（読み方・縦書き・学年）は消えない。** 送信待ちは全製品共通のため `previewReset` の仕様どおり残る。削除も2段階で、件数を見せてから押されて初めて消す。`resetRecords` は `makeResetConfirmation` を通さない限り**必ず拒否する**ため、確認の証跡が型として残る。

**取り込みと削除のあとは一覧が古くなる。** `onChanged` で親へ知らせ、`main.tsx` が読み直す。**この読み直しを足したとき、既存の「記録を開く間はloadingを表示する」が赤くなった**——`await` が1段増えて試験のタイミング前提を崩したためである。**試験を緩めず、開くときの経路を元の形へ戻して直した。**

**この節は `check:overflow` の走査対象外である。** 既存5群に「これまでの記録」画面が無いため、上の実測はブラウザーでの手動測定であって、以後の回帰では守られない。走査群の追加は `tools/overflow-check/index.ts` を触るため、Codex の059作業と衝突する。**次の担当が引き取ること。**

## 何を入れたか

### 1. ポイント（新規）

習熟度とは**別の、飽和しない積算値**。学習者からの「やった合計の点数が見たい」という
要望に応えるもの。

- **結果画面**: 問題数の下に `今回のポイント +48`
- **これまでの記録**: 画面最上部に `これまでに ためたポイント 138`（3桁区切り）

保存形式は増やしていない。習熟度と同じく**毎回イベント履歴から導出**する。したがって
導入した時点で、過去の全記録からポイントが計算される（0からではない）。

### 2. 習熟度の終盤傾斜（変更）

90 を超えたあとの増分を `+9` から **`+2`** にした。89以下は一切変えていない。

```
変更前:  90 →(1日)→ 99 →(1日)→ 100     ← 2日で終わっていた
変更後:  90 → 92 → 94 → 96 → 98 → 100   ← 別々の日に5回
```

### 3. 素材（新規）

`assets/mascot/cat-mascot.{png,webp}`。アプリアイコン右下のネコを切り出したもの。

## 裁定（依頼者・2026-09-09）

1. **得点規則は非開示。** 画面に基礎点も倍率も式も書かない。説明文も置かない。
2. **獲得点（増分）は見せる。** 隠すと記録画面の累計が出所不明の数字になり、信用されない。
   逆算されるのは「正答が多いほど増える」までで、そこは隠す必要がない部分。
3. **誤答でも点が入る（3点）。** 0にすると「全問まちがえた回は、やったのに何も増えない」
   となり、「やったぶんはやったぶんだけたまる」という裁定と衝突する。
4. **弱点倍率は最大2倍まで。** これ以上開くと、覚えた歌をもう一度確かめる行動が損に感じられる。
   復習に罰を与えるのは逆効果。
5. **習熟度は漸近させない。** 100 に永久に届かない設計は、進捗が見えないこと自体が
   離脱要因になる。終盤は「小さいが、数え切れる歩数」にする（目標勾配効果）。
6. **過去分も遡って計算する。** 0から始めると、これまで頑張った学習者が損をする。

## 設計上の要点（次に触る人が踏みやすい場所）

**ポイントは習熟度の走査に相乗りしている。** 倍率がイベント当時の習熟度に依るため、
あとから計算し直すと、強くなった今の習熟度で過去のポイントが目減りする。
`computeMastery(events, observe)` の第2引数がその相乗り口で、順序・繰り返し判定・
対応版の絞り込みを1箇所に保つためにこの形にした。走査を2本書いてはいけない。

**`MASTERY_RULES_VERSION` を上げてはいけない。** `computeMastery` は版が違うイベントを
丸ごと無視するので、上げると全利用者の習熟度が0に戻る。

**`isMasteryCompletionMethod()` が90超の関門を1箇所に集めている。** 依頼者は最終的に
「一首まるまる書ける・作者をまるごと書ける」ことを100の条件にしたい（後述）。
その難度設定が入ったら、**この関数の中身だけを差し替える**。呼び出し側は触らずに済む。

**ネコは透過。** `assets/feedback/**` は透過していないため発注074で
`filter: brightness(1.05)` + `darken` を使っているが、ネコにその処理は要らない。
切り抜きは色の一致ではなく**外周からの塗りつぶし**で行うこと。ネコの体色は背景色に
ごく近いので、色で判定すると体まで消える（`assets/mascot/README.md` に手順あり）。

## 残件

### A. 作者の習熟度が65で頭打ち（未着手・原因特定済み）

**`docs/FINDING_AUTHOR_MASTERY_CEILING.md` に全部書いてある。** 実測値・原因の行番号
（`entry.ts:97`）・注意点まで記録済みなので、**冷えた状態から資料だけで始められる。**

要約: 作者は選択式しか出題されず65で止まる。歌全体は `100×0.8 + 65×0.2 = 93` が上限で、
**100%に到達できない。** `-author-free` / `-author-kana` の問題データは実在するので、
出題経路を通すだけで解消する。見積もり 5〜8%。

### B. 一首をまるまる書く出題形式（未着手・データも無い）

依頼者裁定:「最後は作者まるごと書ける・また、一首まるまる書けないと100にならない」。

A が「経路を通すだけ」なのに対し、B は**問題データから作る**必要がある。現状は句ごとの
空所補充（`type: 'blank'`）しか無い。重さが違うので A と B は別発注にすること。

B が入ったら `isMasteryCompletionMethod()` を差し替える。差し替えると 90 が当面の天井に
なるが、そこで足踏みしてもポイントは伸び続けるので、数字が止まることにはならない。

## 2. 調査で分かったこと（依頼者の3つの質問への回答）

### Q1「要確認」と「誤答」の違いは？何を入れても要確認しか出ないのでは？

**同じ語が3か所で別のものを指しており、うち1つは動いていなかった。**

| 場所 | 意味 | 状態 |
|---|---|---|
| 答え合わせ画面「✓ 要確認！」 | 誤答 | 動く |
| 「これまでの記録」の「要確認の歌」 | 最後が誤答の歌 | 動く |
| 結果内訳の「要確認」 | `needs-review`＝正答/△の候補には当たったが、その歌の**読み**が人手未確認 | **一度も出ない** |

`needs-review` は `judge()` が `context.readingStatus === 'review'` のときだけ返す。該当する歌は100首中2首ある（`poems.json` の `reading.status`）。しかし `Session.tsx` は常に `{ readingStatus: 'confirmed' }` を決め打ちで渡しており、**2首の読み未確認が判定へ伝わっていない。** よって結果内訳の「要確認」は構造上つねに0問である。依頼者の観察は正しい。

### Q2「作者 未確認」が外れるのはどのケース？

**外れない。現状どうやっても外せない。**

`authorUnconfirmed` は「その首の `poemId:author` イベントが1件もない」で決まる。作者イベントは作者問題に答えたときだけ生まれるが、出題を組む `planQuestions` は `learn`・`exam` とも `type === 'blank'` に絞っており、作者問題を選ぶのは Home から到達できない `quick` だけである。**作者問題は300問生成されているのに、どこからも出題されていない。**

副作用：習熟度は「本文80%＋作者20%」の配分なので、作者が永久に0のままだと**どの首も最大80%止まりで、緑（85%以上）へ到達できない。** 既存の単体試験「本文100・作者0は80%で止まり緑にならない」が、この状態を正しい仕様として釘付けにしていた。

### Q3「全5回」とは何か

**「回」は20首ずつのまとまり**（`range.ts` の `MAX_CHUNK_SIZE = 20`）であり、10問ではない。1〜100首なら5回。「あと88首」は範囲全体の未確認首数、「2回目」は現在のまとまりの番号。**1回（20首）は1セッション（練習10問）では終わらない**ため、「回」と「1回の学習」がずれているのが分かりにくさの正体だった。

### 4.1b R6：読みが未確定の2首（追加裁定分）

**対象は13番（陽成院「つくばねの…」）と32番（春道列樹「山川に…」）。** 依頼者へ提示したうえで「確定済みとして扱う」との裁定を受けた。

実装：`parse-variants.ts` に `UNSETTLED`（保留／未確定／未決／要確認／要検討／判断できない／結論を出していない）を置き、`kind === '読み方式'` かつ判定欄がこれに当たる行だけを未確定とする。**判定欄は空にできない**（`parsePipeTable` が空セルを弾く）ため、「空かどうか」では判定できない。`npm run data:build` で再生成し、`poems.json` の変更は13番・32番の `status` 2か所とマニフェストの生成日だけ（読みの中身は1文字も変えていない）。`data:check` は終了コード0。

`tests/data/reading-review.test.ts` を追加。**本番の異同確認表は fixture に使わない**（正当な資料更新でこの試験が赤くなるため）。写しの表で、判定が「確定」の読み行は拾わず／「保留」の読み行だけ拾うことを両方向で確認し、走査対象が0件でないことを先に確かめている。現行の本番データに対しては「読みの行は13番・32番の2件ある」「そのどれも未確定ではない」を別に確認する。

### 4.3 残した事項

- **`needs-review` は依然として発生しない。** R6 により正本の100首はすべて `confirmed` になったため、**いまは発生しないのが正しい**。ただし `Session.tsx` が歌の `reading.status` を判定へ渡していない配線は直していない（依頼者は「未確定のまま残して配線を直す」を選ばなかった）。**将来どれかの読みが「保留」になっても判定へ届かない。** 該当箇所にその旨をコメントで残した。配線を直す場合は、`needs-review` が現状「✓ もう一度！」と表示され加点もされない（`record.ts` が `skipped` へ落とす）ため、正答候補に一致した答えの扱いを先に決める必要がある。
- **読みの確認台帳 `review/readings.yaml` は100首とも `pending`。** 既定で `confirmed` として出ている状態は R6 の裁定どおり別件として残す。承認を埋めるか、既定を逆にするか、`status` の名前を実態（異同メモの有無）へ合わせるかの選択がある。
- **作者問題300問は生成されたまま出題されない。** 今回は配点を外して整合させただけで、問題データ・生成器・`ENTRY_RULES` の `authorWeight` は触っていない。作者を戻すときは `poem.ts` の2値と `planQuestions` の絞り込みを同時に戻す。
- **習熟度一覧（100首）の見せ方**は R4 のとおり未着手。
- 出題画面のヘッダ（`nav-edge`・`back-link`・`wordmark`）と縦書きの器が、文字200%・320/375/414px で切れる。057で見つけた範囲外の既存条件で、今回も直していない。

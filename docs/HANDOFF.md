## 2. 最初に読む順序

### 2.0 文書はローカルから読むこと（GitHub 経由にしない）

**このリポジトリは非公開である。認証のないセッションが GitHub の URL を読もうとすると HTTP 404 が返る。**
GitHub は非公開リポジトリに対して 403 ではなく 404 を返す（存在自体を伏せるため）ので、
受け手には「ファイルが無い／読めない」と見える。2026-08-30 に実際にこの症状が出た。

実測（2026-08-30）:

```text
raw.githubusercontent.com/moyashimisosoup/koten/main/docs/HANDOFF.md  → HTTP 404
github.com/moyashimisosoup/koten                                      → HTTP 404
```

作業ディレクトリをリポジトリ直下（`AI開発\koten`）にし、以後 `docs/HANDOFF.md` のように
相対パスで読むこと。`raw.githubusercontent.com` や `github.com` の URL を読ませない。
ローカルのほうが新しい場合もある（未 push のコミットがありうる）。

**大きい文書は節を指定して読むこと。** `docs/IMPLEMENTATION_PLAN.md` は 2,000 行・150KB を超えており、
読込ツールの既定上限（多くは 2,000 行）に触れる。全文を一度に読むと末尾が欠ける。
本ファイルで全体像をつかみ、必要な節だけを範囲指定で読むこと。

## 3. 絶対に守ること

1. **一次資料を書き換えない。** `百人一首_*.md` 4 点と `古典文法_一次データ索引.md` は読み取り専用。変換処理・出題生成・表示都合のいずれからも書き込まない。
2. **原資料 PDF（`USB-*.pdf`）を公開しない。** 再配布許可未確認。**公開**リポジトリ・Git 履歴・raw URL・配布物のいずれにも入れない。
   現リポジトリは非公開のため PDF が入っていてよい（§7）。公開は P12 で別リポジトリ・新規履歴により行う。
3. **未確認の派生データを公開出題に混ぜない。** `reviewStatus` が `human-confirmed` でないものは出題に出さない。
4. **生成 AI だけで公開問題・正解・正本を確定しない。** AI 案には `proposedBy: "ai"` を付け、人の承認を経る。
5. **ローカル絶対パス（利用者名を含む）をコミットしない。**
6. **公開名義に個人 SNS アカウント名を使わない。** 暫定は `koten contributors`。
7. **勝手にコミット・push しない。** 依頼者の指示があったときだけ行う。

## 7. 現リポジトリの扱い（H-01・確定）

`github.com/moyashimisosoup/koten` は**非公開リポジトリ**である。用途は原資料 PDF の置き場と、Codex との共有経路である。**今後も非公開のまま存続させる。**

### 行わないこと

| 行わない | 理由 |
|---|---|
| リポジトリの削除 | 非公開であり問題が発生していない。Codex 共有経路として必要 |
| `git filter-repo` 等による履歴書き換え＋force push | Codex 側のクローンを壊す。得られるのは容量削減だけで実益がない |
| 原資料 PDF の作業ツリーからの削除 | 原資料として参照する。非公開である限り憲章 §4 に抵触しない |

補足（Git の仕様）: 一度コミットしたファイルは、`git rm` して commit しても**履歴からは消えない**。過去の commit を指定すれば取得できる。履歴から消すには履歴書き換えと force push が必要で、さらに GitHub 側の fork・PR・キャッシュ経由の参照は Support への依頼が要る場合がある。したがって「削除すれば消える」わけではない、という前提で扱う。

### 維持すべき条件（これだけ）

> **このリポジトリを public にしない。public アカウントへ transfer しない。fork を公開しない。**

停止条件 S-1' として計画に記載した。この条件は P12 の設計（新アカウント・新規履歴での移管）によって構造的に守られる。現リポジトリの履歴が公開経路に乗る手順は計画上どこにも存在しない。

### この結果として

- 停止条件 S-1（`origin` が公開設定で PDF が配信されている）は**発動していなかった**。
- `docs/HANDOFF.md` と `docs/IMPLEMENTATION_PLAN.md` は、このリポジトリで**追跡する**（Codex が読めるようにするため）。公開側への流出は `docs/PUBLISH_MANIFEST.md` の許可リストで防ぐ。`.gitignore` では除外しない。

   上位モデルは自動では下位へ落ちない。**明示的にサブエージェントを起動しないかぎり、すべてが上位モデルの単価で処理される。** 判断は上位が持ち、次のような作業は下位のサブエージェントへ渡す。
   - 参照リポジトリ・大量ファイルの読解と要約（本文脈を汚さない利点もある）
   - 広い検索・全件走査・一覧化
   - 決まった形式への機械的な変換・生成
   - 仕様が確定している実装と、その受入条件の検証
3. **上位モデルが自分でやるのは、判断そのものと、その判断の検証だけにする。**
   構造の決定、仕様の解釈、プライバシー境界、不可逆操作。
4. **調査は本文脈へ持ち込む前に分離する。** 大きな資料の読解をサブエージェントに任せ、戻ってきた要約だけを本文脈に置く。文脈が長くなるほど以後のすべての往復が高くつくため。
5. **同じ調査を二度しない。** 実測した事実は §6 に書き、次の担当者が再調査しなくて済むようにする。
6. **人間の確認待ちが発生したらセッションを切る。** 待ちのあいだ文脈を保持し続ける理由がない。§10.4 に区切りの候補を挙げる。
7. **発注文書に実測値を書き込む。** 受け手が再調査しなくて済むだけの情報を渡す。曖昧さを残したまま上位モデルへ投げるより、曖昧さを潰して下位モデルへ投げるほうが安い（`docs/CODEX_WORK_ORDER_001.md` がその例）。

### 10.5 決定権の所在（2026-08-30・依頼者裁定）

H-13 の決定者を問うたところ、依頼者より次の裁定を得た。

> 原則「人」とするが、状況や程度、判断箇所に合わせて柔軟に対応

**H-13 だけの規定ではなく、以後すべての判断に適用する一般規則として読む。**
「人が決める」と書かれた項目を、Claude が機械的に全部止めるのは資源の使い方として悪い、
という趣旨である（§10.0 の原則 9 と整合する）。

#### 既定

**迷ったら人へ上げる。** 以下の切り分けは、迷いを減らすためのものであって、
人を飛ばす口実にするためのものではない。

#### Claude が決めてよい（3 条件を**すべて**満たすとき）

1. **取り返しがつく。** コードか生成物の変更だけで元へ戻せる。
2. **公開物の意味内容・プライバシー境界・ライセンス・権利表示に触れない。**
3. **決めた内容と理由を文書に記録する**（該当する ADR と、計画の当該節の両方）。

例: ファイルの置き場、型の切り方、内部の命名、テストの分割、
`product` 判別子を**技術的にどう表現するか**（フィールド名・既定値の与え方）。

#### 必ず人へ上げる（程度によらない）

| 対象 | 理由 |
|---|---|
| 公開するか否か、公開の範囲 | 憲章 §4。取り返しがつかない |
| ライセンス・権利表示・再配布条件 | 法的根拠。誤ると第三者に及ぶ |
| プライバシー境界（何を送るか・何を保存するか） | 憲章。誤ると個人情報が外へ出る |
| `CONSTITUTION.md` の改訂 | 上位規範。H-12 がこれに当たる |
| 正式名称・公開名義・アカウント | 対外的な同一性 |
| 不可逆操作（履歴書き換え、force push、削除） | 定義どおり戻せない |
| 一次資料の内容に関する判断 | F-05・F-07。人の確認が公開条件そのもの |

#### H-13 への当てはめ

`product` 判別子を**足すこと自体**は保存形式の互換性に関わり、既存の書き出しを持つ
利用者に影響しうるため **人が決める**。一方、足すと決まった後の
**表現方法**（フィールド名、既定値、`schemaVersion` を上げる代わりに省略可能フィールドと
するか）は上記 3 条件を満たすため **Claude が決めて記録してよい**。

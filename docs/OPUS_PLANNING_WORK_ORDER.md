## 4. 確定済み事項

以下は再提案・再裁定の対象にしない。実現困難な根拠が見つかった場合だけ、事実・影響・代替案を示して停止する。

### 製品・公開

- アプリ名「古典学習帳」は仮称。公開準備時に正式名称を決める。
- 中高生の自主学習用で、成績・学校システムとは連携しない。
- 初回公開を優先し、機能は二段階以上に分ける。
- 新しいGitHubアカウントの公開リポジトリとGitHub Pagesを初期公開先とする。
- 現在の個人SNSアカウント名を公開名義に使わない。
- 公開アプリと、管理・報告・内部発注文書を置く非公開側を分ける。

### 技術

- Vite + TypeScript + Preactを採用する。
- 静的Webアプリ、local-first、IndexedDBを基本とする。
- 必須ログインとクラウド履歴同期は初回公開に含めない。
- Firebase Blaze契約を利用できるが、無料枠内を運用目標とする。
- Firebaseは初回公開では匿名統計と問題報告を中心に使う。
- コードはApache-2.0、独自コンテンツはCC BY 4.0、フォントは元ライセンス、原資料PDFは確認まで非公開とする。

### 学習・UI

- 「とりあえず始める」を第一操作にする。
- 見るだけ、おぼえる、全体確認、試験前の確認を実装する。
- URLと利用者操作の両方で範囲を指定できる。
- 固有番号は「番」、歌の数量は「首」、問題数は「問」とする。
- 初回の一巡は番順。一巡後は区切りで番順／ランダムを切り替えられる。
- 問題・選択肢・回答対象は縦書き、操作・進捗・結果は横書きとする。
- 上の句・下の句を基本の2まとまりとし、実機で入らない歌は人間確認済みの改行候補を使う。
- 習熟度は％・メーター・5色。固定した短い段階名を付けない。
- 正解は丸、不正解・自己評価×はチェックと「要確認！」、全問正解は花丸を使う。
- 自動で次問へ進めず、「次へ」またはEnterを使う。
- 効果音は初期状態で使わない。

### データ・統計

- 校正済み一次資料を変換処理や出題生成から書き換えない。
- 穴埋め、句切れ、改行、作者異形、読み、助動詞は、確認状態を持つ派生データとして分ける。
- 生成AIだけで公開問題・正解・一次資料を確定しない。
- 学年は「中一・中二・中三・その他」から選び、「その他」のみ小学生・高一・高二・高三・大人へ分ける。
- 統計の個別オプトアウトは初回公開に設けない。
- 少人数であることを理由に集計値を隠したり丸めたりしない。
- 同じブラウザ保存領域で継続する無作為な利用番号を使う。実人数とは表示しない。
- 氏名、学校名、連絡先、回答本文、手書き画像、端末固有ID、広告ID、フィンガープリントを送らない。
- テスト運用と正式公開をデータ上で分ける。
- 利用者向け統計案内は仕様書の確定文を使う。

- test/official分離、正式公開日時、集計スキーマ版

## 9. テスト計画の原則

- 小さな文言・色・余白変更で、無関係な全テストを毎回実行しない。
- 変更箇所の静的検査、対象unit、代表画面、関連回帰の順で実行する。
- 正本変換、習熟度、履歴統合、削除、Firebase payload、Rulesは自動テストなしで変更しない。
- 公開前には全テスト、production build、秘密情報走査、実機一巡を行う。
- 巨大な一枚テストへ集約せず、原因領域が分かるsuiteに分ける。
- テスト件数ではなく、失敗時に守るべきものと受入条件を示す。

## 10. 裁定の扱い

計画作成中に疑問が出た場合は、まず仕様・憲章・監査文書から答えを探す。確定済み事項の好みによる再提案はしない。

裁定が本当に必要な場合は、本文中へ埋めず、末尾に次の形式で最大5件までまとめる。

```text
裁定番号:
論点:
判明した事実:
利用者への影響:
推奨案:
代替案:
決めない場合に停止するフェーズ:
```

一次資料の不一致、利用者履歴の消失、公開情報の漏えい、統計の個人特定可能性、Firebase費用の大幅増加、主要実機での操作不能は、計画上の回避策だけで処理せず、停止条件として明示する。

## 5. Hの判断をやり直さないための境界

原則は「今回何ができたか→次に何をするか→詳しい記録」。常設の全体%・増加%は追加しない。075の詳細折畳みを維持する。学習意欲への効果は仮説であり、%非表示や10番区切りが心理学的に最適と実証済みとは書かない。

**D-77は未決**（HANDOFF基準463行）。依頼者の候補は①前後見出しをなくし `0 → 0.2%`、②歌一覧のメーター右に増分をまとめて表を減らす、の2つ。比較時の推奨は、まず詳細内の1行を「歌番号＋前→後」で簡潔にする案。大きな矢印は読み取りや200%での折返しを妨げない範囲。二重表現を減らす②は、整数メーターと小数増分の関係を誤読しない説明が必要。**この推奨を依頼者の採用済み裁定として書かない。** 現行のままでも学習継続を妨げないため、U1〜U3を先にする。

今回の振り返りは、100首を10番区切りにする仕事と分離する。`result.poems`は対象範囲の歌単位で、今回の問題単位ではない。新しい表示モデルが必要なら専用発注にし、同じ歌の別空欄・作者問題・閲覧を落とさず、問数と首数を混同しない。原イベントや集計の変更は含めない。

「同じ範囲をもう一度」は再抽選、「まちがえた歌だけをもう一度」は対象問題IDの再確認。前者を「同じ問題をもう一度」へ改名しない。閲覧も再確認対象という直近裁定を維持する。D-57の丸め・計算と057 R5の小数第1位を、動機づけ目的で変えない。新しい習熟段階・ランキングも作らない。

## 6. 短い発注書と検収の型

1本につき次の6項目で足りる。長い旧発注のコピー、全履歴の転記、全A〜Iの再説明をしない。

1. **問題と根拠**: 再現経路、現行HEAD、対象行、実測値。報告のみなら未再現と書く。
2. **採る仕様**: 利用者がする操作と得る結果。裁定変更は理由を先に示し、維持・変更・未決を区別。
3. **変更境界**: ファイル・責務、変えない記録／採点等。CSSが共有なら参照先を確認。
4. **受入条件**: 利用者の行動、数値、主要な陰性例。DOM形状だけで合格にしない。
5. **停止条件**: 境界外変更、裁定衝突、未解決の回帰。軽微な実装選択まで依頼者へ戻さない。
6. **検収・報告**: 実行結果と未確認を分け、別のCodexタスクで確認。公開は既存の権限と公開手順の条件に従う。

起草だけならbuild・全試験を回さない。実装後は対象試験→必須ゲート。**画面変更では `npm run build` の後に `npm run check:overflow` を全走査する規則を維持**する。必須の独立検収は削らない。同じ完成差分を起草者がさらに全検査し直す第三の工程は設けない。証拠にはHEAD・未commit差分・条件・終了結果を残し、別の差分の緑を使い回さない。破壊試験は既存で要求されるものと、今回の重要な回帰を検出するものに限定し、装飾の各行へ機械的に増設しない。

実施順: **U1→U2/U3→A+B+C（同画面はまとめてもよい）→D/F/Gの残証拠確認と必要な修正→H→I**。無関係のファイルを1本へ抱き合わせない。1本完了ごとに本書の対象行へ状態・commit・検収書リンクだけ追記する。未解決を消さず、全文を再執筆しない。

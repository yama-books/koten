## 1. 何をするのか

**いまの難度調整は完全な自動である。** その歌の `openRung`（制覇していない一番下の段）を
計算して、**その段だけを配る。手で上げ下げする経路は 1 本も無い**（実測・grep 0 件）。

**学習者が一時的に易しくできるようにする。**

```
自動が選ぶ段（openRung）        ← 上限。ここより上へは行けない
      ↓ 「やさしくする」
制覇済みの段へ 1 つ下げる
      ↑ 「むずかしくする」
自動の位置へ戻る
```

## 4. 設計（**親担当の判断。覆すなら先に言うこと**）

### 4.1 上げは `openRung + 2` まで。**ただし天井は開かない**（D-17・2026-09-15・依頼者）

> **挑戦は自由。天井は制覇で開く。**

- **上げられるのは `openRung + 2` まで。** 先取りして挑める。
- **実効の天井は「自動の位置の段」のもの。** 段3 の学習者が段5 に挑んでも、天井は 55 のままである。
  **開けてしまうと、段1・2・3 を 1 問も制覇せずに段5 で 80 まで行ける。梯子の意味が消える。**
- **制覇は数える。** 上の段を全問正解したら記録に残す。**ただし段は飛ばせない**ので、
  下を埋めるまで開かない——埋めた瞬間に**一気に上まで開く。早めの挑戦が報われる。**

**`cleared` を「順に積む配列」から「制覇した段の集合」へ変える必要がある。**
いまの `rungProgress` は最初の未制覇でループを止めるので、**飛ばした先の制覇を記録できない。**
`openRung` は「集合に無い一番下の段」で求める。

### 4.2 手動の調整は**その回かぎり**（D-17）

**次に始めるときは自動の位置に戻る。**

**下げたままにすると行き止まりになる。** 下げた先は**すでに制覇した段**で、天井に到達済みである
——`openRung=3`（天井 55）から段2（天井 40）へ下げると、55 > 40 なので**加算は 0**。
**「やさしくする」を押した学習者が、永久に 0% のまま練習し続ける。**

その回かぎりなら「今日は調子が出ないので軽く回す」という使い方になる。

### 4.3 「引き戻さない」規則との衝突（**この発注の山場**）

**いまの `openRung` は「正解したことのある一番上の段」より下へ戻さない**
（`rungs.ts` の `highestAnswered`）。**手動の上げがここに混ざると、
一度試しただけの段が次回からの定位置になり、段を飛ばせてしまう。**

**イベントからは「自動で配られた段」と「手で上げて挑んだ段」を区別できない。**

> **イベントに印を 1 つ足す。** `rung` を足したときと同じく**省略可**にする
> （必須にすると古いイベントが弾かれ、履歴が消える）。作る側では必須にして、型で書き忘れを止める。

```ts
/** 手で難度を上げて解いたか。**省略可**（2026-09-15 より前の保存は持たない＝自動である）。 */
raised?: boolean;
```

`rungProgress` は **`raised` が真のイベントを `highestAnswered` に数えない。**
**制覇（`cleared`）には数える**——正解は正解であり、捨てない。

**なぜ移行の保護をまだ外せないか。** 実測で生徒の最高習熟度は中央値 21（2〜3 回正解に相当）で、
**段3 を制覇していない学習者が大多数**である。`highestAnswered` を外すと、その全員が段1 へ落ちる。

### 4.4 保存と実効の段

`UserSettings` の作りに倣う（`statsOptOut` が先例）。**既定値を書き込まない。**

```ts
/** その回の難度の手動調整。**+ が易しく、− が難しい。** 保存しない（その回かぎり・§4.2）。 */
type RungAdjust = number;
```

```
実効の段 = clamp(openRung - adjust, 一番下の段, min(openRung + 2, 一番上の段))
```

**一番上の段（`FLAG_RUNG` = 8）でも止めること。** これを忘れると `openRung=8` から上げたときに
**存在しない段9 が出る**（2026-09-15・親担当が検算で発見。`openRung + 2` だけでは足りない）。

**検算（2026-09-15・親担当・実測）**

| `openRung` | `adjust` | 実効 | |
|---|---|---|---|
| 1 | 1 / 99 | 1 | 下限が効く |
| 1 | −5 | 3 | ＋2 で止まる |
| 3 | 1 | 2 | 1 段易しく |
| 3 | −2 / −5 | 5 | ＋2 で止まる |
| 8 | 3 | 5 | 下げられる |
| 8 | −1 | **8** | **一番上で止まる**（上限を入れないと 9 が出た） |

**段8 だけ性質が違う。** 段8（番号だけ）は**点を動かさず、印を立てるだけ**である。
段8 から下げると点が入る段へ戻る——**これは意図どおり**だが、
**その状態では完全制覇の印は立たない。画面でそのことに触れること。**

### 4.5 画面

**出題中ではなく、始める前（範囲選択の画面）に置く。** 解いている途中で難度が変わると、
その回の記録の意味が揺れる。

- 「**やさしくする**」——1 段下げる。一番下の段に居るときは**押せない**
- 「**むずかしくする**」——1 段上げる。`openRung + 2` に居るときは**押せない**
- **自動の位置から離れていることが分かる表示**を出す（戻す手がかりが無いと迷子になる）
- いまどこに居るかを 1 行で出す（例: 「いまは**句をまるごと**書く段です」）

**自動の提案は出さない。** D-16 は「自動は提案するだけ」だが、
**提案の文面と出す条件は別の裁定が要る**ので、この発注では**手動の 2 つのボタンだけ**を作る。
提案は次の発注にする。

## 8. 受入条件（**すべて機械判定できる**）

1. **手動の調整が保存に残らない**（その回かぎり・§4.2）。次に始めると自動の位置になる。
2. 1 段下げると、配られる段が `openRung - 1` になる。
3. **`openRung + 2` を超えられない**——いくつ上げても配られる段は `openRung + 2` まで。
3b. **一番上の段を超えられない**——`openRung = 8` から上げても実効は 8。**存在しない段9 を出さない。**
4. **一番下の段より下へ行けない**——いくつ下げても配られる段は一番下。
5. **下げても制覇の記録が消えない**（`cleared` が変わらない）。
5b. **上げて挑んだ段を全問正解すると `cleared` に入る**が、**下が残っていれば `openRung` は上がらない。**
    下を埋めた瞬間に**一気に上まで開く**こと。
5c. **手で上げて解いたイベントは、次回の自動の位置を動かさない**（`raised` を見ている）。
    **`raised` を持たない古いイベントは、これまでどおり位置を保つ**——移行の保護を外さない。
5d. **上げて挑んでも天井は開かない**——段3 の学習者が段5 で正解しても、習熟度は 55 で止まる。
6. 一番下の段に居るとき「やさしくする」が**押せない**。自動の位置に居るとき
   「むずかしくする」が**押せない**（画面の試験）。
6b. **段8 に居て「やさしくする」を押した状態では、完全制覇の印が立たない**ことを確かめる
    （段8 を解いていないのだから当然だが、**画面がそれに触れていること**も見る）。
7. **既存 500 問の受理集合が 1 本も変わらない**（この発注は問題に触らない）。
8. **ゲートは終了コードで見る**——`typecheck` / `lint` / `test:node` / `test:screen` /
   `data:check` / `check:eol` / `scan:publish` / `check:overflow` が**すべて exit 0**。
   **パイプに通して最終行だけを読まないこと**（2026-09-15 に CI を 1 度落とした原因である）。
9. **`check:overflow` の前に `npm run build` を走らせる。** この検査は `vite preview` 経由で
   `dist/` を配るので、**build し直さずに測ると新しい画面を 1 度も見ずに緑になる。**

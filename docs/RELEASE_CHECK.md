## 2. 4 幅の確認（320 / 375 / 414 / 768px）

`check:overflow` が機械で覆っている。**歌の表示 1200 件**（100 首 × 3 読み × 4 幅）に加え、
**2026-09-04 にホームの操作面 8 件**（4 幅 × 文字 100%/200%）を足した。

**足した理由は、そこに欠陥があったからである。** 1200 件は閲覧画面の歌だけを見ており、
**ホームの範囲選択と入口ボタンは一度も測られていなかった。**

## 3. 拡大（WCAG 1.4.4・文字 200%）

**修正前の実測（320px 幅・文字 200%）: 横に 96px あふれ、`.range-panel` が切れていた。**

原因は 2 つ。**(a)** `button { white-space: nowrap }` があり、
**日本語のボタン文字は空白を含まない 1 かたまりなので折り返せず、min-content が器を超えた**
（「とりあえず始める」は 32px 文字で min-content 322px、器は 256px）。
**(b)** `.entry-actions .primary { min-width: 12rem }` が 200% 時に 384px になった。
`.range-fields` に `flex-wrap` が無いことも重なっていた。

**修正後の実測: 320px 幅で文字 100% / 200% / 400% のいずれもあふれ 0・切れ 0。**

**退行を止める釘**: `check:overflow` の拡大走査。修正を取り消して実測したところ、
**終了コード 1、320px@200% で `noPageOverflow: 2` と `noClipping: [range-panel, entry-actions, primary]` を名指しで報告し、
歌の 1200 件は緑のままだった**（破壊が 1 箇所を叩いている）。

## 4. キーボード

- **ホームの操作可能要素 11 件**（数値入力 2・ボタン 8・`summary` 1）に Tab で到達する。
- **実際に Tab を押して確認した。** `:focus-visible` が立ち、**3px の輪郭**が出る
  （`--color-focus`。`button:focus-visible, summary:focus-visible, input:focus-visible`）。

> **測り方の注意。** `element.focus()` をプログラムから呼んでも `:focus-visible` は立たない。
> **その方法で測ると「9 件に輪郭が無い」という誤った結論が出る。**（親担当が実際に一度誤った。）
> **必ず実際に Tab キーを送ってから `matches(':focus-visible')` を見ること。**

- **`summary`（「この版でまだできないこと」）は当初 UA 既定の `1px auto` で、高さ 28px だった。**
  アプリの 3px の輪郭に揃え、**`min-height: 44px`** を与えた（他の操作要素と同じ）。

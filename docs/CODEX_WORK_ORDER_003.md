### 4.2 成果物 B: `仮名遣い規則_一次データ.md`（**人の承認待ちの案**）

リポジトリ直下に作る。設計書 §3.2 の 16 規則を、一次データファイルの形へ起こす。

**各規則に必ず持たせるもの**:

| 項目 | 内容 |
|---|---|
| `ruleId` | `H1`、`H1-a`、`L1` 等。設計書 §3.2 の ID を変えない |
| チップ表示 | 画面に出す短い label |
| 説明 | 変換の内容 |
| 例 | 変換前 → 変換後。**百人一首の実データから採れるものを優先する** |
| 出題 | ○ / × / 句のみ |
| 典拠 | 下記の扱いに従う |
| `proposedBy` | **`"ai"` を必ず入れる**（F-07） |
| `reviewStatus` | **`"pending"` を必ず入れる。`"human-confirmed"` にしない** |

#### 典拠の書き方（**ここを間違えないこと**）

設計書 §3.2 の典拠欄には性質の異なるものが混在している。**扱いを分けること。**

| 典拠 | 性質 | 扱い |
|---|---|---|
| `内閣告示第2`（現代仮名遣い） | **公的資料。告示番号で特定できる** | 告示番号・項番号で参照してよい |
| `画像①〜⑤` | **原資料 PDF（`USB-*.pdf`）由来。再配布不可** | **ファイル名・ページ・ローカルパスを書かない。**「原資料の該当箇所」と書くにとどめる |
| `古文の文法`・`kyoukasyo` | 市販教材 | **書誌情報での参照にとどめる。表の表現・語順を転記しない** |

2026-08-30 の裁定（`docs/HANDOFF.md` §4.1「助動詞機能の範囲」）が同じ論点を扱っている。

> 文法事実（意味・接続・活用型）は参照可。原表の表現・語順の転記は避ける。

**仮名遣い規則にも同じ線を引くこと。** 規則そのもの（「語中語尾のハ行はワ行になる」）は
文法事実であって特定の教材の表現ではない。転記してはならないのは**表の構成・並び・言い回し**である。

#### 特に注意する規則

| 規則 | 注意 |
|---|---|
| `S1`（小書き） | 設計書が「**全資料に記載なし・自前で立項**」と明記している。**典拠が無いことを隠さず、そう書くこと** |
| `D1-a`（ぢづのまま） | 典拠が `内閣告示第2` のみ。他資料に無いことを明記する |
| `K1`（くわ→か） | 画像に記載が無い。教材由来であることを明記する |
| `L1`〜`L3`（長音） | 設計書が「**表記へ翻案**」と書いている。原典は発音の規則であり、表記規則へ読み替えたのは本プロジェクトである。**この翻案を明示すること** |
| `L4` | 表記が変わらない恒等変換。記録するが**表示・出題しない** |

## 5. `百人一首` データを使うときの注意

`百人一首_読み_歴史的仮名遣い.md` と `百人一首_読み_現代仮名遣い.md` は
**7 列・100 行**で、番号 1〜100 に欠番も重複も無い（実測済み）。

**ただし `百人一首_読み_現代仮名遣い.md` は表が空行（59 行目）で 2 ブロックに分断されている。**
行 7-58 がヘッダ + 1〜50 番、行 60-109 が 51〜100 番（**ヘッダ行なし**）。
「ヘッダの次の空行まで」で読むパーサは **50 件で止まる**。

**これは欠損ではない。データは完全である。補完作業を提案しないこと。**
2026-08-30 に別のセッションがこれを「50 首で終わっている」と誤報告した実績がある。

既存の `tools/build-data/parse-table.ts` がこの分断を正しく扱っている。**参考にしてよい。**

## 0. 背景と目的

2026-08-31、親担当が発注008 の検収でフォント資産を手作業で照合した。

- `SOURCES.json` の記録 494 件について SHA-256 を再計算し、実ファイルと全件一致することを確認した。
- `packages/hyakunin` と `packages/kanazukai` に同一の 492 ファイルが重複配置されていることを確認した。
- 各ファミリーに `OFL.txt` があることを確認した。

**しかしこれは 1 回限りの人手の確認であり、回帰検査が存在しない。**
今後フォントを追加・削除するたびに、次の事故が起こりうる。

| 事故 | 現在の検出手段 |
|---|---|
| `fonts.css` が参照する woff2 がリポジトリに無い | **無し**（ブラウザが黙ってフォールバックする） |
| woff2 を足したが `SOURCES.json` に記録し忘れた | **無し** |
| `SOURCES.json` に記録があるが実体を消してしまった | **無し** |
| 記録された SHA-256 と実ファイルが食い違う | **無し** |
| 2 パッケージのフォントが片方だけ更新され食い違う | **無し** |
| `OFL.txt` を消してしまった（**同梱義務違反**） | 一部（`font-coverage.test.ts` が存在のみ検査） |

**最後の 1 つはライセンス義務違反であり、公開後に発覚すると取り返しがつかない。**
本発注は、この 6 つを機械で止める検査を置く。

## 1. この発注の最重要事項 — ウェイトを検査しないこと

**発注010 が、self-host するウェイトを変更する予定である**（Zen Maru Gothic 500 を追加、
Klee One 400 と Zen Maru Gothic 400 を削除）。**本発注はそれと並行して走る。**

したがって本検査は **どのウェイトが正しいかを一切判定してはならない。**
検査するのは「`fonts.css` と実ファイルと `SOURCES.json` が互いに食い違っていないか」という**整合性だけ**である。

> **本検査は、発注010 の前でも後でも、同じように通らなければならない。**

ウェイトの契約（Zen Maru Gothic 500/700・Klee One 600）を検査する役目は発注010 が持つ。
**そちらへ踏み込まないこと。** 踏み込むと発注010 の作業中に本検査が偽の不合格を出し、
互いの足を引っ張る。

## 4. 実装範囲

### 4.1 検査ツール `tools/font-assets-check/index.ts`

`package.json` の scripts へ
`"check:font-assets": "node --experimental-strip-types tools/font-assets-check/index.ts"` を追加する。

検査項目は次の 6 つ。**すべて実装すること。**

| # | 検査 | 違反の意味 |
|---|---|---|
| 1 | `fonts.css` の各 `@font-face` の `src` が指すローカルパスのファイルが、**両パッケージに**実在する | ブラウザが黙ってフォールバックする |
| 2 | `packages/*/public/fonts/` 配下の全ファイルが `SOURCES.json` に記録されている | 出所不明の資産が公開物に混ざる |
| 3 | `SOURCES.json` の全記録に対応する実ファイルが存在する | 記録と実体の乖離 |
| 4 | `SOURCES.json` の SHA-256 と**バイト数**が、実ファイルを再計算した値と一致する | 差し替え・破損の検出 |
| 5 | `hyakunin` と `kanazukai` のフォントディレクトリが**同一内容**である（相対パスの集合と、各ファイルの SHA-256 が一致） | 片方だけ更新された状態 |
| 6 | 各ファミリーのディレクトリに `OFL.txt` が存在し、`SOURCES.json` にも記録されている | **ライセンス同梱義務違反** |

出力の要件。

- 検査したファイル数、記録件数、項目ごとの違反数を**必ず出力する**。
- 違反は種別・パッケージ・相対パスを 1 行ずつ列挙する。
- 違反が 1 件でもあれば終了コード1、0 件なら 0。
- **完走しなかった場合は合否を出さず、終了コード1 で止めること。**
  「0 件検査して合格」という出力を絶対に出さないこと。
- 絶対パス・内部資料名を出力へ出さない。相対パスだけを出す。

### 4.2 unit test `tests/unit/font-assets.test.ts`

既存の書式（`node:test` + `node:assert/strict`）に合わせる。**ネットワークとブラウザに依存させない。**

1. `fonts.css` から `src` のローカルパスを取り出す関数が、実際の記述形式を正しく解析する。
2. SHA-256 の照合関数が、一致する場合に真、1 バイト違う場合に偽を返す。
3. 2 パッケージの内容比較関数が、集合が異なる場合に違反を返す。
4. `OFL.txt` の存在検査が、ファミリーごとに独立して判定する。

**関数を検査できるように、ツールから純粋な関数を export すること**（`tools/font-check/index.ts` が
`parseUnicodeRange` を export しているのと同じ形）。

1. 次がすべて終了コード0で完了する。**それぞれ実際に実行し、`npm test` は件数を書く。**


2. `npm run check:font-assets` が、**現在のリポジトリ状態で違反 0 件**で完走する。
   検査したファイル数・記録件数・項目ごとの違反数を報告に書く。
   （参考値: 親担当が 2026-08-31 に手作業で照合したとき、記録は 1 パッケージあたり 494 件、
   woff2 は 492 個、`OFL.txt` は各パッケージ 2 個であった。**この数値と一致するとは限らない。
   発注010 が並行して走っていれば変わる。合わせにいかず、観測値をそのまま書くこと。**）
3. §4.2 の unit test 4 件が緑である。
4. `git status --short` で、差分が §3 の許可範囲に収まっている。
   **`packages/**` と `docs/**` に差分が出ていないこと。**

### 5.1 ★ 検査ツールが不合格を出せることの実証（必須）

**「違反 0 件で終了コード 0」だけを報告してはならない。**
それは「正しく検査して合格した」場合と「何も検査せずに合格を出した」場合を区別できない。

次を実際に行い、**両方の出力を報告に貼ること。**

1. 一時的に不整合を作る。次の 3 通りを**それぞれ**試す。
   - (a) `packages/hyakunin/public/fonts/` の woff2 を 1 個だけ一時的に別名へ退避する（検査1・3 が反応するはず）
   - (b) `packages/kanazukai/public/fonts/` に `SOURCES.json` に無いダミーファイルを 1 個置く（検査2 が反応するはず）
   - (c) `packages/hyakunin/public/fonts/klee-one/OFL.txt` を一時的に別名へ退避する（検査6 が反応するはず）
2. それぞれで `npm run check:font-assets` が**違反を列挙し、終了コード1 を返す**ことを確認する。
3. **必ず元へ戻す。** 戻した後に `npm run check:font-assets` が再び違反 0 件・終了コード0 になること、
   および `git status --short` で `packages/**` に差分が無いことを確認し、報告に書く。

**この実証をしていない報告は受け付けない。**

## 6. なぜこの実証を求めるか（読むこと）

2026-08-31、別の検査ツールが **1 件も検査していない状態で「1200 件中 1200 件合格」と出力し、
終了コード 0 を返していた**ことが親担当の再実行で判明した。
検査ツールが偽の合格証を発行する状態だったため、**検査を信じると検査の不在に気づけない**という
二重の落とし穴になっていた。

本発注が守ろうとしているのはライセンス同梱義務を含む。
**偽の合格は、無検査より危険である。** だから §5.1 を必須にしている。

## 7. 停止して報告する条件

| # | 条件 |
|---|---|
| S-A | `SOURCES.json` の形式が 2 パッケージで食い違っており、単一の解析器で読めない |
| S-B | 検査を実装した結果、**現在のリポジトリに実際の不整合が見つかった**。**直さずに、種別と相対パスを全件報告して停止する** |
| S-C | 検査に新規 npm 依存が必要だと判断した（**依存追加は禁止**。`node:crypto` で足りるはずである） |
| S-D | `packages/**` の変更が必要だと判断した（§5.1 の一時的な退避と復元は例外。**必ず元へ戻すこと**） |
| S-E | 発注010 が並行して走っており、フォント資産が作業途中で不整合に見える | 

S-E の場合は、**不整合を直さず**「発注010 の作業中と思われる」と明記して観測結果を報告し、停止する。

**どの停止条件でも `docs/` 配下を自分で編集してはならない。**

## 8. 完了報告に含めること

1. 追加したファイルの一覧と、各ファイルで何をしたか。
2. §5 の受入条件1〜4を一項目ずつ、**実行した方法と観測結果**で報告。
3. **§5.1 の実証について、(a)(b)(c) それぞれの出力と終了コード、および復元後の出力と `git status --short`。**
4. `check:font-assets` の通常時の全出力。
5. §7 の停止条件に当たった項目。なければ「なし」と明記。
6. **独自に決めたことがあれば全件。なければ「なし」と明記。**
   出力書式、関数名、ファイル分割、違反種別の呼び名など、本書に書かれていない判断は小さくても全部書くこと。

推測・予定ではなく観測結果を書くこと。**実行していない検査を「成功」と書かないこと。**
**一度も実行できていないコードを完成として報告しないこと。**
**検査ツールは、完走しなかったときに合格を出してはならない。**

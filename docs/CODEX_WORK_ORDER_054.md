## 1. なぜこの発注が要るのか（**先に読む。ここを取り違えると全部ずれる**）

**練習と本番の差が「読みを隠すか」だけになっていた。** 依頼者から
「本番で画面採点を選ぶと練習と同じに見える」という指摘があり、調べたところ**差は表示だけだった。**

**親担当の実測（2026-09-05）**——`planQuestions` を 61〜70 番で走らせた結果:

```
[番号順]   learn=10 exam=10 同一=true
[ランダム] learn=10 exam=10 同一=true
exam に作者問題が入った数: 0 / 10
```

**questionId の並びまで完全に同一である。** `ENTRY_RULES.exam.authorWeight: 1` は
`planQuestions` が先に `type === 'blank'` で絞るため**一度も作用していない**
（`packages/hyakunin/src/domain/entry.ts`）。**2 つのモードの差は `Session.tsx` の表示分岐 3 か所だけだった。**

**根は仕様側にあった。** 旧 `APP_SPEC` §5 の `exam` 定義自身が「**1 問ずつ**確認する」と書いており、
**`learn` との差は「紙に書くこと」1 点しか無かった。** 画面入力を選ぶとその 1 点が消える。

**そこで裁定 D-76 が出た。** **軸を「答え方」から「フィードバックのタイミング」へ移す。**
**`docs/APP_SPEC.md` §5 と §5.1 は親担当が書き換え済みである。実装をそれに合わせる。**

## 3. 裁定済み事項（**これに従う。決め直さない**）

### 裁定 1: 差はフィードバックのタイミングだけである

- **練習**——1 問ごとにその場で答え合わせ。歌番号を出す。読みを出せる。**いまの実装のままでよい。**
- **本番**——**範囲を通して解き終えるまで、正誤も正答も一切出さない。** 歌番号を出さない。読み操作を出さない。

### 裁定 2: 答え方（画面／紙）は本番だけの選択である。軸にはしない

**`RangePicker.tsx` の「答え方」の節を `entry === 'exam'` のときだけ出す形へ戻す。**
**053 で両方に出したのは依頼者の要望を超えている**——B-8 の原文は「**本番側で**選べるように」である。

**練習は常に画面入力である。** 練習に紙の選択肢を出さない。

### 裁定 3: 採点は「解き終えたあと」にまとめて行う

**採点は `Session` の最後の局面として実装する。** 全問を解き終えたら、**採点の一覧を出す。**

| 答え方 | 一覧の 1 行に出すもの | 操作 |
|---|---|---|
| **画面** | 歌番号 ／ **自分の答え** ／ 正答 ／ 自動判定の ○・△・× | 確認して「結果へ」 |
| **紙** | 歌番号 ／ 正答 | **○・△・× を自分で選ぶ**。全行選んだら「結果へ」 |

**△ は現代仮名遣いで書けた場合である**（`APP_SPEC` §7.1.1 の部分正解と同じ扱い。新しい基準を作らない）。

### 裁定 4: `Result.tsx` を変更しない

**採点は `Session` の中で終わらせ、確定した結果を既存の `onComplete` へ渡す。**
**結果画面は今のままでよい。** **触ると発注が膨らむ。**

### 裁定 5: 習熟度イベントは採点確定時にまとめて保存する

**本番では、解いている最中に習熟度イベントを保存しない。** 採点が確定した時点でまとめて保存する。

**理由**——**紙は採点まで判定材料が存在しない。** 画面だけ先に保存すると保存経路が 2 つになり、
**同じモードの中で記録の意味が答え方によって変わる。**

**その帰結として、採点前に閉じた回は復元しない。** **画面にそう書く。黙って消さない。**
**`learn` の保存規律は変えない**（従来どおりその都度保存する）。

### 裁定 6: 「読みを確認しながら穴埋め」「読みを隠して穴埋め」という語を使わない

**053 で入れたこの 2 つの語を、`RangePicker.tsx` と `Session.tsx` の両方から消す。**
**読みの有無はモード名にしない**——練習では読みをその場で出し入れでき、
**開始前に決めても直後に変えられるので、その選択は嘘になる。**

### 裁定 7: 「作者名を確認する」は閲覧側へ移す

**現在「学習方法を選ぶ」の折りたたみの中にあるが、そこは `aria-label="穴埋めの方法"` である。**
**閲覧系の入口なので「歌を確認する」の隣に置く。** **機能は変えない。置き場所だけ変える。**

### 裁定 8: `entry.ts` を変更しない

**効いていない `ENTRY_RULES.exam.authorWeight: 1` は本発注では直さない。**
**出題内容を変えると、この発注で見たいもの（フィードバックのタイミング）と混ざる。** 別件として起票済みである。

### 裁定 9: 統計・保存スキーマに触れない

**`packages/shared/src/storage/**` と `domain/event.ts` を変更しない。**
**採点をまとめる仕組みは、既存のポートと `Session` の局面で組む。**
**スキーマを変えないと実現できないと判断したら S-4 で止まる。**

### 裁定 10: 採点の一覧は、既にある `complete` 局面の画面を置き換える形で作る

**継ぎ目は既に存在する。** `packages/hyakunin/src/ui/screens/Session.tsx` の
`if (!question || flow.phase === 'complete') return ...` が、いま
「今回の範囲を確認しました／結果を見る」を出している。**本番のときここを採点の一覧に差し替える。**

**`flow.ts` に新しい `FlowPhase` を足さない。** 既存の 5 つ（`prompt` / `answered` / `revealed` / `save-failed` / `complete`）で足りる。
**足さないと実現できないと判断したら、実装を始める前に報告すること**（S-9）。

**練習のときのこの画面は今のままにする。** 差し替えるのは本番だけである。

### 裁定 11: 解答中の判定は「計算してよいが、表示も保存もしない」

**画面入力の本番では、`submitAnswer` の判定をそのまま使ってよい。** 新しい判定規則を作らない。
**ただし判定を画面に出さず、習熟度イベントも保存しない**（裁定 1・5）。

**回の途中の答えは `Session` のローカル state に持つ。** **保存スキーマに触れない**（裁定 9）。
**その帰結として、採点前に閉じた回はローカル state ごと消える**——**裁定 5 が「復元しない」と決めているのと同じ結論であり、矛盾しない。**

**紙のときは入力が存在しないので、判定は採点の一覧で本人が付けるものだけである。**

### 裁定 12: 既存の釘 `R-7` と `R-8` は、下の指定どおりに書き換える（**それ以外の R-n は触らない**）

**親担当が発行前に検算したところ、上の裁定と発注053 の釘が 2 本ぶつかっていた。**
**放っておくと着手直後に S-5 を踏む。** **だから、ぶつかる assert を名指しで指定する。**

| 釘 | 現在の assert | どうするか | 理由 |
|---|---|---|---|
| **R-7** | `toContain('作者名を確認する')` を**折りたたみを開いた状態で**見ている | **折りたたみの外**で見るように書き換える | 裁定 7 で閲覧側へ移すため |
| **R-7** | `toContain('歌番号と読みを隠して力試し。')` | **`toContain('試験のように解いて採点')` に差し替える** | §2 の説明文が正本になったため |
| **R-8** | `Session` 内で「答えを確認する」→「自己採点」が出ることを見ている | **解き終えたあとの採点の一覧で ○・△・× を選べることを見る**ように書き換える | 裁定 3 で採点が最後へ移るため |

**`R-8` の前半（本番の開始前画面でだけ「紙に書く」を選べ、`answerMode` が `paper` になる）は残す。**
**それは裁定 2 が守っている性質そのものである。**

**この 3 か所以外の R-n を書き換えてはならない。** **赤くなったら S-5 で止まる。**

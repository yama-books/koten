# QR 同期の実端末確認

## 開始条件

- 2 台とも **同じ HTTPS の検証版**を開く。ブラウザの通常タブとホーム画面アプリは別の保存領域になる場合があるため、各端末で入口を固定する。
- 検証版に Plan 2 の変更が含まれていることを確認する（ホームに新機能の案内があり、「これまでの記録」に「データ管理」タブがある）。
- Firestore の `households/**` に対する Plan 2 のルールが検証先へ反映されていることを確認する。既存の本番ルールのままではコレクション購読とセッション完了の更新が拒否される。
- 大切な既存記録がある端末は、先に「これまでの記録」→「データ管理」から書き出しておく。

## 確認順序

| 順 | 操作 | 期待する結果 |
| --- | --- | --- |
| 1 | 端末 A で同期設定を開き「新しい同期グループを作る」。状態が「端末間同期が有効です」になるまで待つ | QR・招待リンク・共有コードが表示される |
| 2 | 端末 B で「カメラを開く」から QR を読み取る。別途、「画像を選ぶ」から保存した QR 画像も試す | カメラは読み取り後に停止し、「参加の確認」が出る。この時点では B は同期しない |
| 3 | B で「確認して参加する」を押す | B が「端末間同期が有効です」になる。A と同じ共有コード末尾を示す |
| 4 | A で「歌を確認する」から1首を表示し、B で「これまでの記録」を開く | B に A の記録が加わる。B でも1件作り、A に届くことを確かめる |
| 5 | B をオフラインにして記録を1件作り、オンラインへ戻す | B は「オフラインです」を示す。復帰後に送信され、A に記録が加わる |
| 6 | A で読み・表示方向などの設定を変える | B に設定が反映される。B の共有コードと端末固有の設定は書き換わらない |
| 7 | B で「同期を停止」→確認 | B の既存記録は残る。その後 A で作った記録は B に届かない。B を再読み込みしても自動参加しない |
| 8 | 別サイトまたは別パスの URL を「招待リンク・共有コード」に入れる | 参加できない |

## 記録する項目

- 各端末の機種、OS、ブラウザ、通常タブ／ホーム画面アプリの別
- 検証版 URL と確認日時
- 上表の成功／失敗、失敗時の画面文言と操作順
- カメラ許可を断った場合にリンクまたは画像入力へ切り替えられるか

本番 Firebase のルール反映、App Check 施行、公開版への反映はこの文書の作成時点では未実施。

## 一時 HTTPS 環境

端末確認用ビルドは `VITE_QR_SYNC_EMULATOR=1` と `VITE_BASE_PATH=/100/` を設定して作る。このときだけ Firebase SDK の接続先が同一 origin のローカル Firestore エミュレータ（`demo-koten-device`）になる。通常の公開用ビルドにはこのフラグを付けない。

起動中の構成は、Vite preview `127.0.0.1:4173`、Firestore エミュレータ `127.0.0.1:8089`、同一 origin に束ねる `tools/qr-sync-device-preview/proxy.mjs` `127.0.0.1:4180`、Cloudflare Quick Tunnel の順。トンネルが表示する `https://...trycloudflare.com/100/` を2端末で開く。PC または各プロセスを止めると URL は使えなくなり、次の起動時には URL が変わる。

**エミュレータの港は 8089 で、規則試験（`tests/rules`）が使う 8088 とわざと分けてある。** 以前は両方が `firebase/firebase.json` の 8088 を使っていたため、端末確認を動かしたままでは規則試験が `port taken` で走らなかった。端末確認用の設定は `firebase/firebase.device-preview.json`（規則ファイルは本番と同じ `firestore.rules` を読む）。アプリは同一 origin の proxy 越しに繋ぐので、港を変えてもアプリ側の設定は要らない。

`tools/qr-sync-device-preview/start.ps1` はこの4プロセスを非表示で起動し、ログを `D:\dev\qr-sync-preview-logs\` に保存する。URL は `tunnel.err.log` の `https://...trycloudflare.com` 行を参照する。Error 1033 は一時トンネルが切れているときに出る。再起動後は新しい URL を使う。

2026-09-21 01:10 JST 時点の確認先は `https://gif-merchant-succeed-proper.trycloudflare.com/100/`（00:30 と同じ URL）。トンネル PID 8032 と Vite PID 19540 はそのまま、Firestore は 8089 へ移して PID 18572、proxy は PID 13056 で入れ替えた。**トンネルと Vite を止めずに Firestore と proxy だけ入れ替えたので URL は変わっていない。** 一時 URL のため、次のセッションでは利用前に再確認する。

`smoke.mjs` は確認先を `QR_DEVICE_URL` で渡して走らせる。ヘッドレス Edge の独立した2保存領域で、同期作成→招待→参加→記録の双方向反映を確認した。320px と 390px の画面幅で QR 枠がカード内に収まること、生成 QR を復号できることも確認する。2026-09-21 の新 URL でも成功。カメラ、端末のオフライン復帰、PWA は実端末で確認する。

# Codex向け発注文書 007: scan-publish の許可リストを正本から読ませる

発注日: 2026-08-31
階層: **Luna**（裁定は親担当が完了済み。既存ツールの小さな機械的修正と unit test）
優先度: 高（公開ゲートの正しさに直結）
対象: `tools/scan-publish`

---

## 0. 背景（重要・この発注の理由）

発注006で `tools/scan-publish` を staging 全体の再帰 allowlist 検査へ拡張した。走査・再帰・終了コードは
正しく動いている（親担当が再実行し、走査9件・違反0件・終了コード0を観測済み）。

しかし実装は、許可する拡張子 `.html` / `.js` / `.css` / `.json` を **ツール内のソースコードへ直接書いていた**。

```ts
const allowedBuildExtensions = new Set(['.html', '.js', '.css', '.json']);   // ← 根拠が正本に無い
```

発注006 は「allowlist の内容を自分で発明しないこと」「`docs/PUBLISH_MANIFEST.md` に書かれていない許可を
足さない」と定め、この状況を停止条件 **S-A**（許可範囲を自分で決める必要が生じた）として明示していた。
本来はここで停止・報告すべきだった。完了報告にもこの判断は記載されていなかった。

**この発注は責任追及ではない。** 正本が build 成果物用の許可リストを持っていなかったことが原因であり、
親担当が 2026-08-31 に `docs/PUBLISH_MANIFEST.md` **§5.1** としてそれを裁定・追記した。
本発注は、ツールをその正本へ接続し直すだけの作業である。

| 2 | `tools/scan-publish/index.ts` 全体 | 現在の走査・照合・出力・終了コード |

## 3. 実装仕様

1. `docs/PUBLISH_MANIFEST.md` の **§5.1 の `text` コードブロック**を読み、`#` で始まる行と空行を除いた
   各行を、許可する拡張子として使う。**ツール側に拡張子を直書きしない。**
2. §5.1 のブロックが見つからない、または有効な行が0件のときは、**違反ではなく設定異常**として
   専用のメッセージを出し終了コード1にする。空の許可リストで「全部違反」と報告しない。
3. §5 のブロック（ソース用パス形）を読む既存の処理はそのまま残す。
   `packages/<name>/**` が §5 に載っているかの確認は現状どおり続ける。
4. 拡張子の比較は小文字化して行う（`.JSON` も `.json` として扱う）。
5. 出力書式・走査件数の表示・終了コードの規則は発注006 §3 のまま変えない。
6. 絶対パス、内部資料名、スクリーンショット名を出力へ出さない。相対パスのみ。

---

## 4. 追加する unit test

`tests/unit/scan-publish-allowlist.test.ts` を新規に置く。既存テストの書式（`node:test` + `node:assert/strict`）に
合わせること。次を検査する。

1. `docs/PUBLISH_MANIFEST.md` の §5.1 ブロックが実際に取り出せ、有効な行が1件以上ある。
2. 取り出した許可拡張子に `.html` `.js` `.css` `.json` `.woff2` が含まれる。
3. **`.map` が含まれない**（ソースマップを公開しない裁定の回帰検査）。
4. `tools/scan-publish/index.ts` の本文に、拡張子の直書き配列が残っていない。
   （例: `'.html'` と `'.js'` を同一の配列リテラル内に並べた記述が無いこと）

テストはネットワークにもビルド成果物にも依存させないこと。

---

## 5. 受入条件

1. `npm run build` 後に `npm run scan:publish` が終了コード0で完走し、走査件数を出力する。
   **実行して得た実際の件数を報告に書くこと。**
2. ビルド出力へ許可外拡張子（例: `.map`）のファイルを一時的に1つ置くと終了コード1で当該ファイルが列挙される。
   **確認後、置いたファイルは必ず削除し、削除したことを報告に書く。**
3. ビルド出力が存在しない状態では終了コード1になる。
4. §4 の unit test 4件が緑である。
5. 次がすべて終了コード0で完了する。**それぞれ実際に実行し、`npm test` は件数を報告に書く。**

```text
npm run typecheck
npm run lint
npm test
npm run build
npm run data:check
npm run scan:publish
```

6. `git status --short` で、本発注の差分が §2 の2ファイルに収まっている。

## 7. 完了報告に含めること

1. 変更したファイルの一覧と、各ファイルで何を直したか。
2. §5 の受入条件1〜6を一項目ずつ、**実行した方法と観測結果**で報告。
3. §6 の停止条件に当たった項目。なければ「なし」と明記。
4. **独自に決めたことがあれば全件。なければ「なし」と明記。**
   仕様に書かれていない値・規則・既定値を自分で決めた場合は、たとえ小さくても必ず全部書くこと。
   これは発注006で漏れた項目であり、本発注では受入条件と同じ重みで扱う。

推測・予定ではなく観測結果を書くこと。**実行していない検査を「成功」と書かないこと。**

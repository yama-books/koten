# 発注078案 — 「わからない！」の開示を「要確認・回答なし・正解」で示す

起草: 2026-09-08 / Codex（設計監査継続）

## 1. 問題と根拠

基準HEADは `44531daf449598937706ba70ac1d9caa69b63bde`。発注077はコミット `933e2a5` で実装され、独立最終検収に合格している。起草時に製品の追跡ファイル差分は無い。既存の文書差分と未追跡資料は他者作業として保持する。

077により、非本番の作者問題で「わからない！」を押すと、閲覧保存成功後に「答えを確認しました。」と正しい作者名・読みが出るようになった。本文問題でも保存成功後に正解は開示される。一方、利用者からは、答えを出せなかった状態を誤答時と同じ手書き風チェック印と「要確認！」で示し、自分の答えの位置には空欄相当を見せたいという要望がある。

現行 `packages/hyakunin/src/ui/screens/Session.tsx:690-707` は、実際に送信した回答があるときだけ「自分の答え」の入力欄をreadOnlyで残し、正誤の印を左へ置く。`725-760` の「わからない！」経路は、保存成功後も `submitted` と `judgement` が `null` で、固定文と、作者問題の場合だけ077の正解表示を出す。これは記録上正しいが、「回答できなかったため次に確認する」という意味が画面上で弱い。

採る案は、手書き風チェック印と「要確認！」、表示専用の「回答なし」、既存規則による正解を順に示すものとする。空の入力欄を置く案は、回答を送信していないのに「自分の答え」が存在したように見え、編集できる欄とも誤認されるため採らない。見た目の空白だけを残す案も、読み上げでは情報が欠落するため採らない。

読んだ範囲は `docs/DESIGN_AUDIT_CONTINUATION.md` のU2、`docs/HANDOFF.md` の2026-09-08要望、発注076・077と077検収記録、`docs/APP_SPEC.md` の即時フィードバック・閲覧・本番規則、現行 `Session.tsx`、`AnswerFeedback.tsx`、`FeedbackMark.tsx`、対象CSSとSession・開示時機・結果集計の試験である。矛盾が無かったため、既存監査全件には範囲を広げていない。

## 2. 採る仕様

画面入力の通常練習または再確認で「わからない！」を押し、閲覧イベントの保存が成功した場合、表示順と読み上げ順を次のとおりとする。

1. 「自分の答え」という見出し。
2. 誤答時と同じ手書き風チェック印。その隣の表示専用テキストは「回答なし」。
3. 判定文「要確認！」。この文言は1回だけ通知する。
4. 問題の正解と既存の補足・注記。
5. 「次へ」。

「答えを確認しました。」は「要確認！」へ置き換え、同じ画面に重ねて出さない。「回答なし」は入力値、選択値、判定値ではなく、回答を送信しなかった事実を説明する表示専用テキストとする。`input`、`textarea`、`contenteditable`、無効化した入力欄、空のsubmittedを使って表現しない。見た目を回答行へ揃える場合も、DOM上は編集欄ではない要素を使う。

本文問題と作者問題の両方で同じ状態表現を使う。正解は誤答時に既に使う `AnswerLines` と同じ規則で表示し、本文では漢字・歴史的仮名遣い・必要な現代仮名遣い、作者では正式名・現代読み・異なる場合の歴史的仮名遣いを示す。問題本文内の空欄開示も維持する。

利用者が本文入力欄へ途中まで文字を入れてから「わからない！」を押しても、その文字列を回答済みとして残さない。「回答なし」と表示し、途中入力はイベント、結果、再確認、統計へ送らない。

保存待ち・保存失敗では、チェック印、「回答なし」、「要確認！」、正解を出さない。現行の失敗案内と同じ問題での再試行を維持する。

本番では解答中にこの即時表示を出さない。本番の採点一覧にある「要確認（わからなかった）」と手書き風チェック印は現行のまま維持し、「要確認！」や「回答なし」へ一括改称しない。

記録上は従来どおり閲覧である。`viewed`を`incorrect`へ変更せず、習熟度の増分・上限、再確認対象、`itemKey`、`questionId`を変えない。表示上の「要確認！」は、誤答イベントへ変換したことを意味しない。

## 4. 受入条件

1. **本文・保存成功:** 本文問題で「わからない！」を押すと、保存成功後に「自分の答え」「回答なし」「要確認！」、手書き風チェック印、正解、必要な仮名遣い補足が表示される。「答えを確認しました。」は表示されない。
2. **作者・保存成功:** 作者問題でも同じ状態表示が出て、正式な作者名・現代読み・異なる歴史的仮名遣いを既存規則で読める。作者用textboxを作らない。
3. **通知の一意性:** 「要確認！」は画面とアクセシビリティ上で意味のある通知として1回だけ存在する。印の画像は装飾として重複読み上げされない。「回答なし」は読み上げ可能である。
4. **架空回答の禁止:** 本文へ途中入力してから「わからない！」を押しても、その文字列や空文字のsubmittedを表示・保存しない。開示後のDOMに編集可能またはreadOnlyの空入力欄を作らず、表示上も「回答なし」と明記する。
5. **保存失敗:** 閲覧保存に失敗した場合は、チェック印、「回答なし」、「要確認！」、正解、成功を意味する文言を出さない。失敗案内、途中入力、候補、再試行可能性を現行どおり維持する。
6. **本番の陰性例:** 本番解答中にはU2の表示と正解を出さない。採点一覧では既存の「要確認（わからなかった）」、正解、`grade-mark--viewed`を維持する。
7. **記録意味:** 本文・作者ともイベントは1操作につき1件で `kind: "view"`、`outcome: "viewed"` のまま。元の `itemKey` と `questionId`を保持し、結果集計で同じ問題IDが再確認対象になる。
8. **実回答の回帰:** 正答・部分正解・誤答では、076で定めた同一input、原入力、印の左配置、判定と正解の順序を変えない。U2用の「回答なし」が実回答へ出ない。
9. **実描画:** 幅320・375・414・768・1024px、文字100%・200%で、本文と作者のU2表示に横あふれ・重なり・文字欠けがない。印と「回答なし」は交差せず、自然な折返しを許す。44px以上の「次へ」を維持し、200%で1行表示を強制するための文字縮小をしない。

恒久試験は本文成功、作者成功、途中入力、保存失敗、本番先行非開示、`viewed`と再確認対象を直接検出する。文言の存在だけでなく、入力要素が作られていないこと、通知が1回であることも確認する。

## 5. 停止条件

次の場合は変更を広げず、事実と最小の代案を報告する。

- U2表示のために `viewed`、submitted、judgement、イベント、習熟度、再確認集計の変更が必要になる。
- 空の編集欄、架空の回答、途中入力の保存が必要になる。
- 保存成功前または本番解答中に判定・正解がDOM、読み上げ、疑似要素へ漏れる。
- 既存の正答・部分正解・誤答、本番一覧、作者表示の意味または通知回数が変わる。
- 画面を収めるために文字縮小、内容削除、固定高、隠れたあふれ、共通CSSへの無差別な上書きが必要になる。
- 他者の製品差分が入り基準を特定できない、または対象試験・必須ゲートに未解決の失敗がある。

U3の高さ問題を同時に直さない。U2による高さ増加は対象条件で測定し、再確認画面の常設中断案内と競合する場合は事実を検収記録へ残してU3へ渡す。

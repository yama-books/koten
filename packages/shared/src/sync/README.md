# 独立アプリの記録と共有グループ

百人一首・変体仮名・活用表は独立したWebアプリです。履歴・習熟度・ポイント・JSONファイルはアプリごとに保持し、共通にするのは招待と共有グループの識別だけです。

## 招待と保存場所

- 既存の16文字コード、`houseId = SHA-256(code)`、AES-GCM/PBKDF2暗号形式を維持します。QRは記録本体を含みません。
- 同じオリジン・リポジトリ配下の `/100/`、`/vintage-kana/`、`/conj/` の招待を相互に読み取れます。読み取りと参加確定は別操作です。
- 同じブラウザでは共通localStorage設定と百人一首のIndexedDB設定を調べ、既存グループの利用を案内します。異なるグループは自動で切り替えません。
- Safari・独立PWA・別ブラウザ・別端末で保存場所を共有できない場合は、既存のQR画像・カメラ・コード入力で明示参加します。
- コード、招待URL、能力トークンとなる保存先パスは秘密として扱います。記録JSON、ログ、スクリーンショット、公開成果物に含めません。

## Firestoreと互換性

新しいグループは `sharedGroups/<domain-derived-capability>/members/<anonymous uid>` に参加し、`apps/hyakunin/{events,sessions,reports,settings}`、`apps/vintage-kana/records`、`apps/conj/records` に分離して保存します。能力トークンはコードから別のドメイン文字列を用いて導出します。旧houseIdだけでは新領域へ参加できません。

招待を知る人は自分の匿名UIDを登録できます。匿名認証だけで読み書きを許可せず、所属をルールで確認します。これは招待を共有する本人の端末向けで、招待を渡した相手の権限取消し機能はありません。App Checkは所属認可の代替ではありません。

旧百人一首グループは従来の `households` を維持します。既存のコード・暗号文・記録を移動・削除しません。旧グループから他アプリが参加した場合も、その百人一首データの保存場所は変えません。**旧領域には従来の所属認可の制約が残ります。** 新規グループの仕組みと同等の安全性を主張しません。旧クライアントによる新規グループへの記録書込みは旧領域へ向かうため、新規グループの百人一首同期には更新版を使ってください。

本番利用には匿名認証の有効化、ルールの承認・適用、App Check設定と実際の接続確認が必要です。ソースの `appCheckEnabled` やエミュレータ成功だけでは、本番の有効状態を証明できません。通常のビルドとデプロイにエミュレータ設定を混ぜないでください。

## 記録の統合

- 百人一首は既存JSON形式を維持し、製品と記録IDを検証します。端末固有の共有・同意・匿名統計の設定を保持し、取込と送信待ち登録を同一IndexedDBトランザクションで行います。
- 変体仮名はversion 1のJSONで読み・字母・解読記録をイベントIDで統合します。同IDの異なる内容は拒否します。旧2,000件窓で保存履歴を切り捨てません。解読20,000件の容量上限を超える入力は書込み前に停止します。同期時の解読レベルは、時系列で最後の解答レベルを統合履歴で再判定します。レベルだけを持つ旧バックアップは最大値を保つ互換規則です。
- 活用表は `katsuyoProtoV37` を維持し、version 2のJSONに移行基準値・一意な解答イベント・旧累計のバックアップを含めます。以後の解答の増分だけをIDで統合します。同じ基準値の系統は一度だけ適用し、異なる旧累計を単純加算しません。空の端末では基準値を引き継ぎ、既存累計のある端末では別系統の旧累計をバックアップとして保持します。旧version 1と旧生集計JSONも同じ規則で読み込めます。
- 記録容量の上限・保存失敗・識別子の衝突では、既存記録を上書きして成功に見せません。

## ローカル検証

`npm run build:app-sync` は静的2アプリ向けの同一招待・接続モジュールを生成します。生成ファイルはGit管理対象外です。Pagesの組み立て前にも生成してください。

通常の検査は `npm run typecheck`、`npm run lint`、`npm test`、`npm run build`、`npm run test:rules` です。

ブラウザ結合検査では、`VITE_APP007_EMULATOR=1` を設定してビルドした後、`firebase/firebase.app007.json` のdemo Auth/Firestoreエミュレータ内で `node tools/app-sync-check.mjs` を実行します。`--webkit` はWebKitです。外部通信を遮断し、架空記録だけを使います。QR画像はメモリ内で受け渡し、秘密値を出力しません。物理iPhoneや本番Firebaseの検査とは区別します。

ロールバックは旧アプリへ戻す前に各アプリのJSONを保存し、同期を停止して行います。新しいルール領域・記録・移行前累計は削除せず保持します。活用表の新しい台帳を旧版の集計だけで上書きしないでください。
